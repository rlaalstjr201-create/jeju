# Plan — 지금 주변 문화생활, 첫 판 (서울시 문화행사)

Spec: `specs/now-culture.md`. 주인 결정(2026-11-04): 「서울시 데이터랑 팝업으로 먼저 진행해. 그리고 막 넣는것이 아니라 잘 나와야 하는데 …
그냥 정보의 홍수에 빠지면 안되니까」.
**판 2 (2026-11-04, Plan Review MAJOR 4·MINOR 8 반영).** 첫 판은 **서울시 문화행사 갈래만** 낸다. 팝업은 다른 날짜 재측정(트렌드 06 한계)을
통과한 뒤 붙이는 별도 단계(§7). 공연(KOPIS + 인디·라이브클럽, spec OQ6)도 이 판 밖이고 같은 파일 꼴에 나중에 붙인다.

## 0. 원칙: 적게, 지금, 이유와 함께

- **홈에는 최대 2개**(spec도 2로 맞춤), 목록 시트는 **최대 6개**. 6개 밖은 보이지 않는다. 장소 카드의 「다른 3곳 보기」(ADR-0058)와 다른 층이라
  넘겨 보기를 두지 않는다 — 새 ADR에 적는다.
- 고른 것마다 **왜 지금인지** 한 줄: 「오늘만」, 「일요일까지」, 「지금 열림 · 무료」, 「저녁 7시 30분 시작」.
- 같은 종류(CODENAME)는 둘까지, **같은 장소(PLACE)는 하나**, 같은 제목의 회차 행은 하나로 합친다(기관 이름은 구청·재단이라 쓰지 않음).
- 시간을 모르는 항목은 **ADR-0111 3의 시간대 규칙**을 받는다: 실내(전시·실내 행사)는 19:00~09:00에 뺀다. 야외 축제·야간 프로그램처럼
  밤이 본래인 것은 종류로 남긴다. 이것은 ADR-0111 결정 6(제주만)을 **서울 문화행사 층에 넓히는 것**이라 새 ADR에 적는다.
- 기간·장소가 확실하지 않으면 넣지 않는다.

## 2. 고르는 순서

1. **거르기**(수집기, 매일): 위 표의 제외 규칙, 좌표 검사(서울 범위·LAT/LOT 뒤바뀜·좌표 구와 GUNAME 불일치는 뺌), HTML 엔티티 풀기,
   같은 제목 회차 합치기.
2. **기간·지금 열림**(앱, 지금 시각): 끝 날짜를 **앱에서도 다시** 거른다(수집이 하루 빠져도 어제 「오늘만」이 남지 않게). 읽힌 시간 밖이면 뺀다.
   시간을 모르면 §0의 시간대 규칙.
3. **점수**(앱): 가까움(걸어서 15분 안 > 차로 15분 안; 차로 15분 밖은 홈에 올리지 않음 — 범위 시트(ADR-0060)와 따로 둔다고 새 ADR에 적음) →
   지금성(오늘만·이번 주 끝남 > 한 달 이하 > 4달 이하 > 4달 넘음) → 열림 확실(시간 읽힘 > 모름) → 누구나·무료(동점 깨기).
4. **다양성**: §0의 종류 둘·장소 하나.
5. **자르기**: 홈 2, 목록 6.

## 3. 데이터·코드·배포 자리

- **파일 하나**: `public/culture/seoul.json`(서울 전체, 오늘 열린 것 약 200건 수준이라 작다). 앱이 거리로 거른다.
  구 단위 파일을 받지 않으므로 **접속 기록에 구가 남지 않는다** — 개인정보 안내에 새로 적을 위치 정보가 없다(서울 파일을 받는다는 사실만 적는다).
- 파일 머리에 `generatedAt`. **48시간이 넘은 파일이면 줄을 숨긴다**(낡은 정보를 보여 주지 않음).
- 캐시: 짧게(`Cache-Control: max-age=3600`), 서비스 워커 미리받기 목록에서 뺀다(장소 파일의 `?v=`·immutable과 다름).
- 갱신·배포: 매일 예약 작업이 수집 → 파일 커밋 → **Cloudflare Pages 배포까지** 한다(지금 01:10 루틴은 커밋만 하므로 배포 단계를 더한다).
  키는 저장소 루트 `.env`의 `SEOUL_OPEN_API_KEY`(로컬), 클라우드 루틴에서는 그 환경의 비밀값. 배포 경로는 구현 전에 정해 ADR에 적는다.
- 코드: `scripts/culture/collect-seoul.mjs`(http만 열리는 API, 1,000건씩), `src/culture.ts`(기간·열림·점수·다양성·자르기, 순수 함수),
  화면 코드는 ADR-0100의 진입 예산(60KB)을 지키도록 **따로 받는 청크**.
- 첫 판에서 기분 버튼(OQ3)과 섞지 않는다. 홈 줄 하나 + 목록 시트만.

## 4. 품질을 먼저 잰다 (화면 만들기 전, 사전등록)

1. PRO_TIME 파서: 오늘 208건 원문 전수로 테스트를 만들고 읽힘 비율을 적는다. 닫는 쪽 표현(「토요일 휴관」, 「매주 금 19:00」,
   「~17:00(입장마감 16:30)」)을 반드시 넣는다.
2. **품질 측정 사전등록**(장면·시각·기준을 측정 전에 커밋):
   - 장면 6곳(성수·홍대·대학로·광화문·잠실·이태원) × 시각 3개(목 14시, 토 19시, **평일 22시** — 빈 목록이 맞는지 시험).
   - 새 Opus 하위 에이전트가 눈가림으로 매긴다. 판정자에게 **거르기 전 후보 풀(원자료 필드 포함)**도 준다.
   - 목록마다: 「여행자가 지금 받고 갈 만한가」 1~5점, 「쓸모없음」 항목 수(못 가는 것·신청제·아이 전용·닫힘·뻔한 상설),
     **「빠졌는데 갈 만한 것」 수**(후보 풀에서).
   - **대조 목록**(그냥 가까운 순 6개)을 섞어 판정자가 둘을 구별하는지 본다.
   - 통과: 평균 4점 이상, 목록당 쓸모없음 1개 이하, 목록당 놓침 1개 이하, 우리 목록 평균이 대조 목록보다 높음.
   - 통과 못 하면 고쳐서 **다른 날짜 + 장면 일부 교체**로 다시 잰다.

## 5. 개인정보·출처

- 서울 파일 하나라 위치가 서버에 가지 않는다. 개인정보 안내(네 언어)에는 「서울 문화행사 목록 파일을 받는다(위치 없음)」만 적는다.
- 출처: 「정보: 서울시 문화행사(서울 열린데이터광장)」.

## 6. 순서

1. ADR(서울 파일 하나·앱 재거르기·48시간 숨김·ADR-0111 시간대 규칙의 서울 문화행사 확장·넘겨 보기 없음·범위 시트와 별개) 작성.
2. 수집기 + `culture.ts` + PRO_TIME 파서(208건 전수 테스트).
3. 품질 측정(§4-2) — 통과해야 화면을 만든다.
4. 화면(홈 줄·목록 시트, 375px와 320px 넘침 확인) + 개인정보 안내 → 독립 리뷰 MAJOR 0 → 배포 경로 구성 → 배포.
