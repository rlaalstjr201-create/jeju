# Plan — 지금 주변 문화생활, 첫 판 (서울시 문화행사 + 팝업)

Spec: `specs/now-culture.md`. 주인 결정(2026-11-04): 「서울시 데이터랑 팝업으로 먼저 진행해. 그리고 막 넣는것이 아니라 잘 나와야 하는데 …
그냥 정보의 홍수에 빠지면 안되니까」. 공연(KOPIS)은 키가 오면 같은 틀에 붙인다.

## 0. 원칙: 적게, 지금, 이유와 함께

- **홈에는 최대 2개**, 누르면 열리는 목록도 **최대 6개**. 그 이상은 「더 보기」 없이 버린다(못 고른 것은 보여 주지 않는다).
- 고른 것마다 **왜 지금인지** 한 줄: 「오늘만」, 「일요일까지」, 「지금 열림 · 무료」, 「저녁 7시 30분 시작」.
- 같은 종류는 목록에 둘까지(전시 6개 같은 목록을 막는다).
- 확실하지 않으면 뺀다(기간·장소·시간을 모르면 넣지 않는다). 장소 카드와 같은 원칙(ADR-0111).

## 1. 오늘(11/4) 서울시 데이터에서 본 것 — 거를 근거

| 관찰 | 수 (오늘 열린 208건 중) | 처리 |
|---|---|---|
| 교육/체험 | 87 | 신청·회차 강좌(강좌·강의·수업·모집·접수·회차·학급·단체·길 위의 인문학)는 뺀다. 야간·투어·현장 체험만 남긴다 |
| 4달 넘게 하는 것 | 83 | 남기되 「지금성」 점수를 낮춘다(상설에 가까움) |
| 대상이 어린이 단체·유아 전용 | 소수 | 뺀다 |
| 이미지·좌표·링크 | 208/208 | 표시·거리 계산 가능 |
| 시간(PRO_TIME) | 형식 제각각 | 읽히는 것(「수 19:30」, 「10:00~18:00」, 요일 범위)만 오늘 시간으로 쓴다. 못 읽으면 「시간 확인」 링크만 |

## 2. 고르는 순서 (구 파일 → 앱)

1. **거르기**(서버, 매일): 위 표의 제외 규칙, 기간이 오늘을 포함, 좌표 있음.
2. **지금 열림**(앱, 지금 시각): 읽힌 시간 밖이면 뺀다. 오늘 이미 끝난 하루짜리는 뺀다.
3. **점수**(앱):
   - 가까움: 걸어서 15분 안 > 차로 15분 안 > 그 밖(그 밖은 홈에 안 올림).
   - 지금성: 오늘만·이번 주 끝남 > 한 달 이하 > 4달 이하 > 4달 넘음.
   - 열림 확실: 오늘 시간이 읽힘 > 모름.
   - 누구나·무료는 동점 깨기에만.
4. **다양성**: 같은 종류 둘까지, 같은 기관 하나까지.
5. **자르기**: 홈 2, 목록 6.

팝업 갈래는 주 1회 검수 목록(트렌드 06 방식, 확신 「높음」만)을 같은 순서로 섞는다. 팝업은 「지금성」을 기간 끝 기준으로 매긴다.

## 3. 데이터·코드 자리

- `scripts/culture/collect-seoul.mjs`: 서울시 문화행사 → 거르기 → `public/culture/seoul/<구 코드>.json`(항목: id, 이름, 갈래, 장소, 좌표, 시작·끝, 읽힌 시간, 무료, 링크, 이미지, 출처).
- `scripts/culture/popups.mjs`: 주 1회 검수 목록 → 같은 꼴로 구 파일에 합침.
- `src/culture.ts`: 지금 열림·점수·다양성·자르기(순수 함수, 테스트 대상).
- 앱: 지금 구(와 이웃 구) 파일만 받는다. 홈 줄 하나 + 목록 시트.
- 매일 갱신: 기존 클라우드 루틴(01:10 수집)과 같은 방식의 예약 작업. 팝업 검수는 주 1회 예약 작업(구독 사용량).

## 4. 품질을 먼저 잰다 (만들기 전 판정 기준)

배포 전에 **「목록이 잘 나오는가」**를 사전등록해 잰다. 데이터만으로 돌릴 수 있게 거르기·점수 함수를 먼저 만들고:

- 서울 장면 6곳(성수·홍대·대학로·광화문·잠실·이태원) × 두 시각(목 14시, 토 19시)의 목록 12개를 만든다.
- 새 Opus 하위 에이전트가 눈가림으로 매긴다: 목록마다 「여행자가 지금 이 목록을 받고 갈 만한가」 1~5점, 항목마다 「쓸모없음」(못 가는 것·신청제·아이 전용·닫힘·뻔한 상설) 표시.
- **통과 기준**: 평균 4점 이상, 목록당 쓸모없음 1개 이하, 빈 목록은 「빈 게 맞는」 경우만.
- 통과 못 하면 거르기·점수를 고쳐 **다른 날짜**로 다시 잰다(같은 날짜로 다시 재지 않는다).

## 5. 개인정보·출처

- 구 파일 요청이 접속 기록에 남는다 → 개인정보 안내(네 언어)에 적는다.
- 출처: 「정보: 서울시 문화행사(서울 열린데이터광장)」, 팝업은 근거 글 링크.

## 6. 순서

1. 이 plan 독립 검토(Plan Review) → ADR(구 파일 구조·주 1회 검수 예약 작업).
2. 수집·거르기·점수(`collect-seoul.mjs`, `culture.ts`) + 단위 테스트.
3. 품질 측정(4절) — 통과해야 화면을 만든다.
4. 화면(홈 줄·목록 시트, 375px) + 개인정보 안내 → 독립 리뷰 MAJOR 0 → 배포.
