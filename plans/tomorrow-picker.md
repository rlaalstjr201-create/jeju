# Plan — 내일 뭐하지 (apps/web)

근거: ADR-0025·0026·0027, `specs/tomorrow-picker.md`. 작성 2026-09-30.

## 목표 기준

"계획 안 세우는 여행자가 밤에 링크 하나 열고, 탭 한 번에 내일 갈 곳을 정한다."
- 한 화면, 탭 1번, 로그인 0, 서버 0, 추가 데이터 수집 0.
- 마무리: 10/14 배포 가능한 빌드 + 전 지역 카드 3장 이상, 10/30 실사용자 1명.

## Open Question 결정 (spec OQ 1~5)

1. **기분 매핑** (restaurant 제외):
   - `rest`(푹 쉬고 싶어) = `cafe` + `sightseeing` 중 이름·코멘트에 `해변|해수욕장|바다|해안|전망|포구|비치` 포함
   - `walk`(좀 걷고 싶어) = 나머지 `sightseeing` (+ `oreum`, 사진 있으면)
   - `new`(새로운 거 해보고 싶어) = `experience` + `cultural_space`
   - `any`(아무거나 골라줘) = rest·walk·new에서 하나씩
2. **차로 약 N분** = 하버사인 직선거리(km) × 1.3 ÷ 40km/h × 60, 5분 단위 반올림, 최소 5분.
3. **숙소 등록** = 외부 API 없이 두 가지: "지금 위치를 숙소로 저장" / 지역 4개(제주시·서귀포·동쪽·서쪽) 중 선택. `localStorage`에 저장.
4. **카드 수** = 3장 고정. 같은 버튼을 다시 누르면 다음 3장(본 카드는 뒤로).
5. **예약 링크** = `experience`만 "예약 찾아보기" → 마이리얼트립 검색(스팟 이름). 그 외는 카카오맵만.

## 구조

- `apps/web/` 새 워크스페이스. Vite + TypeScript, 프레임워크 없음.
- `apps/web/scripts/export-spots.ts` — 로컬 DB에서 **한 번** 뽑아 `apps/web/public/spots.json` 생성. 이후 재실행하지 않는다.
- 소스: `spots`(is_active) ∪ `curation_candidates`(status='pending', spots와 kakao_place_id 중복 제외).
- 기분 버튼 4개는 정적 HTML에 있어 `spots.json` 로딩 전에 보인다.
- PWA: `manifest.webmanifest` + 서비스워커(앱 셸·spots.json 캐시). 외부 PWA 플러그인 없이 직접 작성.

## 성공 기준 (전부 명령으로 확인 가능)

**S1 데이터** — `spots.json` 레코드마다 `id,name,lat,lng,mood,reason,image,kakaoPlaceId,paid`.
- lat 33.1~33.6, lng 126.1~127.0 (0·범위 밖 제외), `image`는 https, `reason` 18~120자
- restaurant 0건, `comment_warning_flag ∈ {rejected, needs_fix, declining}` 0건, kakaoPlaceId 중복 0건
- 총 ≥ 400건, 기분별(rest·walk·new) 각 ≥ 80건, 파일 gzip ≤ 120KB

**S2 선택 로직 (vitest)**
- 대표 좌표 4개 × 버튼 4개 = 16조합 모두 정확히 3장, 서로 다른 스팟
  - 제주시 33.4996,126.5312 / 서귀포 33.2541,126.5600 / 동쪽(성산) 33.4580,126.9310 / 서쪽(한림) 33.4125,126.2650
- 16조합 모두 3장의 추정 이동시간 ≤ 60분 (실데이터 사용)
- `any`는 rest·walk·new에서 각 1장
- 같은 버튼 재탭 시 직전 3장과 겹치지 않음(후보가 6개 이상일 때)
- 가까운 순 정렬, 이동시간 공식 단위 테스트

**S3 화면 (vitest + jsdom)**
- 첫 화면: 기분 버튼 4개 + 위치 전환 1개 외 인터랙티브 요소 없음, 로그인·가격·운영시간·평점·음식 문구 없음
- 탭 후 카드 3장: 이미지·이름·이유·"차로 약 N분"
- 카드 링크 = `https://place.map.kakao.com/{kakaoPlaceId}`, `target="_blank" rel="noopener"`
- experience 카드만 마이리얼트립 링크 존재
- 위치 권한 거절 → 지역 4개 선택 UI 표시
- 숙소 저장 → `localStorage` 유지, 새로 그려도 숙소 기준 유지

**S4 빌드·용량**
- `tsc --noEmit` 0 에러, `vite build` 성공
- 빌드 JS+CSS gzip 합계 ≤ 50KB (spots.json 제외)
- 번들·public에 `.env` 키 값 문자열 0건, 외부 요청은 이미지 CDN과 링크 이동뿐

**S5 PWA**
- manifest: name, start_url, display=standalone, 아이콘 192·512
- 서비스워커 등록, 앱 셸 + spots.json 캐시

**S6 리뷰**
- 스펙·ADR 준수 리뷰: 범위 밖 기능(로그인·예약결제·일정·맛집·가격/운영시간/평점) 0건
- Codex 교차 리뷰: 미해결 MAJOR 0건

**S7 실제 브라우저** (메인 세션이 확인) — 390×844 화면에서 4버튼 → 카드 3장 → 링크 동작, 스크린샷

## 범위 밖

배포 실행(계정 필요 — 명령만 준비), 스토어 앱, 데이터 재수집·갱신.

## 전 항목 검수 (ADR-0028, 2026-09-30 사전 등록)

1차 빌드 결과 S1 개수 기준(≥400)은 275곳으로 실패했다. 이 기준은 ADR-0028(맛집 포함·전 항목 검수)로 범위가 바뀌어 아래 **S1'**로 대체한다. 아래 기준은 검수 실행 **전에** 고정했으며, 결과를 본 뒤 바꾸지 않는다.

### 대상과 입력

- 대상: `spots`(is_active) ∪ `curation_candidates`(pending) 중 사전 필터 통과분 — 좌표가 제주 범위, 사진이 https, `comment_warning_flag ∉ {rejected, needs_fix, declining}`. 맛집 포함.
- 입력 파일: `apps/web/review/input/batch-NNN.json` (DB에서 읽기 전용으로 한 번 뽑음).
- 판정 근거는 입력에 든 보유 텍스트뿐. 웹 검색으로 스팟 정보를 보강하지 않는다.

### 파이프라인과 모델 배정

| 단계 | 모델 | 이유 |
|---|---|---|
| 방법론 조사 (LLM 기반 대량 검수 연구·실무) | opus | 설계 판단 |
| 기준 판정 세트: 층화 표본 60곳 판정 | opus | 기준 라벨 |
| 보정: 검수 모델이 같은 60곳 판정 → 기준 세트와 일치율 계산 | sonnet | 대량 검수 후보 |
| 전 항목 검수 (배치당 약 50곳) | 보정 통과 시 sonnet, 미달 시 opus | 비용 대비 품질 |
| 재판정: 확신 낮음 항목 | opus | 애매한 건만 상위 모델 |
| 감사: 무작위 5% 재판정 | opus | 오류율 추정 |
| 병합·앱 반영 | sonnet | 코딩 |
| 독립 검증 | sonnet | 기준 재확인 |

### 판정 출력 (항목별)

`keep`(bool), `dropReason`(뺄 때 코드), `mood`(rest|walk|new|food), `reason`(한국어 한 줄), `confidence`(high|low)

### 성공 기준 S1'

- **완전성**: 사전 필터 통과 항목 100%가 판정을 받는다(누락 0).
- **보정**: 검수 모델과 기준 세트의 keep/drop 일치율 ≥ 85%, keep 항목의 mood 일치율 ≥ 80%. 미달이면 전 항목 검수를 opus로 한다(기준을 낮추지 않음).
- **감사**: 무작위 5% 재판정의 불일치율을 보고한다(합격선 없음, 투명성용).
- **이유 문장**: 15~70자, 가격·운영시간·요일·평점 표현 0건(정규식 검사), 입력 텍스트에 없는 사실 추가 금지(감사에서 점검).
- **앱**: 대표 좌표 4곳 × 버튼 5개 = 20조합 모두 60분 안에 카드 3장, 전체 테스트 통과, 빌드 성공, S3~S5 유지.

### 성공 기준 S8

- **S8-1 지역 커버리지**: 15지역 × (쉬기·걷기·새로운 것·아무거나·먹기-식사·먹기-카페) 6가지 = 90조합 모두 서로 다른 카드 3장, 모두 60분 안(실데이터 테스트).
- **S8-2 기준 전환**: 위치 전환 시트에 내 위치 / 숙소 / 지역 15곳(제주시 쪽·서귀포 쪽 두 묶음). 지역을 고르면 라벨이 "<지역> 기준"이 되고 새로고침 뒤에도 유지. GPS 거절 시 같은 지역 목록을 보여 준다.
- **S8-3 하트**: 모든 카드에 하트 버튼(`<button>`, `aria-pressed`, 접근 가능한 이름). 누르면 저장/해제, `localStorage['jeju.saved']`(id 배열)에 반영, 새로고침 뒤 유지. 하트를 눌러도 카드 링크(지도)로 이동하지 않는다.
- **S8-4 저장 목록**: 저장 0개면 상단 저장 버튼 없음(첫 화면 = 기분 5개 + 위치 전환). 1개 이상이면 "♥ N" 버튼 → 저장한 카드 목록, 현재 기준에서 가까운 순, 여기서도 해제 가능, 돌아가기 가능. 데이터에 없는 id는 조용히 제외.
- **S8-5 유지**: 기존 테스트·S3~S5 전부 유지, 390px 가로 넘침 없음, 가격·운영시간·평점 없음.

## 전체 QA·디자인 개편 (2026-09-30 사전 등록)

목표: 기능이 아니라 **쓰는 느낌**. 밤에 폰으로 내일을 고르는 사람이 AI가 만든 앱이라고 느끼지 않고, 생각 없이 편하게 흘러가야 한다. 전면 수정 허용. ADR-0025~0029의 범위(한 화면, 로그인·일정·결제 없음, 추가 수집 없음)는 유지.

측정 시점 기준선: 카드 이유 문장의 77.2%가 "~수 있어요"로 끝남.

### 성공 기준 S9

- **S9-1 코드 멱등성·정합성**: 최종 적대적 코드 감사(opus)에서 MAJOR 0건. 최소 점검 항목 — 빠른 연타·중복 탭, 핸들러 중복 등록(재마운트), 겹치는 위치 요청(늦게 온 응답이 새 결과를 덮지 않음), history push/pop 균형, 손상된 localStorage 값 허용, 서비스워커 갱신 시 새 spots.json 반영.
- **S9-2 경우의 수**: 시나리오 표(첫 방문·GPS 허용/거절/지연/제주 밖·오프라인·데이터 로드 실패·저장소 불가·사진 실패·긴 이름·후보 소진·320px·큰 글씨·다크 모드·동작 줄이기·뒤로가기·PWA 단독 실행 등)의 모든 행에 기대 동작이 있고, 각 행이 자동 테스트 또는 기록된 브라우저 확인으로 통과.
- **S9-3 문구**: 카드 이유 문장 — 어떤 한 종결 어미도 전체의 25% 초과 금지, "~수 있어요" ≤ 20%, 길이 15~70자, 금지 패턴 0건. opus 충실성 감사(표본 ≥5%)에서 원문에 없는 내용 비율 ≤ 2%. 초과 시 전 항목 충실성 검사 후 걸린 문장은 기존 문장으로 되돌림.
- **S9-4 디자인**: 320·390·430px × 라이트·다크에서 가로 넘침 0, 탭 대상 ≥ 44px, 본문 대비 WCAG AA(4.5:1), 디자인 스펙의 AI slop 체크리스트 위반 0 — 시각 QA(opus)가 스크린샷으로 판정.
- **S9-5 성능·외부 요청**: 빌드 JS+CSS gzip ≤ 50KB. 외부 폰트 CDN 금지(필요하면 자체 호스팅, 폰트 합계 ≤ 150KB). 외부 요청은 이미지 CDN과 링크 이동뿐.
- **S9-6 접근성**: 키보드 포커스 표시, 모든 버튼 접근 가능한 이름, prefers-reduced-motion 존중, 글자 200%에서 핵심 버튼 잘림 없음.
- **S9-7 회귀 없음**: S1'·S2~S8 전부 유지, 타입 검사·테스트·빌드 통과.
