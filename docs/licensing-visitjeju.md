# 비짓제주 데이터·사진 이용 근거 검토

조사일: 2026-10-01. 대상은 "P의 여행" 정적 웹 앱(`apps/web`). 지금은 무료·비상업이고 나중에 상업화할 수도 있다.
법률 자문이 아니다. 공개된 문서를 읽고 정리한 것이다.

## 1. 우리 데이터가 어디서 왔나 (저장소 기준)

- 수집 경로: 비짓제주 자체 OPEN API(`https://api.visitjeju.net/vsjApi/contents/searchList`, `apiKey`, `locale=kr`). visitjeju.net의 신청 양식으로 API 키를 받았다(ADR-0023, `apps/api/src/infrastructure/visitjeju/VisitjejuAdapter.ts`). data.go.kr를 거친 호출이 아니다.
- 받은 필드: `title`, `latitude/longitude`, `tag`, `introduction`, `repPhoto.photoid.thumbnailpath/imgpath`(ADR-0023 표).
- 웹에 나가는 것(`apps/web/public/spots.json`, 2,955곳): `name`, `lat/lng`, 새로 쓴 `reason`, `image`. `image` 2,955곳 모두 `https://api.cdn.visitjeju.net/photomng/thumbnailpath/...` 핫링크다.
- `reason`: `apps/web/review/`에서 보유 텍스트(소개·태그·요약·코멘트)를 근거로 LLM이 새로 쓴 한 줄 문장이다. 원문에 없는 표현은 감사에서 뺐다(`apps/web/review/REPORT.md`). 원문 문장을 그대로 옮기지 않는다.
- 사진: 서비스워커는 같은 출처의 GET만 캐시한다(`apps/web/sw/sw.js` 48행). 그래서 비짓제주 사진은 저장·재배포하지 않고, 브라우저가 CDN에서 바로 받는다. `<img>`에 `referrerpolicy="no-referrer"`가 붙어 있다(`src/render.ts` 321행).
- 출처 표시는 이미 있다. `index.html` 결과 화면과 저장 화면 하단에 "정보·사진: 비짓제주(제주관광공사)"가 나온다.
- ADR-0023에는 "비짓제주는 공공누리 1유형으로 명시"라고 적혀 있다. 이번 조사에서는 **이 표시를 찾지 못했다**(아래 3절 참고).

API 응답, 가이드, data.go.kr 목록, 콘텐츠 상세 페이지 HTML 어디에서도 공공누리(KOGL) 유형 표시(`kogl`, "공공누리")는 나오지 않았다. 핫링크나 CDN 사용을 허용하거나 금지하는 문구도 찾지 못했다.
CDN 응답 헤더는 `access-control-allow-origin: *`(CloudFront)다. Referer를 바꿔 받아 봐도 차단은 관측되지 않았다. 기술적으로 막지 않는다는 뜻일 뿐, 이용을 허락한다는 뜻은 아니다.

## 3. 충돌·공백

1. **S1·S2 "이용허락범위 제한 없음" vs S5 제14조 "상업적 목적으로 이용할 수 없습니다"·"무단 복제·배포 처벌".** S5는 2016년 웹사이트 약관이고 *사이트에 게재된 자료*가 대상이다. S1은 OPEN API에 붙은 공공데이터 이용 조건이다. 우리 데이터는 API로 받았으므로 S1이 더 직접 적용된다고 볼 여지가 크다. 다만 같은 콘텐츠가 사이트에도 실려 있고, S5는 API를 따로 빼 주지 않는다. 그래서 문서만으로는 결론이 나지 않는다.
2. **공공누리 유형 미표시.** ADR-0023의 "공공누리 1유형"은 이번에 확인한 1차 출처로 뒷받침되지 않는다. 한국관광공사 관광사진(포토코리아)과 혼동했을 가능성이 있다. data.go.kr의 "제한 없음"은 공공누리 유형과 다른 항목이다.
3. **사진 저작권자.** S5 제14조 2는 게시물의 권리가 게시자에게 있다고 한다. 업체가 직접 올린 사진(특히 음식점 1,704곳)은 공사가 아니라 업체나 촬영자가 권리자일 수 있다. 공공데이터법도 제3자 권리가 포함된 정보는 정당한 이용허락 없이는 제공 대상에서 빼도록 하므로(제17조 제1항 제2호), "제한 없음" 표시가 제3자 사진까지 확실히 덮는다고 보기는 어렵다.

## 5. 출처 표시

정해진 문구는 공개된 곳에서 찾지 못했다(S1~S4). S6과 저작권법 관행에 맞춰 아래를 권장한다.

- 문구: `정보·사진: 비짓제주(제주관광공사) · visitjeju.net`. 현재 문구에 링크만 더하는 것이다.
- 위치: 사진이 보이는 결과 화면 하단(현재 위치)과 앱 정보 영역(현재 위치)이면 충분하다. 카드마다 붙일 필요는 없다. 정적 랜딩은 모든 페이지 하단, 장소 페이지는 사진 바로 아래에도 `사진: 비짓제주(제주관광공사)`(ADR-0072).
- 공사가 회신에서 다른 문구나 공공누리 마크를 요구하면 그 문구로 바꾼다.

## 6. 남은 위험

- 이용 조건 문서끼리 충돌한다(3-1). 상업화하면 이 충돌이 바로 쟁점이 된다.
- 업체가 올린 사진은 권리자가 따로 있을 수 있다(3-3). 비상업이어도 권리자가 요청하면 내려야 한다.
- 공사가 CDN 경로를 바꾸거나 핫링크를 막을 수 있다. API 페이지에 "활용제한" 조항도 있다(S3).
- ADR-0023의 "공공누리 1유형" 기재는 근거가 확인되지 않았다. 다음 ADR 갱신 때 바로잡을지 결정이 필요하다(이 문서에서는 ADR을 고치지 않았다).

## 7. 권장 조치

1. 지금(비상업): 현재 방식(핫링크, 캐시 없음, 출처 표시)을 유지한다. 사진 재호스팅은 하지 않는다. 정적 랜딩도 같은 방식이고(ADR-0072), 문의 회신이 거절이거나 상업화를 정하면 랜딩은 `LANDING_PHOTOS=0`으로 먼저 끈다.
2. 공사에 이메일로 문의하고 회신을 저장소에 보관한다. 받는 곳: OPEN API 담당 daemadoo@ijto.or.kr(가이드 V1.1 기재, 064-740-6933). 대표 전화는 064-740-6000. 회신이 오면 이 문서와 ADR에 반영한다.
3. 상업화 결정 전에 2번 회신이 없으면 사진을 빼는 안을 준비한다.

## 4. 공사 확인 (2026-10-01)

- 사용자가 제주관광공사에 문의해 **사진 이용 가능** 확인을 받았다(사용자 전달, 2026-10-01). 앱 카드와 정적 랜딩·장소 페이지의 사진 핫링크·출처 표시 방식을 그대로 유지한다.
- 회신 원문(메일·통화 기록)은 사용자가 보관한다. 조건(출처 문구, 상업적 이용 범위)이 따로 있었다면 이 절에 추가한다. 상업화(광고·유료·제휴 수익)는 이번 확인 범위에 포함됐는지 기록이 없으므로 2절 판단(상업화 전 확인)을 유지한다.
