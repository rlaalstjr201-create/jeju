# 트렌드 06 — AI 검수를 붙이면 「지금 열린 팝업」 목록이 쓸 만해지나 (사전등록)

작성 2026-11-04 KST, 실행 전에 커밋한다. 커밋 뒤에는 검수 지시·판정·결론 규칙을 바꾸지 않는다. 검수는 한 번이다.

## 묻는 것

트렌드 05: 규칙 후보는 재현율 58.1%, 정밀도 15~30%로 그대로는 내보낼 수 없다. 주인 조건은 「매일 비용이 드는 외부 AI API는 안 됨」.
운영안은 무료 수집(네이버·유튜브) + 규칙 후보 + **주 1회 Claude 검수(Claude Code 예약 작업, 구독 사용량)**다.
**그 검수가 「11-05에 성수·홍대에서 열린 팝업」 목록을 얼마나 정확하게 만드나?**

## 검수 (예약 작업을 흉내 낸 하위 에이전트 1개, Sonnet — 운영 비용에 맞춤)

- 입력: `docs/research/trend-seoul-05/02-candidates-v2.json`(규칙 후보 1,138개)과 원자료 `docs/research/trend-seoul-04/02-posts.json`(글 9,881건),
  `docs/research/trend-seoul-03/02-sources.json`(유튜브 235개). 이 세 파일만 읽는다(Read·Grep). **웹 검색·웹 읽기는 쓰지 않는다**(운영 때도 수집한 글만 본다).
- 기준 목록·판정 파일·결과 파일(`01-reference.md`, `03-match.md`, `04-result.md`)은 열지 않는다.
- 할 일: 성수(성수역 1.5km)·홍대(홍대입구역 1.5km) 각각, **2026-11-05에 열려 있다고 글에서 확인되는** 팝업스토어·팝업 체험·기간 한정 행사 목록.
  항목마다 이름·장소(건물·주소, 글에 있는 만큼)·기간·근거 글 링크 1~3개·확신(높음/보통). 기간이나 장소를 글에서 확인할 수 없으면 넣지 않는다.
- 이태원은 01부터 판정 제외였으므로 이번에도 만들지 않는다.

## 판정 (새 Opus 하위 에이전트, 이전 판정자들과 다름)

- **재현율**: 기준 목록(성수 23·홍대 8)의 몇 %가 검수 목록에 있나.
- **정밀도**: 검수 목록 전체(최대 40개, 넘으면 앞에서부터 40개)가 11-05에 실제로 반경 안에서 열렸나. 웹 확인 최대 40회. 확인 실패는 따로 센다.
  기준 목록에 없는데 실제로 열린 팝업은 「맞음」이다(기준 목록이 다 잡지 못하므로).

## 미리 정한 결론 규칙

- **재현율 60% 이상이고 정밀도(확인된 것 기준) 70% 이상** → 「이번 주 성수·홍대 팝업」 작은 판을 설계한다(매일 수집 + 주 1회 검수 예약 작업).
- **재현율 40~60% 또는 정밀도 50~70%** → 검수 지시를 한 번 고쳐 다른 날짜로 다시 잰다(같은 날짜로 다시 재지 않는다).
- **재현율 40% 미만이거나 정밀도 50% 미만** → 트렌드 층은 만들지 않고, 카드 영업시간 표시 등 다른 개선으로 돌아간다.

## 미리 적는 예상 (틀려도 고치지 않는다)

실행자(Claude) 예상: 재현율 50~65%(글에는 93.5% 있지만 기간·장소가 글에 다 적혀 있지는 않음), 정밀도 70~85%.
