# 트렌드 03 — 유튜브 영상을 더하면 얼마나 잡히나 (사전등록)

작성 2026-11-04 KST, 실행 전에 커밋한다. 커밋 뒤에는 출처·판정·결론 규칙을 바꾸지 않는다. 출처 조회는 한 번이다.

## 묻는 것

주인 제안(2026-11-04): 「유튜브 api까지 해봐 … 관련 영상이나 트렌드같은거는 잘 포착할 수 있을 거 아니야」.
**YouTube Data API(S6) 영상 제목·설명이 성수·홍대 팝업을 얼마나 잡는가, 그리고 S1~S5에 더하면 결론이 바뀌는가?**
커뮤니티 게시물은 공식 API에 읽는 기능이 없어 넣지 않는다.

## 같은 것 (트렌드 01·02 그대로)

- 지역·반경·기준일(2026-11-05), **기준 목록은 `docs/research/trend-seoul-01/01-reference.md`**(S6을 보지 않고 만들어짐), 이태원 판정 제외.
- 판정 방법(새 Opus 하위 에이전트, 애매는 못 잡음, 정밀도 표본 최대 20개)과 결론 규칙의 기준값(60% / 30%).

## 새 출처 (실행자가 스크립트로 한 번)

- **S6 YouTube Data API v3** `search.list`: 「성수 팝업」·「홍대 팝업」·「이태원 팝업」·「한남 팝업」, type=video, order=date, regionCode=KR,
  relevanceLanguage=ko, publishedAfter=2026-10-01, 50개씩 최대 2쪽(검색 8회, 할당량 800). 찾은 영상의 전체 설명은 `videos.list`로 받는다.
  제목·설명·올린 날·채널 이름을 남긴다.
- 유튜브 API 약관상 받은 데이터는 이 측정에만 쓰고, 영상 내용은 결과 파일에 제목과 링크만 남긴다(설명 전문은 판정용 원자료 파일에만).

## 판정

- S6 재현율, 그리고 **여섯 출처(S1~S6) 합친** 재현율(S1~S3은 01 판정, S4·S5는 02 판정을 그대로 쓴다). S6이 새로 잡은 항목 수.
- 정밀도: S6이 낸 팝업 후보 표본 최대 20개.

## 미리 정한 결론 규칙

- 여섯 출처 합친 재현율 **60% 이상** → 2단계(구별 「이번 주」 목록)를 만든다.
- **30~60%** → 가장 잘 잡는 출처 하나 또는 둘로, 「일부만 보여 준다」를 밝히는 작은 판을 검토한다.
- **30% 미만** → 공식 출처로는 만들지 않는다.

## 미리 적는 예상 (틀려도 고치지 않는다)

실행자(Claude) 예상: 유튜브는 브이로그·쇼츠가 「성수 팝업 투어」처럼 여러 팝업을 한 영상에 묶어 설명란에 적는 경우가 있어 블로그와 비슷하게
잡는다(15~30%). 여섯 합쳐 **35~50%**.
