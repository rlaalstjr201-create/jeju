# 문화생활 품질 04 — KOPIS 공연을 섞은 목록 (사전등록)

작성 2026-11-04 KST. 측정 전에 커밋하고, 커밋 뒤에는 장면·시각·자료·판정·통과 기준을 바꾸지 않는다. 측정은 한 번이다. ADR-0113 7.

## 무엇을 재나

같은 장면에서 앱 목록 두 개를 눈가림으로 비교한다.
- **A**: 서울시 문화행사만으로 고른 목록(지금 배포된 `pickCulture`, 품질 03 통과 코드).
- **B**: 서울시 문화행사 + KOPIS 공연을 합쳐 같은 `pickCulture`로 고른 목록(ADR-0113 구현 코드).
X/Y 섞기는 장면 번호가 홀수면 X=B. 후보 풀은 그 장면의 직선 3km 안 서울 행사와 KOPIS 공연(가까운 순 각각 최대 40개, 시간·출연 포함)이다.

## 장면·시각

- 장면 6: 대학로(37.5822, 127.0019), 홍대(37.5572, 126.9245), 광화문(37.5759, 126.9768), 성수(37.5446, 127.0560), 강남역(37.4979, 127.0276), 잠실(37.5133, 127.1001).
- 시각 3: 목 **2026-11-05** 14:00, 토 **2026-11-07** 19:00, 목 **2026-11-05** 22:00. 18장면.
- 자료: 측정 직전 서울 API 전체 1회, KOPIS 그날 서울 목록과 공연 상세·공연장 상세를 1회 받아 `01-rows-fetched.json`에 남긴다.

## 판정

- 판정자: 새 Opus 하위 에이전트 하나(앞선 판정자들과 다름), 웹 확인 최대 20회. 목록마다 항목별 「갈 만함/그저 그럼/쓸모없음」, 후보 풀에서 빠진 「놓침」, 목록 점수 1~5.
- **통과 기준**(모두):
  1. B 평균 점수 4.0 이상.
  2. B 쓸모없음 목록당 평균 1개 이하, 놓침 목록당 평균 1개 이하.
  3. B 평균이 A 평균보다 낮지 않음.
  4. 22시 장면 6개 중 5개 이상에서 B에 이미 끝났거나 시작해 버린 공연·닫은 곳이 없음.
- 통과하면 배포 단계로 간다. 못 하면 원인을 적고 주인과 다음 걸음을 정한다(재측정은 다른 날짜로만).

## 미리 적는 예상 (틀려도 고치지 않는다)

실행자(Claude) 예상: B 평균 3.9~4.4, A보다 0.1~0.4 높음. 대학로·홍대에서 차이가 크고, 강남역·잠실은 거의 같다.
가장 걱정: 대학로에서 연극이 두 개까지 차서 같은 느낌의 목록이 될 것, 출연이 빈 소극장 공연이 「누가 하는지 모름」으로 낮게 평가될 것.
