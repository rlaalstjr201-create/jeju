# 유명한 곳 인기 측정과 순서 — 사전등록 (2026-10-16, 측정 전 고정)

근거: ADR-0092 Amendment 2(주인 결정, 2026-10-16: 「가로 새로 재고 인기순까지」, 「거리순도 중요해 … 인기 점수랑 거리점수를 적절하게 조합」). 이 문서는 측정을 돌리기 전에 커밋한다. 측정 뒤에 고치지 않는다. 바꾸려면 주인 승인을 받고 새 회차로 한다.

## 1. 대상

출하 `apps/web/public/spots.json`에서 `famous: true`인 곳 전부(73곳, id 순서). 호출은 곳마다 2번, 모두 146번이다(상한 150).

## 2. 검색어 (곳마다 하나, 고정)

`apps/web/scripts/famous-measure.mjs` `popQuery(name)`:
- 이름의 공백을 하나로 줄이고, 끝의 「(…)」 별칭을 뗀다. 예: `어승생(어승생악)` → `어승생`, `다랑쉬오름(월랑봉)` → `다랑쉬오름`.
- 이름에 `제주`가 없으면 끝에 ` 제주`를 붙인다(ADR-0051 `buildBuzzQuery`와 같은 꼴). 예: `성산일출봉 제주`, `우도 제주`. `제주`가 있으면 그대로다(`제주4.3평화공원`).
- 따옴표·연산자는 쓰지 않는다.

73곳의 검색어 목록은 측정 파일 `apps/web/review/famous/pop-01.json`의 `query`에 그대로 남는다.

## 3. 호출

- 네이버 검색 API `https://openapi.naver.com/v1/search/blog`와 `…/cafearticle`, `query`와 `display=1`. 응답의 `total`만 쓴다.
- 키는 저장소 루트 `.env`의 `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET`(ADR-0051 파이프라인과 같은 키). 출력·기록·커밋하지 않는다.
- 차례로 부르고 호출 사이에 150ms를 쉰다. 다른 네트워크 호출은 없다.
- **확인 실패**: 응답이 200이 아님(429 포함), 네트워크 오류, `total`이 0 이상의 정수가 아님. 그 값은 `null`로 적고 상태를 남긴다. 0으로 적지 않는다. 같은 회차에서 다시 부르지 않는다.
- **한 번만 돈다**: 파일이 이미 있으면 스크립트가 멈춘다. 확인 실패가 하나라도 있으면 그 결과를 커밋하고, 순서 구현 전에 멈춰 보고한다. 다시 재려면 주인 승인이 필요하다.

## 4. 인기 점수 `pop` (0~1)

- 곳마다 `n = blog + cafe`(블로그와 카페 글 수를 같은 무게로 더함, ADR-0051과 같음).
- `pop = (log10(1 + n) − 최소) ÷ (최대 − 최소)`. 최소·최대는 73곳의 `log10(1 + n)`이다. 소수 셋째 자리까지 반올림한다.
- 로그를 쓰는 이유: 글 수는 몇십 배씩 차이 나는 긴 꼬리 분포다. 열 배 더 많이 찾는 곳이 같은 간격만큼 앞서게 한다.
- `scripts/famous.mjs`가 측정 파일에서 계산해 유명한 곳에만 `pop`으로 붙인다. 측정이 없거나 확인 실패인 유명한 곳이 있으면 멈춘다.

## 5. 순서 (유명한 데 가 보고 싶어만)

카드를 고르는 후보와 범위·넓히기는 지금과 같다(`pick.ts` `pool`). 그 안의 순서만 바꾼다.

- `가까움 = max(0, 1 − 이동 분 ÷ 범위 최대 분)`. 이동 분은 앱이 이미 쓰는 범위 기준의 분(걸어서면 걷기, 아니면 차, 5분 단위)이고, 범위 최대는 15·30·60분이다. 넓혀서 범위 밖이면 0이다.
- **`합 = 0.5 × pop + 0.5 × 가까움`**, 높은 순.
- 무게를 반반으로 둔 이유: 주인이 둘 다 중요하다고 했다. 차로 30분 범위에서는 이동 5분 차이가 가까움 0.167, 합 0.083이다. pop이 0.083 앞서려면 대략 글 수가 두 배쯤 많아야 한다. 측정 범위가 로그로 네 자릿수(만 배)쯤이면 그렇다. 그래서 「훨씬 많이 찾는 곳은 몇 분 더 멀어도 앞서고, 조금 더 찾는 곳은 많이 멀면 못 앞선다」가 된다.
- 같은 합이면 지금 정렬(점수 → 장날 → 철 → 이동 → id)을 따른다.
- 밤(ADR-0091): 산길·배로 가는 섬이 다른 곳 뒤로 가는 것이 첫 키이고, 그 안에서 합 순이다.
- 순환·`다른 3곳 보기`: 지금처럼 안 본 곳 → 본 곳 → 직전 3장 순서이고, 각 칸 안에서 합 순이다.
- 기준이 없을 때(홈 `제주 인기:`): 가까움을 잴 수 없어 `pop` 높은 순이다(밤엔 산길·섬 뒤).
- 실내: 유명한 곳의 실내도 날씨와 상관없이 후보다. 비 와요(실내만)는 지금처럼 실내만 남긴다.
- 다른 기분은 바꾸지 않는다.

## 6. 미리 정한 점검 (결과는 통과·실패 그대로 보고, 무게를 다시 맞추지 않는다)

- C1(합성): A `pop 0.8`·15분, B `pop 0.3`·5분, 차로 30분 → A가 앞선다.
- C2(합성): A `pop 0.55`·25분, B `pop 0.45`·5분, 차로 30분 → B가 앞선다.
- C3(합성): 같은 합이면 지금 정렬(점수 → … → id)대로다.
- C4(실데이터): 15개 동네 × 첫 탭과 `다른 3곳 보기`: 둘째 3장은 첫 3장을 빼고 합 순으로 이어진다.
- C5(실데이터, 보고만): 성산 동네 기준 차로 30분 낮의 첫 3장에 성산일출봉이 있는가. 서귀포 시내 첫 3장에 천지연폭포·정방폭포가 있는가. 실패해도 무게를 바꾸지 않고 보고한다.
- C6(보고만): 이름이 흔해 글 수가 부풀었을 곳(예: `우도`, `새섬`, `비양도`, `소천지`, `방선문`)의 글 수를 따로 적는다.
