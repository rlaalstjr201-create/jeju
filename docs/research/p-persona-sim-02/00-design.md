# 가상 여행자 실험 2차 — 단계별 실험 체계 설계

작성 2026-10-09. 앞 실험: `../p-persona-sim-01/`(1차, 「낮은 신뢰」). 이 문서는 실험 **체계**의 설계다. 각 단계의 판정 규칙은 그 단계에 들어가기 전에 따로 사전등록한다(`10-stage0-prereg.md` 등).

## 한 줄 요약

신약 시험처럼 단계를 나눈다. 먼저 **시뮬레이터라는 도구가 믿을 만한지**를 시험하고(0단계), 통과해야만 흐름 비교로 넘어간다. 흐름 비교는 넓게 많이 돌려 후보를 떨어뜨리고(1·2단계), 남은 것만 새 표본으로 한 번 확증하고(3단계), 마지막은 실제 사용자 기록으로 확인한다(4단계). 패널 크기는 미리 정하지 않고 앞 단계에서 잰 잡음과 효과 크기로 계산한다.

## 1. 1차 실험에서 신뢰를 깎은 원인 (고칠 대상)

| 원인 | 근거(1차 결과) | 성격 |
|---|---|---|
| 흐름 설명 글이 반응을 끈다(점화) | 화면이 같은 상황(S2·S4)에서도 A가 B보다 6%p 낮음, p<.05 | 편향 — 표본을 늘려도 안 줄어듦 |
| 한 호출이 여러 명을 연기 → 묶음마다 말투 | 같은 흐름 안 묶음별 S2 성공률 9~14%p 흔들림 | 편향 + 잡음 |
| 화면 없이 상상으로 누름(열린 고리) | 카드 내용 상상, 엔진 규칙 불일치로 막힘 359건 오집계 | 측정 오류 |
| 한 사람 1회 실행 | 같은 100명 재실행 일치 83%, 차이 3.0%p | 잡음 |
| 다른 모델과 안 맞음 | Haiku 교차 일치 61~69% | 타당도 불명 |
| 정답을 아는 시험이 없음 | 도구가 실제 차이를 잡는지, 없는 차이를 만드는지 모름 | 검증 부재 |
| 실제 사람 자료와 대조 없음 | R12 미실행 | 보정 부재 |
| 저장 목록 이름이 내부 번호, 동행 무관한 제약 | 40-report 한계 | 조건 품질 |

표본을 늘리면 줄어드는 것은 「잡음」 두 줄뿐이다. 나머지는 설계를 바꿔야 줄어든다.

## 2. 단계 구조

각 단계는 **들어가기 전 사전등록 → 1회 실행 → 통과 기준 판정**. 통과 못 하면 다음 단계로 가지 않고, 원인 보고 → 무엇을 고칠지 주인 승인 → 고친 뒤 그 단계를 새 번호로 다시(같은 설정으로 통과할 때까지 돌리지 않는다). 탐색 단계에서 쓴 인물·실행 번호는 확증 단계에 다시 쓰지 않는다.

### 0단계 — 도구 검증 (흐름 비교 없음)

시뮬레이터가 「있는 차이는 잡고, 없는 차이는 만들지 않고, 사람과 비슷하게 움직이는지」만 본다. 신약으로 치면 측정 장비 교정이다.

| 시험 | 방법 | 통과 기준(안, 사전등록에서 확정) |
|---|---|---|
| 0-1 A/A(없는 차이) | 같은 흐름을 이름·순서만 바꿔 두 팔로 | 차이 95% 구간이 ±2%p 안 |
| 0-2 음성 대조(겉모양만 바뀐 것) | 버튼 문구 동의어, 색, 아이콘만 바꾼 판 | 차이 없음(동등성 검정 TOST, 경계 ±3%p) |
| 0-3 양성 대조(뻔히 나쁜 것) | 하트 버튼 숨김 / 저장 목록 버튼을 메뉴 안으로 / 「다른 3곳」을 화면 밖으로 | 성공률이 유의하게 떨어짐 |
| 0-4 용량-반응 | 0-3의 망가뜨림을 1·2·3단계로 점점 세게 | 단계마다 단조로 나빠짐 |
| 0-5 재검사 | 같은 사람·같은 설정 k회(실행 번호만 다름) | 사람 단위 성공 확률의 재검사 상관, 집계 차이 ≤ 2%p |
| 0-6 교란 격자(멀티버스) | 온도, 인물 문장 바꿔 쓰기, 프롬프트 언어(한/영), 선택지 순서, 서사 유무, **한 호출당 인원 1·10·50** | 각 축에서 0-3의 방향이 유지되는 비율 ≥ 90%. 한 호출당 인원 효과를 수치로 보고 |
| 0-7 모델 교차 | Opus·Sonnet·Haiku(+가능하면 다른 회사 모델 1개) | 0-3 방향 일치. 개인 일치율 기록 |
| 0-8 실제 기록 정합 | 지금 앱(A)만 돌려 실제 기록과 같은 지표 비교: 날짜 고른 상태 하트 비율, 밤 하트 비율, 하트 뒤 저장 목록 재방문, 첫 길찾기까지 탭 수 | 실제 값이 시뮬 90% 구간 안 or 상대 오차 기준(사전등록). 실제 기록 표본이 작으면 「판정 보류」 |
| 0-9 알려진 UX 사실 재현 | 선택지가 많으면 늦어진다, 화면 아래 정보는 덜 본다, 한 손·누운 자세에서 실수 증가 | 방향 재현 |

0-6에서 「한 호출당 인원」이 효과가 있으면 1인 1호출로 고정한다. 0-8·0-9가 실패하면 그 축의 결론(예: 탭 수 절댓값)은 이후 단계에서 쓰지 않는다.

### 1단계 — 안전성·부작용 (소규모, 우열 비교 아님)

- 50~100명 × 후보 흐름 전부. 목적: 막힘, 엉뚱한 탭, 부담·혼란 코드, 엔진 오류, 실행 로그 누락을 찾는다.
- 부작용 목록을 미리 정한다: 하트 수 감소, 저장 목록 재방문 감소, 계획형 동행의 정리 실패, 날짜 지난 곳 찾기 실패, 첫 화면 이탈.
- 통과: 막힘 원인이 흐름 결함이면 시안 수정 → 1단계 재실시(새 번호). 결함 없으면 2단계로.

### 2단계 — 탐색 (여러 팔, 단계마다 탈락)

다중 팔·다단계(MAMS) 방식: 공통 대조(지금 앱 A)에 여러 후보를 붙이고, 중간 점검에서 「대조보다 나을 가능성이 낮은」 팔을 미리 정한 무익성 경계로 떨어뜨린다.

- 팔(아래 3절 D 목록에서): A, A′(최소 수정), B 변형 2~4개, C.
- 요인 설계: 「담을 때 날짜」 × 「지난 날 처리」 × 「♥ 숫자 세는 법」처럼 독립 요소는 팔을 따로 만들지 않고 요인으로 교차한다.
- 중간 점검 2회, 무익성 경계는 사전등록. 남은 1~2개 팔과 효과 크기·분산을 3단계 표본 크기 계산에 넘긴다.
- 이 단계 결과는 「탐색」이라 결론으로 쓰지 않는다.

### 3단계 — 확증 (1회)

- 새 인물 패널, 새 실행 번호, 사전등록한 1차 지표 하나(예: 다음 날 꺼내기 성공)와 최소 의미 효과(예: 3%p).
- 표본 크기는 2단계에서 잰 「짝 엇갈림 비율」과 사람당 반복 k로 계산(1차 값 20%, k=1이면 3%p 검출 80% 검정력에 집단당 약 1,700명. k를 늘리면 줄어듦).
- 0단계를 통과한 모델 전부에서 같은 방향이어야 결론. 다중 비교는 Holm 보정. 「해롭지 않다」 주장은 동등성 검정으로.

### 4단계 — 실제 확인

- 앱에 숨김 스위치로 후보 흐름을 넣고 일부에게만 연다(또는 실제 사람 5~8명 과제 시험).
- 실제 기록으로 1차 지표와 부작용 지표를 본다. 소수 실제 자료로 시뮬 추정치의 치우침을 바로잡는 예측 보정 추론(PPI: 많은 시뮬 값 + 적은 실제 값으로 편향을 추정해 빼는 방법)을 적용해 시뮬레이터 신뢰도를 다음 실험용으로 갱신한다.

## 3. 실험 조건 카탈로그 (넓게 — 단계마다 여기서 골라 쓴다)

### A. 시뮬레이터 실행 방식
- 열린 고리(1차 방식, 순서 한 번에) vs **닫힌 고리**(화면 보고 한 번 누르고 다음 화면 받음)
- 화면 표현: 흐름 설명 글 / 엔진이 그린 화면 글 / **실제 앱 접근성 트리(Playwright)** / 스크린샷(시각 모델)
- 한 호출당 인원 1·10·50, 맥락 공유 여부
- 모델·온도·언어·프롬프트 문장 변형(교란 격자)
- 「너무 유능함」 보정: 읽기 건너뜀 확률, 화면 아래 정보 무시, 손가락 오탭(인접 요소 대신 누름)을 엔진이 확률로 주입하는 조건 vs 주입 없음

### B. 인물 패널
- 속성 고정(실태조사 분포) / 서사 먼저 만들고 분포에 맞춰 고르기(Anthology) / 서사 없음
- 다양성: 서사 임베딩 중복 제거, 전형에서 벗어난 조합(계획형 P, 즉흥형 J) 일정 비율
- 신체·환경: 폰 숙련도, 큰 글씨 사용, 한 손, 누운 자세, 햇빛 아래, 아이 안고 있음
- 동행: 혼자 / **두 에이전트 동행**(계획 담당 + P, 실제로 대화하며 한 폰을 같이 봄) / 단체
- 언어: 내국인 한국어 / (참고) 외국인 영어 — 제주 범위 안에서만
- 제약은 동행·나이와 맞는 것만 붙인다(1차 오류 수정)

### C. 상황·시간
- 시간대: 아침 출발 전 / 낮 현장 / 저녁 식사 뒤 / 밤 누워서 / 자정 넘어
- **여러 날 여정**: 2박 3일·3박 4일을 처음부터 끝까지, 날마다 기억 요약을 다음 날로 넘김(밤에 담고 다음 날 꺼내기, 날짜가 지나는 효과가 자연스럽게 나옴)
- 장소: 제주 밖 집(며칠 전) / 공항 / 숙소 / 현장 / 이동 중 차 안(동승자가 폰 봄)
- 사건: 비가 옴, 장날, 가려던 곳 휴무, 동행이 갑자기 다른 데 가자고 함, 배터리 부족·느린 통신
- 재방문 간격: 다음 날 / 3일 뒤 / 여행 끝나고 2주 뒤 다시 열기
- 목적: 「지금 갈 곳」 / 「내일 염두」 / 「동행 설득」 / 「담아 둔 것 정리」 / 「그냥 심심해서 훑기」

### D. 흐름 후보 (비교 대상)
- A 지금 앱
- **A′ 최소 수정**: 날짜 고르기는 그대로 두고, 밤(예: 20시 이후)에 `지금`으로 담으면 「내일」에 담기 / 지난 날을 접지 않고 「담아 둔 곳」으로 되돌리기 / ♥ 숫자에 지난 날 포함 — 각각 요인으로. 「흐름을 바꿀 필요 없이 이것만 고치면 되는가」를 가르는 팔
- B 변형: 「날짜에 두기」 위치(줄마다 / 목록 위 묶음 편집 / 길게 누르기), 날짜에 둔 날이 지나면(되돌림 / 접음 / 지움), 장날·철 표시를 저장 목록에서 볼지
- C 날짜 없음
- 흐름 무관 개선(별도 요인): 「다른 3곳」 위치, 대중교통 이용자 이동 문구, 밤·제주 밖에서 「오늘」 표기

### E. 측정
- 엔진 로그: 성공, 탭 수, 뒤로 가기·되돌아감, 막힘, 화면을 떠남, 놓친 정보
- 여러 날 지표: 다음 날 꺼내기 성공, 담은 곳 중 실제 간 비율, 여행 끝 저장 목록 상태
- 사후 질문은 행동 사실만(어디서 멈췄나, 무엇을 다시 확인했나). 점수형 만족은 보조
- 부담·혼란 코드 분류는 시뮬레이터와 다른 모델 + 규칙 사전, 무작위 50건 사람 검수(정밀도·재현율)
- 선호 순위: 순서 바꿔 두 번, 다르면 「불명」

### F. 분석
- 사람·호출 묶음·모델을 무작위 효과로 둔 혼합 로지스틱 모형
- 사람당 k회 반복 → 사람별 성공 확률
- 효과 = 흐름 차이 − A/A 차이(0-1에서 잰 바닥 잡음)
- 멀티버스 보고: 교란 격자 모든 칸에서 결론 방향이 같은 비율
- 다중 비교 Holm, 해롭지 않음은 동등성 검정
- 실제 자료가 생기면 PPI로 보정

## 4. 실험 도구 (`sim-lab`)

1차 `sim/` 코드(표본·엔진·재생·분석)를 살리고 붙인다.

```
experiments/<단계>-<번호>.json   설정: 팔, 요인, 패널, 상황, 모델, 온도, k, 실행 번호, 통과 기준, 호출 상한
runner      1인 1호출 실행기(닫힌 고리). 화면은 엔진 글 또는 실제 앱(Playwright, 숨김 스위치 ?variant=)
store       원본 요청·응답·모델 버전·시각 전부 JSONL로 보관
replay      로그 → 지표(엔진이 셈)
gate        사전등록 기준으로 통과/실패/보류 자동 판정, 결과 표
ledger      단계별 실행 이력(같은 설정 재실행 금지 확인)
```

- 실행 수단 두 가지: (1) Anthropic API 직접 호출 — 1인 1호출·온도·번호 통제가 쉽다(API 키·예산 필요) (2) Claude Code 하위 작업 — 키는 필요 없지만 1인 1호출이면 호출 수가 너무 많아 0-6에서 「한 호출당 인원」 효과가 작다고 나올 때만 묶음 허용.
- 실제 화면 실행에는 앱에 `?variant=` 숨김 스위치가 필요하다(A′·B·C를 앱 코드로 구현). 이건 제품 코드 변경이라 스펙→계획 절차를 따른다. 그 전에는 엔진이 그린 화면 글로 닫힌 고리를 돌린다.

| 0 | 200명 × 9개 시험(일부 공유) × k=3, 상황당 4~6단계 → 수만 호출 | 교란 격자는 50명 소패널로 |
| 1 | 100명 × 팔 5~6 × 상황 2~3 | |
| 2 | 300~500명 × 남은 팔, 중간 점검 2회 | |
| 3 | 2단계 계산값(수백~2천 명) × 팔 2 × 모델 2~3 | 1회 |

1차 본 실행(6,000회)보다 0단계만으로도 호출이 많다. 0단계는 작은 패널로 먼저 돌려 비용을 보고 확대 여부를 정한다.

## 6. 정한 것 (2026-10-09 주인)

1. 실행 수단: **Claude Code 하위 작업**. 완성도를 위해 호출 수는 감수한다. 한 하위 작업 = 한 묶음(0단계 기본 10세션), 묶음 수백 개는 워크플로로 돌린다.
2. 4단계 「실제 확인」은 사람을 모집해 시험하지 않고, **업데이트를 배포한 뒤 실제 사용자의 GA4·자체 기록·의견 등 자료로 확인**한다. 그래서 0-8(실제 기록 정합)은 지금 자료가 없어 보류하고(2026-10-04 하루, 기분 탭 2회), 4단계에 필요한 기록 항목(하트 시각대·날짜 상태·다음 날 저장 목록 열기)을 먼저 넣어야 한다.
3. 모델: 시뮬레이터 기본 Opus(1차와 비교 가능), 교차 Sonnet·Haiku·Fable.
