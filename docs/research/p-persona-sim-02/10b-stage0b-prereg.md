# 0b단계 사전등록 — 도구 검증 다시 (고친 설계, 주 모델 Sonnet)

작성 2026-10-10, 실행 전. 0단계(`10-stage0-prereg.md`)는 G6 재검사로 **실패**했다(`20-stage0-results.md`). 이 파일은 실행 뒤 고치지 않는다.

## 0단계에서 바꾼 것과 이유

| 바꾼 것 | 이유 |
|---|---|
| **주 시뮬레이터 Opus → Sonnet** | 2026-10-10 주인: 「Opus여야 할 근거가 없으면 Sonnet」. Opus를 고른 이유는 1차와 같은 모델이라는 것뿐이었고, 실제 사람에 더 가깝다는 근거는 없다(0단계 교차 결과에서도 우열을 가를 자료 없음). 0단계 자체가 모델별 검증이라, 바꾸려면 지금 0b에서 Sonnet을 검증하는 게 맞다. Opus는 교차 모델로 남긴다. 사용 한도에 덜 걸리는 것도 이유다 |
| **「없는 차이」 비교의 기준 = base·dup 두 표본 평균** | 0단계에서 같은 화면 비교가 모두 음수였다. 공통 기준(base) 한 표본의 운이 모든 비교에 실린 탓으로 본다. G1은 base 대 dup 그대로, G2·G5는 두 표본 평균 대비 |
| **재검사 120 → 240명**(base·L3) | 재검사의 우연 폭을 줄인다 |
| **1인 1호출은 판정 밖 「상한」 조건** | 0단계에서 1인 호출은 숨긴 것도 다 찾았다(L3 89.6%). 기본 실행은 10명 묶음으로 고정하고, 1인 호출은 「가장 유능한 경우」로만 보고한다. G7은 per50·영어·서사 없음 세 축 |
| **새 240명** | 0단계 결과를 보고 설계를 고쳤으므로 같은 사람을 다시 쓰지 않는다(0단계·파일럿과 겹침 0명 확인). 1차 인물 900명 중 다음 칸(P 158~313, 보통 86~169) |

지시문·화면 엔진·팔·상황·성공 규칙·묶음 구성(한 묶음 = 한 팔·한 상황·서로 다른 10명)은 0단계와 같다. 만들기: `node lab/build0.mjs --0b` → `work/stage0b/`(묶음 774개, 세션 6,912개). 교차 모델: Opus·Haiku·Fable(48명 소패널).

## 통과 기준 (`lab/analyze0.mjs`, `work/stage0b` 경로면 0b 규칙)

| | 시험 | 기준 |
|---|---|---|
| G1 | A/A: dup − base, 합침 | 95% 구간이 0을 포함 |
| G2 | neg − (base·dup 평균), 합침 | 90% 구간이 ±6%p 안 |
| G3 | L3 − base, S5 | 차이 ≤ −15%p, 95% 구간 위끝 < 0 |
| G4 | S5 base ≥ L1 ≥ L2 ≥ L3 | 이웃 뒤집힘 2%p 넘는 것 없음, L3 < base |
| G5 | L1~L3 − (base·dup 평균), S1·S2 합침 | 90% 구간이 ±6%p 안 |
| G6 | 재검사(240명, base·L3 각각 짝, 합침) | 합친 차이 절댓값 ≤ 4.5%p |
| G7 | per50·영어·서사 없음 | S5의 L3 − base가 음수이고 같은 48명 main 차이의 절반 이상 |
| G8 | Opus·Haiku·Fable | G7과 같은 기준 |

판정 규칙은 0단계와 같다: G1·G2·G3·G5·G6 중 하나라도 실패 → 실패, 모두 통과 + G4·G7·G8 통과 → 통과, 그 밖 → 조건부 통과(막히는 주장을 적는다).
