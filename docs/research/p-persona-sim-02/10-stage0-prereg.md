# 0단계 사전등록 — 시뮬레이터 도구 검증

작성 2026-10-09, 실행 전. 설계: `00-design.md` 2절 0단계. 이 파일은 실행 뒤 고치지 않는다(고치면 끝에 날짜·이유를 덧붙인다).

## 질문

흐름 비교에 들어가기 전에, 가상 여행자 시뮬레이터가 (1) 없는 차이를 만들지 않는지 (2) 있는 차이를 잡는지 (3) 실행 방식·모델을 바꿔도 같은 방향을 내는지 확인한다. 이 단계는 앱의 어느 흐름이 나은지 판단하지 않는다.

## 도구 (1차에서 바뀐 점)

- **닫힌 고리**: 시뮬레이터는 화면 글을 보고 버튼 하나를 누르고, 엔진(`lab/screen.mjs`)이 다음 화면을 그린다. 보이지 않는 버튼은 화면에 없다. 1차처럼 흐름 설명 글을 읽고 순서를 한 번에 적지 않는다.
- **실제 장소**: 카드와 저장 목록은 `apps/web/public/spots.json`의 실제 이름·이유·차로 시간이다.
- **조건 숨김**: 묶음 파일에는 팔 이름 대신 무작위 코드, 세션 id·씨앗은 해시. 파일럿에서 하위 작업이 지시를 어기고 묶음 파일을 연 일이 있어 넣은 장치다.
- **한 묶음 = 한 팔·한 상황, 서로 다른 사람**. 같은 사람의 다른 팔은 다른 묶음(다른 하위 작업)에 간다.
- 동행과 맞지 않는 제약(혼자인데 「아이를 챙기느라」)은 고쳤다.

## 패널·상황·팔

- 사람: 1차 인물 중 서사가 있는 900명에서 층화 240명(P 156 · 보통 84, 씨앗 `stage0-2026-10-09`). 2·3단계에는 이 240명을 쓰지 않는다.
- 상황: S1 밤 10시 숙소에서 내일 훑어보기(저장 없음) · S2 오후 2시 현장 · S5 다음 날 아침, 어젯밤 「내일」로 담아 둔 3곳(오늘 묶음에 보임, 걷기·먹기·쉬기/새로운 거 각 1곳)에서 하나로 가기.
- 팔(모두 지금 앱 A 위): `base` 그대로 · `dup` base와 똑같은 화면 · `neg` 문구만 동의어 · `L1` ♥ 버튼이 첫 화면 맨 아래(내려야 보임) · `L2` ♥ 버튼 대신 ⋯ 메뉴 안 「보관함」 · `L3` 첫 화면에서 저장 목록 길 없음, 카드 화면 맨 아래 작은 「담은 곳」 링크만.
- 성공(`done`, 엔진 판정 `screen.mjs judge`): S1 하트 1개 이상 또는 길찾기 · S2 길찾기 · S5 저장 목록에서 처음부터 있던 곳으로 길찾기. 15번 누르면 그만둔 것으로, 없는 버튼 3번이면 막힘으로.

## 통과 기준 (`lab/analyze0.mjs`)

짝 비교는 같은 사람·같은 상황끼리, 구간은 사람 단위 부트스트랩.

| | 시험 | 기준 |
|---|---|---|
| G1 | A/A: dup − base, 세 상황 합침 | 95% 구간이 0을 포함 |
| G2 | 음성 대조: neg − base, 합침 | 90% 구간이 ±6%p 안(동등성) |
| G3 | 양성 대조: L3 − base, S5 | 차이 ≤ −15%p, 95% 구간 위끝 < 0 |
| G4 | 용량-반응: S5 성공률 base ≥ L1 ≥ L2 ≥ L3 | 이웃끼리 2%p 넘는 뒤집힘 없음, L3 < base |
| G5 | 특이성: L1~L3 − base, S1·S2(저장 목록을 안 쓰는 상황) 합침 | 90% 구간이 ±6%p 안 |
| G6 | 재검사: retest − main(base·L3 각각 짝, 합침) | 합친 차이 절댓값 ≤ 4.5%p |
| G7 | 실행 방식 교란(per1·per50·en·nonarr) | 각 축에서 S5의 L3 − base가 음수이고, 같은 48명 main 차이의 절반 이상 |
| G8 | 모델 교차(sonnet·haiku·fable) | G7과 같은 기준 |

**판정**: G1·G2·G3·G5·G6 중 하나라도 실패 → **실패**(흐름 비교로 가지 않는다. 원인 보고 후 고칠 것을 정해 새 번호로 재실시). 모두 통과하고 G4·G7·G8도 통과 → **통과**. 앞의 다섯은 통과했지만 G4·G7·G8 중 실패가 있으면 → **조건부 통과**: 실패한 항목이 막는 주장을 적고 그 주장은 이후 단계에서 쓰지 않는다(예: G4 실패 → 「찾기 쉬움」 정도의 차이는 잴 수 없음, G8 실패 → 그 모델은 교차 확인에서 뺌, per1 축 실패 → 이후 1인 1호출 고정).

함께 보고(판정 아님): 팔×상황 성공률·탭 수·그만둠, 한 호출당 인원 1·10·50의 S5 base 성공률, 호출 간 흩어짐(관측 분산 ÷ 이항 분산), 모델별 S1 성공률, 사후 답의 부담 문장.

### 기준 보정 (결과 보기 전)

조건과 무관하게 화면의 버튼을 무작위로 누르는 가짜 정책으로 전체 6,192 세션을 30번 돌려, 「차이가 없을 때 우연히 실패하는 비율」을 쟀다(가짜 정책의 재검사 일치율 약 85~88%, 1차 Opus 재실행 일치 83%와 비슷).
- 처음 기준(A/A |차이| ≤ 3%p, 동등성 ±5%p 팔별, 재검사 팔별 ≤ 3%p): 30번 중 7~8번 핵심 기준 실패(약 25%) → 너무 빡빡함.
- 지금 기준(위 표): 새 30번 중 1번 실패(G1, 약 3%). G4는 무작위 정책이 용량-반응을 따르지 않아 30번 모두 실패(예상대로 → 「조건부 통과」).
- 뜻: 이 크기에서 도구의 **해상도는 약 4~6%p**다. 0단계를 통과해도 2·3단계에서 이보다 작은 흐름 차이는 A/A 차이를 빼고 더 큰 표본으로만 말한다.
