# 목표와 성공 기준 — 0c 이후 끝까지 (2026-10-10)

주인 지시(2026-10-10): 「목표 성공 기준을 정해 놓고 거기까지 진행해, 단계별로 묻지 말고, 그래프 엔지니어링으로」. 이 문서가 그 기준이다. 실행 중 바꾸지 않는다. 바꿀 일이 생기면 아래에 「수정 N」으로 이유와 함께 덧붙인다.

## 목표

저장·날짜 흐름(지금 앱 A, 최소 수정 A′, 날짜 없이 담고 나중에 날짜 B, 날짜 없음 C) 중 무엇을 앱에 둘지 사전등록한 시뮬레이션 단계로 정하고, 정한 흐름과 그 흐름을 실제 사용으로 확인할 기록(ADR-0085)을 앱에 넣어 배포한다. 4단계(실제 확인)는 배포 뒤 기록이 쌓여야 하므로 이 목표 밖이다. 그 준비(기록·보고서)까지가 끝이다.

## 그래프

```
0c(조건부 통과) ─▶ 1 안전성 ─▶ 2 탐색(MAMS, 중간 점검 1회) ─▶ 3 확증 ─▶ 결정 ADR ─▶ 스펙·계획 ─▶ 구현(기록 + 흐름) ─▶ 독립 리뷰 ─▶ 배포·push·실화면 확인
                    │ 결함          │ 모든 후보 탈락                │ 이긴 흐름 없음
                    ▼               ▼                               ▼
                 고쳐서 1b        A 유지 결정                     A 유지 결정 ──▶ 구현(기록만) ─▶ …
```

각 시뮬레이션 단계 = 사전등록 커밋 → 워크플로 실행 1회(sim-player, 동시 3) → 판정 스크립트 1회 → 결과 커밋. 결과를 보고 같은 설정으로 다시 돌리지 않는다.

## 공통 도구 설정 (0c가 허락한 범위)

sim-player · Sonnet · 한국어 · 10명 묶음 · 서사 있음. 0c에서 48명 묶음과 영어는 깨졌으므로 쓰지 않는다. 화면 엔진은 `lab/flow.mjs`(0단계 엔진과 같은 화면 규칙, 팔만 흐름 후보).

## 사람 배정 (겹침 금지)

1차 실험 서사 있는 900명(P 590 · 보통 310)을 0단계와 같은 섞기 순서로 쓴다.

| 쓰임 | 사람 |
|---|---|
| 0단계(Opus) | P 0–155 · 보통 0–83 — 흐름 비교에 안 쓰였으므로 **3단계 확증 예비** |
| 파일럿 | P 156–157 · 보통 84–85 |
| 0b·0c | P 158–313 · 보통 86–169 — 1단계에 그중 100명 재사용(안전성은 우열 비교가 아님) |
| 2단계 탐색 | P 314–443 · 보통 170–239 (200명) |
| 3단계 확증 | P 444–589 · 보통 240–309 (216명) + 필요하면 0단계 사람 |

## 단계별 성공 기준

| 단계 | 끝 조건 |
|---|---|
| 1 안전성 | `10-stage1-prereg.md`대로 판정. 결함 팔은 원인 기록 뒤 한 번 고쳐 1b, 또는 탈락 |
| 2 탐색 | 사전등록(1단계 결과로 수치 확정) 판정. 남은 팔 1~2개와 효과 크기·짝 엇갈림 비율 → 3단계 표본 계산 |
| 3 확증 | 1차 지표 하나(N 다음 날 꺼내기 성공), 대조 A. 이김 = 95% 구간 아래끝 > 0. 부작용 비열등: S2 성공 −5%p, P(계획 정리) 성공 −10%p 경계 |
| 결정 | ADR 발행: 이긴 흐름 채택 또는 A 유지(이긴 것 없을 때). 시뮬레이션은 「낮은~중간 신뢰」라 결정 근거에 1차 실험 조사·구조 분석을 같이 적는다 |
| 구현 | ADR-0085 기록(`specs/saved-flow-events.md` F1~F7) + 채택 흐름(있으면). 단위·e2e 전부 통과, 타입 검사 통과 |
| 리뷰 | Codex 사용 가능하면 Codex, 아니면 Claude 독립 리뷰(ADR-0058). MAJOR 0개 남김 |
| 배포 | Cloudflare Pages 배포, 실화면 확인(저장 목록 열기·하트·길찾기, 이벤트 전송), push 후 remote HEAD 대조 |

## 멈추는 조건 (그때만 주인에게)

- 사람만 할 수 있는 일(GA4 맞춤 측정기준 등록 등) — 끝에 모아서 알린다.
- 사용 한도로 실행이 끊김 — 끊긴 묶음은 한 번 다시, 그래도 안 되면 「안 끝남」으로 보고하고 진행.
- 0단계 판정 규칙처럼, 같은 설정 재실행이 필요해지는 경우 — 하지 않고 기록한다.
