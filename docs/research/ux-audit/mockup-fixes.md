# 목업 2판(A′·B′)의 문제 3개 해결책 (2026-10-03)

대상: `apps/web/design/proto-d/` 2판. 문제는 2판을 만들면서 드러났다. 기준은 `mockup-judgment.md`의 Q1~Q5다.

## 1. 노을 볼 곳 데이터가 없다

**지금**: 소개글(reason)에 「노을·일몰·석양·해넘이」가 있는 곳만 쓴다. 32곳이고 대부분 서쪽이다. 생선구이 사진처럼 노을과 무관한 첫 카드도 나온다.

**시험한 방법** (`sunset-check.mjs`, OSM 해안선 22,866점):

| 방법 | 오늘(10월, 해 지는 방위 264°) | 글에 노을 32곳 맞힘 | 문제 |
|---|---|---|---|
| A. 가장 가까운 해안의 바다 방향 | 376곳 | 15 (47%) | 북쪽 해안처럼 해안선이 해 지는 방향과 나란한 곳을 놓침 |
| B. 장소에서 해 지는 방향(±10°)으로 20km 선을 긋기. 300m 안에서 바다로 나가고, 그 뒤 본섬에 다시 닿지 않음 | 412곳 | **22 (69%)** | 건물 안 식당(해장국집 등)도 잡힘. 언덕(사라봉·군산오름)은 고도가 없어 놓침 |
| B + 실외이거나 소개글에 바다 단어 | **237곳**(+글 노을 = 247) | 22 + 10 | 표본 20개가 그럴듯함: 신창풍차해안도로, 박수기정, 이호-내도 해안도로, 월평포구 등 |

- 날짜마다 방위가 바뀐다: 6월 298°(512곳), 12월 242°(303곳). 「오늘」 기준으로 계산하면 계절이 반영된다.

**해결책 (3단)**:
1. **계산(빌드 때, 서버 없음)**: 방법 B + 실외/바다 단어 필터로 후보를 만든다. 날짜별 방위 3개(봄가을·여름·겨울)에 대해 `sunsetView: [..]`를 `spots.json`에 넣는다.
2. **확인**: 후보 약 250곳과 오름 후보 109곳을 원문(`review/out`) 기준으로 판정한다. ADR-0065(실내 판정)와 같은 방식이고, 무작위 5% 재채점 ±일치율 85% 이상이 통과 기준이다. 오름은 「정상이 트였다」가 원문에 있을 때만 넣는다. 원문은 이 PC에 없어 지금은 못 한다.
3. **표시 규칙**: 해 지기 2시간 30분 전부터, 차로 45분 안에 확인된 곳이 **3곳 이상**일 때만 「노을 볼 곳 ›」을 띄운다. 모자라면 「해 지는 시각 18:14」만 쓴다(Q5 정직성).

- 비용: 해안선은 빌드 때 한 번만 쓴다. 앱 용량은 장소당 플래그 몇 바이트다.
- 라이선스: OSM은 ODbL이다. 파생 값을 내보내므로 출처 줄에 「© OpenStreetMap contributors」를 단다. 국토지리정보원 해안선(공공누리)으로 바꿀 수 있는지는 확인 못 함.

## 2. 오늘 줄이 3줄까지 길어진다

**지금**: 비·노을·장날이 겹치면 누를 수 있는 줄이 3개다. 기분 목록이 y≈305까지 밀린다.

**해결책 (목업 반영, `mock2.js` today)**:
- **누를 수 있는 줄은 한 번에 하나.** 근거: 계기(prompt)는 하나일 때 행동으로 이어진다(Fogg 2009). 선택지가 늘면 결정 시간이 는다(Hick 1952). 판정 Q4의 비용 기준도 같은 방향이다.
- **우선순위는 「놓치면 사라지는 순서」로 정한다.**
  1. 비: 모든 추천이 바뀐다.
  2. 노을: 시간이 한정돼 있다.
  3. 장날: 하루 종일 열린다.
- 나머지는 날짜 옆 회색 글자로 접는다. 예: 「10월 2일 금요일 · 해 지기 1시간 44분 전 · 오늘 제주오일시장 장날」.
- 결과: 최악의 경우에도 판은 2~3줄이다. 기분 목록 시작이 y≈305에서 **y≈245**로 올라온다. 증거는 `apps/web/design/proto-d/shots/a2-today-crowded-fixed.jpeg`.
- 장날 블록은 아래에 그대로 있어서, 접힌 정보도 스크롤 한 번이면 찾을 수 있다.

## 3. 날씨 출처

**확인한 사실 (2026-10-03)**:

| 출처 | 상업 이용 | 키·서버 | 브라우저 직접 호출 | 비고 |
|---|---|---|---|---|
| Open-Meteo 무료 API | **불가**(「non-commercial purposes」), CC BY 4.0 | 키 없음, 하루 1만 회 | 됨(`access-control-allow-origin: *` 확인) | KMA 모델(`kma_seamless`)은 **값이 전부 null**. 2026년 3월 KIM 전환으로 갱신이 멈췄다(공식 문서). 기본 모델은 응답함 |
| 기상청 단기예보 조회서비스(data.go.kr 15084084) | **가능**(공공누리 1유형, 출처 표시) | 키 필요, 무료, 개발 계정 하루 1만 건, 자동 승인 | 키를 숨겨야 해서 서버 경유 | 공식 출처라 「기상청 예보」라고 쓸 수 있다(B4) |

**해결책**: 기상청 단기예보를 **Cloudflare Pages Function** 하나로 받는다(`/api/rain?area=애월`).
- **키**: 서버 환경 변수에 둔다.
- **캐시**: 15개 동네 × 1시간. 하루 최대 360건이라 한도의 4%다.
- **개인정보**: 동네 중심 좌표 15개만 보낸다. 사용자 GPS는 기기 밖으로 나가지 않는다.
- **실패하면** 줄을 숨긴다. 오래된 예보는 보여 주지 않는다.
- **자동 전환은 하지 않는다.** 「실내만 볼까요?」로 묻기만 한다. 비 예보는 틀릴 수 있고, 사용자 통제가 우선이다(Nielsen #3).
- **보여 주는 조건**: 앞으로 3시간 안에 강수확률 60% 이상일 때만. 맑은 날은 날씨를 쓰지 않는다. 행동이 안 바뀌는 정보는 장식이기 때문이다(판정 Q1).

**대안**: 서버를 끝까지 두지 않으려면 Open-Meteo를 브라우저에서 직접 부를 수 있다. 다만 무료 조건이 비상업이라 수익화(남은 작업 9)와 충돌하고, 출처 표시 「Open-Meteo」가 필요하다.

**결정 필요**: Pages Function 도입은 「정적 사이트, 외부 요청 최소」(ADR-0058·0063)를 바꾸는 일이라 새 ADR이 필요하다.

## 4. 함께 확인한 위험

- **사진 사용권**: 홈 사진도 결과 화면과 같은 비짓제주 CDN·같은 데이터다. 이용 확인(ADR-0072 Amendment 1, `docs/licensing-visitjeju.md`) 범위 안이고, 새 위험은 없다.
- **사진 용량**:
  - A′는 첫 화면 썸네일 8장, B′는 4장이다.
  - 동네 사진 14장은 `loading="lazy"`라 스크롤해야 받는다.
  - 기존 「JS+CSS gzip 50KB 이하」 예산은 사진과 무관하게 지켜진다.
