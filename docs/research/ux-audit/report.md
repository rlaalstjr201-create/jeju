기준: `docs/research/ux-audit-criteria.md`(8차원 100점, 근거 문헌 포함).
상세: `ours.md` · `onuljeju.md` · `myrealtrip.md` · `references.md`(당근·네이버지도·카카오맵). 증거 사진 `shots/`.

## 한 줄 결론

우리는 **고르는 흐름은 가장 낫고, 홈은 가장 약하다.** 남들은 홈을 「역할마다 다른 모양의 블록 + 사진 + 큰 묶음 간격」으로 채운다. 이걸 가져오되, 그들의 피곤한 부분(별점·태그·긴 목록·광고)은 가져오지 않는 게 방향이다.

## 2. 우리 홈이 비어 보이는 이유 (관찰)

1. 위 285px·아래 130px가 비어 있다. 의도한 5:2 여백(SPEC)인데, 사진·색이 없으니 「여백」이 아니라 「빈칸」으로 읽힌다.
2. 사진 0장, 카드 0장, 앱 이름 0번. 색은 주황 밑줄 한 줄뿐.
3. 홈에 「제주」가 없어 5초 안에 뭐 하는 곳인지 모른다(T1 문장: 「기분 고르면 뭔가 골라 주는 곳」).
4. 데스크톱(1440px)은 448px 한 줄만 가운데 있고 70%가 비었다.

## 4. 제안

### A. 바로 가능 (기존 결정과 충돌 없음)

| # | 바꿀 것 | 근거 |
|---|---|---|
| A1 | 뒤로 가기 두 번째에 앱 밖으로 나가는 문제 수정(화면 전환마다 history) — **버그** | ours T7 실패 |
| A2 | 「길찾기」를 카드 밖 밑줄 글자 → 카드 안 연파랑 버튼(높이 48) | 네이버 상세, ADR-0067과 맞음 |
| A3 | 「비 와요(실내만)」 켜짐을 헤더에 표시(「구제주 근처 · 실내만」) | ours T3 |
| A4 | 결과 화면 간격 두 단계(카드 안 좁게, 묶음 사이 넓게) | 오늘제주·마이리얼트립 |
| A5 | 3곳 위 「왜 이 3곳인지」 한 줄 | 마이리얼트립 「어떤 기준으로 선정되나요?」 |
| A6 | 위치 찾는 4초 동안 카드 뼈대 먼저 | 마이리얼트립 |
| A7 | 결과 카드 메타에 글자로 「오늘 장날」(배지 아님, 데이터 있음) | 오늘제주 오일장 |
| A8 | 우리 네이버지도 길찾기를 위치 없을 때도 점검(출발지·자동차 기본) | 네이버 T4 |
| A9 | 장소 사진 alt 채우기 | ours 7.5 |

**정정 (2026-10-03, 코드 확인 뒤)**:
- **A1은 버그가 아니다.**
  - 홈이 앱의 첫 기록이다. 결과에서 뒤로 1번이면 홈, 2번이면 앱에 들어오기 전 페이지로 간다. 일반 웹의 정상 동작이고, 의도된 설계다(e2e S17~S20, `nav.test.ts:252`).
  - 감사 T7의 「실패」는 홈보다 앞의 기록이 없다는 것을 실패로 센 판정 오류다. 고치지 않는다.
- **A6·A7은 이미 있다.**
  - 위치를 기다리는 동안 회색 뼈대 카드가 뜬다(`ghostCard`).
  - 결과 카드 메타 줄에 「오늘 장 서는 날」이 나온다(`marketText`).
- **A8은 확인했다.** 네이버 길찾기 링크는 출발지 `-`(지금 폰 위치)·자동차 기본이다(`links.ts:44-48`). 웹에서 앱이 없을 때 어떻게 동작하는지는 실기기 점검표에 남긴다.
- **A9는 하지 않는다.** 사진 alt를 비운 것은 이름이 바로 옆 제목에 있어 중복 낭독을 피하려는 의도이고, WCAG상 맞는 처리다. 감사 7.5의 감점은 철회한다.
- **실제로 할 것**: A2(큰 카드 길찾기 버튼), A3(실내 표시), A4(간격), A5(고르는 방식 한 줄).

### B. 새 ADR이 필요 (주인 결정)

| # | 바꿀 것 | 충돌하는 결정 | 메모 |
|---|---|---|---|
| B1 | 홈 위 빈칸에 「오늘 제주」 줄: 날짜 · 일몰 시각 · 오늘 장 서는 곳 (+날씨) | SPEC §1-1, ADR-0029 「조용하게」 | 일몰·장날은 서버 없이 됨. 날씨는 외부 요청이라 ADR-0058 확장 필요 |
| B2 | 기분 4줄을 사진 타일 2×2로(기분마다 대표 사진) | SPEC §1-1, §14 | 대안: 줄은 두고 오른쪽에 작은 사진 2×2 모자이크(당근식) — 선택지 수는 그대로 |
| B3 | 홈 아래(스크롤)에 블록 추가: 「동네별로 둘러보기」 15곳 사진 타일 → 이미 있는 지역 페이지로 | ADR-0029, SPEC §1-1 | 검색 유입에도 도움 |
| B4 | 페이지 바탕 연회색 + 흰 판 (당근식) | ADR-0070(흰 바탕) | 묶음을 선 없이 읽히게 함 |
| B5 | 행동 색 하나로 통일(지금 파랑·주황이 같은 「행동」에 섞임) | ADR-0070 역할 재배정 | |
| B6 | 홈에 앱 이름 또는 「제주에서 지금」 한 줄 | SPEC 문구 규정 확인 | 5초 이해 2점 → 해결 |
| B7 | 데스크톱 전용 배치 | 없음(지금은 모바일 우선) | 데스크톱 유입이 생기면 |

### C. 피할 것 (남들이 하지만 우리 목표에 해로움)

별점·리뷰 수·가격·할인율·배지, 카드당 태그 6~18개, 결과 30장·무한 목록, 여러 색 배지·파스텔·그라데이션, 홈 첫 블록 광고, 앱 설치 유도, 영문 라벨·세리프 이탤릭, 직선 km 거리, 자연어 검색창을 첫 화면 주 행동으로.

### D. 지킬 것 (우리가 이미 이김)

기분 1탭 → 근처 3곳(입력 0), 「차로 약 N분」, 이유 한 줄, 위치 실패 → 동네 고르기, 로그인 없는 저장, 길찾기 한 탭, 비 오는 날 실내. 경쟁 3곳은 이 과제들에서 실패하거나 느렸다.

## 5. 주인이 정할 것 (이 보고서 뒤)

1. 홈 「조용하게」 원칙(ADR-0029·SPEC 5:2 여백)을 바꿀까? → B1·B2·B3·B6이 여기에 걸린다.
2. 바꾼다면 사진을 어디까지: 기분 타일(B2 큰 사진) / 작은 모자이크(B2 대안) / 아래 블록에만(B3)?
3. 바탕색 하나 추가(B4)를 허용할까?
4. 날씨를 넣을까(외부 요청, 새 ADR)? 아니면 일몰·장날만?
5. A(충돌 없음) 9개는 먼저 해도 될까?

추천 순서: A1 버그 → A 나머지 → B는 시안 2개(지금 vs 제안)를 390px 스크린숏으로 비교한 뒤 ADR.

## 6. 실제 사용자에게 물을 것 (5~10명, 15분)

조건: 제주 여행 중이거나 다녀온 사람. 폰으로. 설명 없이 링크만 준다.

1. 첫 화면을 5초 보여 주고 끄기 → 「뭐 하는 앱 같아요?」(정답: 제주에서 지금 갈 곳 골라 주는 앱)
2. 「지금 근처에서 밥 먹을 곳 하나 정해 보세요」 → 걸린 시간, 망설인 곳 기록(말 걸지 않기)
3. 「비 오는 날이라면?」 → 실내 설정을 찾는지
4. 끝나고: 「추천 3곳을 믿고 가겠어요? 왜/왜 아니요?」
5. 「첫 화면이 어땠어요? 한 단어로」 (비었다·깔끔하다·심심하다 등)
6. 같은 과제를 오늘제주로 한 번 → 「어느 쪽이 더 편했어요?」
7. (선택) SUS 10문항 — 5명 이상일 때만 점수 냄

기록은 `docs/research/user-test-01.md`에. 시안이 나오면 같은 질문으로 다시 해 비교한다.
