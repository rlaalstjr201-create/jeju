# 트렌드 02 — 서울시 문화행사 API와 네이버 뉴스를 더하면 얼마나 잡히나 (사전등록)

작성 2026-11-04 17시 KST, 실행 전에 커밋한다. 커밋 뒤에는 출처·판정·결론 규칙을 바꾸지 않는다. 출처 조회는 한 번이다.

## 묻는 것

트렌드 01(`docs/research/trend-seoul-01/04-result.md`)은 공식 출처 셋(TourAPI·카카오·네이버 블로그)을 합쳐 재현율 29.0%로 「만들지 않는다」였다.
주인이 서울 열린데이터광장 키를 받았다(2026-11-04). **서울시 문화행사 API(S4)와 네이버 뉴스 검색(S5)을 더하면 결론이 바뀌는가?**

## 같은 것 (01 그대로)

- 지역·반경(성수·홍대·이태원, 1.5km)과 기준일(2026-11-05에 열려 있음).
- **기준 목록은 01의 `01-reference.md`를 그대로 쓴다.** 그 목록은 S4·S5를 보지 않고 만들어졌다. 이태원(2개)은 01처럼 판정에서 뺀다.
- 판정 방법(이름 맞추기는 새 Opus 하위 에이전트, 애매는 못 잡음으로 셈, 정밀도 표본 최대 20개)과 결론 규칙의 기준값(60% / 30%).

## 새 출처 (실행자가 스크립트로 한 번)

- **S4 서울시 문화행사 정보**(`culturalEventInfo`, 서울 열린데이터광장): 전체를 1,000건씩 받아(약 20회 호출) 시작일 ≤ 11-05 ≤ 종료일이고 좌표(LAT·LOT)가
  지역 반경 안인 것만 남긴다. 좌표가 없으면 자치구(성동구·마포구·용산구)와 장소 이름을 남겨 판정 에이전트가 반경 안인지 본다.
- **S5 네이버 뉴스 검색 API**: 「성수 팝업」·「홍대 팝업」·「이태원 팝업」·「한남 팝업」, 최신순 100건씩, 2026-10-01 이후 기사. 제목·요약을 남긴다.
- 호출 상한: 서울 API 25회, 네이버 뉴스 10회.

## 판정

- S4·S5 각각, 그리고 **다섯 출처(S1~S5) 합친** 재현율과, S4·S5가 01에 더한 몫(새로 잡은 항목 수).
- 정밀도: S4·S5가 낸 팝업·행사 후보 표본 최대 20개.

## 미리 정한 결론 규칙

- 다섯 출처 합친 재현율 **60% 이상** → 2단계(구별 「이번 주」 목록)를 만든다.
- **30~60%** → 가장 잘 잡는 출처 하나 또는 둘로, 「일부만 보여 준다」를 밝히는 작은 판을 검토한다.
- **30% 미만** → 공식 출처로는 만들지 않는다(01 결론 유지). 다음은 「AI가 공개 페이지를 읽고 사실만 정리」를 새 기준 목록으로 시험할지 주인과 정한다.

## 미리 적는 예상 (틀려도 고치지 않는다)

실행자(Claude) 예상: S4는 공공 문화행사 위주라 상업 팝업을 거의 못 잡는다(0~10%). S5 뉴스는 큰 브랜드 팝업을 잡는다(15~35%).
다섯 합쳐 **30~45%**.
