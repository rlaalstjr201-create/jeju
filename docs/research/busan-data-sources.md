# 부산 확장용 관광 데이터 API·MCP 조사

- 작성: 2026-10-17. 요청: 주인 「부산으로 범위를 넓히자 비짓제주같은 api나 mcp 찾아」
- 관련 결정: ADR-0062(지역 확장은 TourAPI 허용, 부산 후보), ADR-0023(비짓제주 1차 출처), ADR-0050(카카오 로컬), ADR-0065(실내 판정은 원문 근거).
- 앞선 조사: `docs/research/data-sources-korea-japan.md`(TourAPI 일반). 이 문서는 부산에 한정해 실측을 더한 것이다.
- 방법: 웹 검색 10회, 공공데이터포털 페이지 직접 읽기, **주인이 이미 가진 공공데이터포털 키(`.env`의 `DATA_GO_KR_SERVICE_KEY`)로 읽기 전용 호출 약 18회**(개발 한도 1,000회/일 중). 키 신청·계정 생성·MCP 설치는 하지 않았다.
- 표기: 「실측」= 이번에 API를 직접 불러 확인, 「확인함」= 공식 페이지에서 읽음, 「확인 실패」= 못 읽음(추정하지 않음).

## 결론

**주 출처는 한국관광공사 TourAPI 국문(KorService2), 보조는 부산광역시 관광 API 5종(명소·맛집·도보여행·축제·쇼핑)과 카카오 로컬(장소 ID만)이다.** 비짓부산에는 비짓제주 같은 자체 공개 API가 없다. 부산시 API가 사실상 「비짓부산 콘텐츠의 공개 창구」 역할을 한다.

- TourAPI는 키가 이미 있고 부산 2,230건이 바로 나온다(실측). 좌표·분류·개요·이용시간·사진 공공누리 유형까지 비짓제주 파이프라인에 그대로 맞는다.
- 부산시 API는 건수가 적지만(페이지 샘플 기준 명소 107·맛집 200 수준, 실제 건수 확인 실패) 비짓부산이 고른 곳이라 「큐레이션 신호」로 쓸 수 있고, 5개 언어를 준다.
- MCP는 쓸 이유가 약하다. 우리 파이프라인은 빌드 때 한 번 받아 고정하는 구조(ADR-0027)라 REST를 직접 부르는 편이 단순하고 안전하다.

### 1-1. TourAPI 국문(KorService2) — 주 출처

공식 정보(확인함, https://www.data.go.kr/data/15101578/openapi.do):
- 전국 약 26만 건, 15개 데이터 종류, 무료, 실시간 갱신, 이용허락범위 「제한 없음」.
- 개발계정 1,000회, 운영계정은 활용사례 등록 시 증설. 운영단계는 심의 승인.
- 이미지는 공공누리 1·3유형. 피사체 명예훼손·인격권 침해 용도와 기업 CI·BI 사용 금지.

실측(2026-10-17, 주인 키):
- **지역 코드 함정**: `areaCode=6`(옛 부산 코드)은 548건, `lDongRegnCd=26`(법정동 시도 코드)은 2,230건. 제주도 `areaCode=39` 731건 대 `lDongRegnCd=50` 2,117건으로 같은 차이. **부산은 반드시 `lDongRegnCd=26`으로 받아야 한다.**
- 부산 종류별 건수: 관광지 351, 문화시설 123, 축제·행사 74, 여행코스 1, 레포츠 60, 숙박 118, 쇼핑 986, 음식점 517.
- 관광지 351건 대표사진: 3유형 192, 1유형 131, 사진 없음 28. 즉 **사진 있는 곳의 약 59%가 변경 금지(3유형)**.
- 목록 필드: `contentid, title, addr1, mapx/mapy, cat1~3, lclsSystm1~3(새 분류), firstimage, firstimage2, cpyrhtDivCd, modifiedtime` 등.
- `detailCommon2`에 `overview`(개요)가 있다. 표본 1건(가덕도 등대) 332자. 전체 분포는 확인 실패.
- `detailIntro2`(관광지)에 `usetime, restdate, parking, chkbabycarriage, chkpet, expguide, useseason` 등.
- 한 번에 400건 목록 호출 성공. 다만 상세(개요)는 장소마다 1회라 관광지·문화·음식 등 1,000곳 이상이면 개발 한도로 이틀 이상 걸린다.

공공누리 3유형은 「출처 표시, 상업 이용 가능, 변경 금지」이며, 무엇이 「변경」인지(자르기·크기 조정)는 공식 페이지가 정의하지 않는다(확인함, https://www.kogl.or.kr/info/licenseType3.do). 앞선 조사와 ADR-0062 §5의 열린 질문이 그대로 남는다.

### 1-2. TourAPI 다국어

- 영문(EngService2): 약 8만 건, 개발 1,000회, 이미지 공공누리 1·3유형, 「제한 없음」(확인함, https://www.data.go.kr/data/15101753/openapi.do). 마지막 수정 2026-02-26.
- 주인 키로 부르면 「등록되지 않은 서비스키」(실측) → **언어별로 따로 활용신청**해야 한다. 일·중 서비스는 이번에 페이지를 읽지 않음(확인 실패). 서비스 이름(JpnService2·ChsService2·ChtService2)은 MCP 코드에서 확인(https://github.com/harimkang/mcp-korea-tourism-api).
- 외국어판 표기 규칙(메모리 「Korean terms first」)과 충돌할 수 있으니 받아도 그대로 쓰지 말고 대조가 필요하다.

- 맛집·도보여행 설명은 「부산관광포털 비짓부산 내 추천여행」 콘텐츠라고 밝힌다(확인함). 그래서 이 API들이 비짓부산 큐레이션의 공개 창구다.
- 이미지 경로는 `/uploadImgs/files/cntnts/...` 같은 상대경로다(페이지 샘플). 호스트와 사진 라이선스는 문서에 없다 → **확인 실패**. 비짓부산 쪽 부산 관광 아카이브는 「공공누리 표시 자료만 허락 없이 이용, 미표시는 저작권자 허락 필요」라고 안내한다(확인함, https://visitbusan.net/archive/index.nm?menuCd=9). 「이용허락범위 제한 없음」이 사진까지 덮는지는 모른다. **사진은 공사·부산시 확인 전까지 쓰지 않는다.**
- 관광안내소정보(15063445)도 있으나 장소 추천과 무관.
- 실제 건수·최근 갱신 여부: 키 미등록으로 **확인 실패**. 페이지 샘플(totalCount 107 등)은 예시값일 수 있다. 등록일 2020년, 사진 경로 날짜가 2019년이라 낡은 내용이 섞였을 위험이 있다(추정 아님, 샘플에서 본 날짜).
- 별도로 부산관광공사 「비짓부산패스 관광지·여행일정」 파일 데이터가 있다(CSV, 연간, 2026-09-14 수정, https://www.data.go.kr/biz/dcat/metadata/15160440.do). 패스 가맹 관광지라 추천 원천으로는 좁다.

### 1-4. 비짓부산(visitbusan.net) 자체 API

- 검색과 사이트 확인에서 공개 API·개발자 페이지를 **찾지 못했다**(검색 결과 https://www.data.go.kr/data/15076361/openapi.do 는 비짓제주 API였다). visitbusan.net 첫 화면은 이번 조회 때 오류 페이지를 돌려줬다.
- robots.txt는 `Allow: /`이지만, 아카이브 저작권 안내상 공공누리 미표시 자료는 허락이 필요하다. **긁어오기는 하지 않는다.**

### 1-5. 카카오 로컬

- 데브톡 답변들: 로컬 API 결과는 어떤 형태로든 저장 금지, 실시간 호출만 허용, 임시 캐시도 불가(https://devtalk.kakao.com/t/api/151343 , https://devtalk.kakao.com/t/api-20/151271).
- 같은 곳의 2026-08-26 직원 답변: 자체 장소 DB에 **카카오 장소 ID·place_url만 매칭해 저장하는 것은 허용**(https://devtalk.kakao.com/t/db-id/151335).
- 우리 쓰임(ADR-0050: 장소 ID 얻기·실재 확인·지도 링크)은 이 범위 안이다. 부산에서도 좌표·이름을 카카오에서 가져와 저장하면 안 되고, 좌표는 TourAPI 값을 쓴다.
- 현재 쿼터: 확인 실패(검색에 나온 정책 문서는 2017년판, https://developers.kakao.com/terms/ko/site-policies-20170525).

### 1-6. 네이버 검색(지역 포함)

- 2차 보도: 3개 검색 API 신규 신청이 7월 31일부터 막혔고, 기존 개발자는 2027-06-30까지 유예, 9월 7일부터 API HUB 이관, 결과의 저장·캐싱·AI 학습·요약 활용 금지(https://brunch.co.kr/@ainote/123 , https://www.tokenpost.kr/news/ai/403521). **공식 공지 원문은 확인 실패**, 지역 검색이 그 3개에 들어가는지도 확인 실패.
- API HUB 이관 안내: 기존 Client ID·Secret은 HUB에서 못 쓴다(확인함, https://guide.ncloud-docs.com/docs/apihub-migration).
- 영향: 부산 장소 원천으로는 부적합. 오히려 제주 파이프라인의 네이버 교차 검증(ADR-0038)·발굴(ADR-0024)이 2027-06-30 뒤 끊길 수 있다 — 부산 이전에 따로 점검할 일.

## 2. 비짓제주가 주던 것 중 부산에 없는 것

| 비짓제주에서 쓰던 것 | 부산(TourAPI 기준) | 영향 |
|---|---|---|
| `tag`(태그) | **없음.** 대신 3단계 분류(`lclsSystm`, `cat`) | 기분 매칭·실내 판정(ADR-0065)이 태그를 근거로 쓰던 부분이 약해진다. 분류+개요로 규칙을 다시 짜야 한다 |
| `introduction`(짧은 소개) | `overview`(개요). 장소마다 상세 호출 1회 필요 | 이유 문장의 근거는 확보. 호출 수가 늘어 수집이 며칠 걸린다 |
| 큐레이션(비짓제주가 고른 목록) | TourAPI는 전국 일괄 등록 성격. 쇼핑 986건처럼 잡다한 곳 다수 | 「유명·추천」 신호가 없다. 부산시 API(비짓부산 추천) 포함 여부를 가산점으로 쓰는 안 |
| 외부 노출도 점수(ADR-0051)용 원천 | 네이버 블로그 검색이 막힐 수 있음(1-6) | 인기 점수 산정 방법이 부산에서 다시 필요 |
| 사진 라이선스 | 3유형이 다수(관광지 59%) | 자르기 여부가 정해질 때까지 3유형은 `contain` 표시 등 결정 필요 |
| 실내 여부 | 둘 다 직접 필드 없음(우리가 판정) | 판정 근거 문서(`review/copy/indoor.json`) 부산판 필요 |

## 3. 추천 조합

1. **주: TourAPI 국문 KorService2**, `lDongRegnCd=26`. 관광지·문화시설·레포츠·음식점(필요하면 카페 분류)부터. 좌표·개요·이용시간·사진 유형을 그대로 저장. 쇼핑 986건은 걸러서 일부만.
2. **보조 A: 부산시 관광 API(명소·맛집·도보여행)** — 장소 원천이 아니라 「비짓부산이 추천한 곳」 표시와 소개문 보강용. TourAPI와 이름+좌표로 매칭. 사진은 라이선스 확인 전까지 쓰지 않음.
3. **보조 B: 카카오 로컬** — 장소 ID·지도 링크·폐업 확인만(저장은 ID만).
4. **외국어판**: TourAPI 다국어를 신청하되, 부산시 API 5개 언어와 대조해 고유명사 표기를 고른다.
5. 쓰지 않음: 네이버 지역 검색(원천·저장 불가), MCP(1-7), 비짓부산 긁기.

이유: 이미 키가 있고 실측으로 바로 2,230건이 나오는 곳은 TourAPI뿐이다. 구조가 비짓제주와 같아 기존 심사→이유 문장→점수→사실 확인 파이프라인(ADR-0062 §2)을 그대로 탈 수 있다. 부산시 API는 건수가 작아 단독으로는 하루 3곳 추천을 동네마다 채우기 어렵지만, 큐레이션 신호가 TourAPI에 없는 빈칸을 메운다.

## 4. 주인이 할 일

계정이 주인 것이라 아래는 주인만 할 수 있다.

1. **공공데이터포털 활용신청(같은 계정, 개발단계 자동승인)**
   - 부산광역시_부산명소정보 서비스(15063481), 부산맛집정보(15063472), 부산도보여행정보(15063454). 필요하면 축제(15063500)·쇼핑(15063487).
   - 외국어판을 할 때: 한국관광공사_영문 관광정보서비스_GW(15101753)와 일·중 서비스.
   - 국문 TourAPI(15101578)는 이미 되어 있음(실측).
2. **운영계정 전환(트래픽 증설)**: TourAPI 상세 호출이 1,000회/일을 넘으니, 배포 전 활용사례 등록으로 운영 신청. 심의 승인이라 시간이 걸린다.
3. **문의 2건**
   - 한국관광공사: 공공누리 3유형 사진을 카드 비율에 맞게 CSS로 잘라 보여주는 것이 「변경」인지, 출처 표시 문구·위치. (문안은 `data-sources-korea-japan.md` §5-1)
   - 부산시 관광정책과(또는 부산관광공사): 부산시 관광 API 이미지의 공공누리 유형과 상업 서비스 표시 가능 여부, 이미지 호스트, 데이터 갱신 여부.
4. **네이버 검색 API 확인**: 개발자센터 공지에서 우리가 쓰는 블로그·카페·지역 검색이 신규 중단·2027-06-30 종료 대상인지 확인(제주 파이프라인 영향).
5. 다음 단계 승인: 워크플로우상 Light Spec `specs/region-expansion.md`(ADR-0062 Consequences)로 넘어갈지.
