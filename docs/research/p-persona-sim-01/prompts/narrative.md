# 서사 작성 지시 (모든 묶음 공통, 바꾸지 않는다)

너는 제주 여행자 가상 인물의 「생활 서사」를 쓴다. 입력은 속성 골격 JSONL 한 묶음이다. 이 인물들은 나중에 여행 앱을 시험하는 데 쓰인다 — 그러니 **앱이나 앱 기능에 대한 생각·선호는 절대 쓰지 않는다**(날짜 정하기·저장 목록·일정 앱에 대한 호불호 포함). 서사는 사람이지 앱 리뷰가 아니다.

## 먼저 읽을 것
- `docs/research/p-persona-sim-01/10-research-p-archetypes.md` — 각 `type`(유형)이 여행 전·전날 밤·현장에서 실제로 하는 행동. 보통 여행자 유형(`일정 짜는 계획형(J)`, `큰 줄기만 정하는 보통형`, `동행이 다 짜는 맡김형`, `패키지·코스 따라가는 형`)은 이름 그대로 보통 사람 수준으로 상상한다.
- `docs/research/p-persona-sim-01/12-research-app-habits.md` — `save`(저장 습관) 유형의 실제 모습.

## 인물마다 쓸 것
- `name`: 나이·성별에 맞는 흔한 한국 이름(성+이름). 같은 묶음 안에서 겹치지 않게.
- `narrative`: 한국어 4~6문장. 속성에 있는 것만 풀어 쓴다(새 사실을 크게 지어내지 않는다). 담을 것:
  1. 어떤 사람인지(직업·생활 리듬·성격 한두 개, 말투가 느껴지게)
  2. 이번 제주 여행: 누구와(`companion`, `party`), 며칠(`days`), 몇 번째(`visits`), 숙소·이동(`lodge`, `move`), 동행 중 누가 정하는지(`decider`)
  3. 여행 중 폰으로 갈 곳을 찾는 때(`phone`)와 그때 실제로 하는 행동 — `type`의 행동을 구체 장면으로(예: 지난 여행 한 장면)
  4. 저장·캡처 습관(`save`)이 실제로 어떤 모습인지 한 문장
  5. 폰 다루는 솜씨(`fluency` 1~5)와 상황 제약(`constraint`)이 드러나는 한 마디
- `offType`이 true면 유형과 어긋나는 면 하나를 자연스럽게 넣는다(예: 즉흥파인데 첫날 숙소 근처 식당만은 꼭 미리 봐 둔다).
- 「P」「J」「MBTI」라는 말은 쓰지 않는다. 행동으로 보여 준다.
- 사람을 극단으로 그리지 않는다. 보통 사람의 생각 수준이다. P라도 밤에 내일 갈 만한 곳을 슬쩍 훑어보고 염두에 두는 건 자연스럽다. 싫어하는 건 순서·시간·날짜에 묶이는 것이다.

## 출력
- `"narrative":false`인 줄은 건너뛴다(서사 없는 대조군).
- 출력 파일: 지시받은 경로에 JSONL, 한 줄에 `{"id":"T0001","name":"…","narrative":"…"}`.
- 파일은 여러 번 나눠 써도 되지만(Write로 처음, 이어서는 기존 내용을 읽고 덧붙여 다시 Write, 또는 Bash heredoc `>>`), 끝나면 줄 수가 대상 수와 같아야 한다. `node -e` 등으로 JSON 파싱이 되는지 스스로 확인한다.
- 이 지시 파일과 입력 파일은 고치지 않는다. 저장소의 다른 파일도 만들거나 고치지 않는다. 커밋하지 않는다. 웹 검색하지 않는다.

## 종료 조건
출력 파일의 줄 수 = 입력에서 `"narrative":false`가 아닌 줄 수, 모든 줄이 JSON으로 파싱되고 id가 입력과 일치. 마지막 메시지는 「n줄 작성, 파싱 OK」 한 줄.
