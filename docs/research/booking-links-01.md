# 예약 링크 조사 01 — 「마이리얼트립에서 예약 찾아보기」를 진짜 예약·소개 페이지로 바꿀 수 있나 (2026-10-01)

조회일: 모든 요청 **2026-10-01**. 읽기 전용 조사이며 앱 코드는 바꾸지 않았다.
원자료: `apps/web/review/audit/booking-links-sample.json` (장소마다 후보 URL·판정·근거).
관련: `apps/web/src/links.ts` `bookingUrl`, `apps/web/src/render.ts`(카드의 `a.book`), ADR-0058(`bookable` = 비짓제주 `category === 'experience'`, 예약은 마이리얼트립만), ADR-0025, `docs/licensing-visitjeju.md`.

## 0. 결론

- **지금 링크는 거의 맞지 않는다.** `myrealtrip.com/search?q=이름` 결과에 그 장소 상품이 보이는 곳은 **60곳 중 10곳(17%)**이다. 나머지 50곳은 상품이 0건이거나 해외 투어처럼 관계없는 상품이 나온다. 예를 들어 「뱅듸승마클럽」은 다낭 골프, 「백제사」는 라스베이거스 투어가 나온다.
- **진짜 예약 페이지는 네이버 예약에 가장 많다.** 네이버 예약 24곳(40%), 카카오 예약 7곳(12%), 마이리얼트립 직접 상품 10곳(17%)이다. 마이리얼트립 상품이 있는 10곳 중 9곳은 네이버나 카카오 예약도 있다. 마이리얼트립에만 있는 곳은 1곳뿐이다.
- **권장:** 버튼은 **확인된 링크가 있을 때만** 단다. 순서는 ① 업체 예약 페이지(네이버·카카오 예약) → ② 마이리얼트립 직접 상품 → ③ 공식 홈페이지 → ④ 버튼 숨김이다. 카카오 장소 페이지(c)는 버튼 후보에서 뺀다. 카드의 이름과 사진이 이미 지도 장소 페이지로 가기 때문이다(ADR-0071). 표본 기준으로 예약 버튼은 42%, 홈페이지 버튼은 8%이고, 50%는 버튼이 사라진다. 비짓제주 상세를 「소개 보기」로 넣으면 32%가 더 생기고 숨김은 18%가 된다(§4).
- 제휴(수수료) 링크는 **지금 쓰지 않는다.** 그냥 링크만 거는 것은 문제가 없다. 제휴 수익은 상업적 이용이 되고, 비짓제주 데이터 이용 조건은 상업화 전에 확인이 필요하다고 정리되어 있다(`docs/licensing-visitjeju.md` §4).

**표본:** `public/spots.json`의 `bookable: true` 385곳(new 308 · walk 45 · rest 26 · food 6)을 id로 정렬한 뒤 `random.Random(20261001)`으로 뽑았다.

**판정 기준:**
- 일치: 이름이 같고, 거기에 좌표·주소·전화·판매자 이름 중 하나 이상이 다른 출처와 맞는다.
- 부분: 운영자 SNS처럼 공식 채널이지만 예약·상세 페이지는 아니다.
- 불일치: 다른 장소로 간다.
- 죽은 링크: 404, DNS 실패, 인증서 오류, 「존재하지 않는 장소」.
- 미확인: 판단할 근거가 없다.

추정한 판정은 없다.

## 3. 비용과 법·약관

**링크만 거는 것:** 공개 페이지(네이버 예약, 카카오 예약, 마이리얼트립 상품, 업체 홈페이지)로 가는 일반 하이퍼링크다. 계약도 비용도 필요 없다. 지금의 지도·검색 링크와 성격이 같다.

**링크를 찾아 모으는 방법(수집)은 출처마다 다르다:**

| 출처 | 공식 경로 | 이번 조사에서 쓴 경로와 위험 |
|---|---|---|
| 비짓제주 | 우리가 가진 OPEN API 키(ADR-0023)로 `contentsid` 조회. 상세 페이지는 robots에서 허용, `Crawl-delay: 5` | 사이트 검색 `/kr/search`는 **robots.txt가 막은 경로**다. 전체 수집은 OPEN API로 `contentsid`를 얻은 뒤 상세 페이지를 5초 간격으로 읽어야 한다. OPEN API 응답에 `homepage`·`phoneno`·`reservelink`가 들어 있는지는 이번에 키가 없어 **미확인**이다 |
| 데이터 이용 조건 | `docs/licensing-visitjeju.md` | 링크 URL·전화 같은 사실 정보는 위험이 매우 낮다. 다만 같은 문서 §4가 「광고·제휴 링크 수익 포함 상업화」는 공사 서면 확인 전에는 불가로 정리했다. 제휴 수수료를 붙이는 순간 이 조건에 걸린다 |

| 카카오 | Local REST API(키 필요)는 `place_url`만 준다. 홈페이지·예약은 주지 않는다 | `place-api.map.kakao.com`은 비공개 내부 API다. `place.map.kakao.com`은 봇 UA를 403으로 막는다. 운영 파이프라인에 넣지 않는다 |

## 4. 권장 링크 정책

**원칙:** 버튼은 **사람이나 대조 규칙으로 확인한 URL이 데이터에 있을 때만** 단다. 이름 검색 링크(지금 방식)는 쓰지 않는다. URL은 `spots.json`에 필드로 저장하고, 빌드 때 바꾸지 않는다.

**우선순위:**
1. **업체 예약 페이지**: 네이버 예약(`m.booking.naver.com/booking/…/bizes/{id}`) 또는 카카오 예약(`booking.kakao.com/detail/ticketStore|accommodation/{id}`). 업체가 직접 연 예약 창구라서 가장 정확하다. 둘 다 있으면 지도 앱 설정에 맞춰 고를 수도 있고, 네이버로 고정해도 된다. 표본에서는 카카오 예약이 있는 곳에 모두 네이버 예약도 있었다.
2. **마이리얼트립 직접 상품**(`experiences.myrealtrip.com/products/{id}`). 판매자·주소·전화가 맞는 것만 쓴다. 제휴 파라미터는 붙이지 않는다(§3). 표본에서 이 단계로만 버튼이 생기는 곳은 1곳이다.
3. **공식 홈페이지**: 자체 도메인이고 응답이 정상인 곳. 인스타그램·블로그 같은 SNS는 넣지 않는다.
4. **버튼 숨김.** 카카오 장소 페이지는 카드 이름 링크가 이미 하고 있다.

선택 사항으로 3과 4 사이에 **비짓제주 상세(「소개 보기」)**를 넣을 수 있다. 출처 표시 링크와 성격이 같고, 표본의 32%가 여기에 해당한다.

**표본 60곳에 적용하면:**

| 결과 | 곳 | 비율 |
|---|---|---|
| 예약 | 25 | 42% |
| 공식 홈페이지 | 5 | 8% |
| (선택) 비짓제주 소개 | 19 | 32% |
| 숨김 | 11 | 18% |

선택 단계를 쓰지 않으면 숨김은 30곳(50%)이다.

**버튼 문구 후보** (이름과 운영처를 정직하게 밝힌다):

| 링크 종류 | 문구 후보 |
|---|---|
| 예약 페이지 | 「예약하기」 / 「네이버에서 예약」·「카카오에서 예약」 / 「마이리얼트립에서 예약」 |
| 공식 홈페이지 | 「공식 홈페이지」 / 「홈페이지에서 보기」 |
| 비짓제주 상세 | 「소개 보기」 / 「비짓제주에서 자세히」 |

- `aria-label`은 지금처럼 「{이름}, {문구}」로 둔다.
- 예약 페이지가 판매 중인지는 날짜와 재고에 따라 바뀐다. 그래서 「예약 가능」처럼 단정하는 문구는 피한다.

**이 정책이 바꾸는 것:**
- ADR-0058의 「예약은 마이리얼트립만(`bookable`)」.
- `bookable`(비짓제주 분류)을 「확인된 링크가 있음」으로 바꾸는 것.
- `tests/app.test.ts` 218행의 검색 URL 단언.

모두 **새 ADR**로 결정해야 한다. 이 문서는 ADR을 고치지 않았다.

## 5. 전체 385곳 작업량과 위험

**수집(자동):**
- 이번 순차 수집은 장소당 약 70초였다. 비짓제주 페이지가 1MB 안팎이고 요청 간격 1.2초에 재시도가 들어갔다. 385곳이면 순차로 약 7.5시간, 출처별로 병렬하면 2~3시간이다.
- 비짓제주는 `Crawl-delay: 5`를 지키면 상세 페이지 385건 × 5초 ≈ 32분이 하한이다.
- 마이리얼트립은 파트너 API를 쓰면 수십 분이다.

**판정(에이전트):**
- 이름 + 좌표 300m + 전화·주소·판매자 대조 규칙으로 자동 확정되는 비율은 표본에서 약 70~75%였다.
- 나머지 약 100곳은 에이전트가 장소마다 2~3분 검토한다(4~5시간).
- 사람이 10% 표본을 브라우저로 확인한다(약 1시간).

**합계:** 에이전트 기준 하루 안팎. 병렬 서브에이전트 4개로 나누면 실제 걸리는 시간은 반나절이다. 비용은 API·계약 0원이다. 마이리얼트립 파트너 가입은 무료이고 이번에는 선택 사항이다.

**위험:**
1. **링크가 낡는다.** 표본 60곳에서 죽은 홈페이지 6건, 죽은 카카오 id 1건, 다른 업체로 가는 카카오 id 1건, 예약처가 엇갈린 곳 1건이 나왔다. 분기마다 다시 확인해야 한다. `scripts/check-links.ts` 같은 네트워크 점검에 넣는 방법이 있다.
2. **수집 경로의 약관 문제.** 네이버·카카오는 robots나 비공개 API라서 자동 대량 수집이 부적절하다. 사람·에이전트가 브라우저로 확인하는 일회성 검수로 하고, 결과 URL만 저장한다.
3. **재판매 상품이 사라진다.** 마이리얼트립 일치 10곳 중 8곳이 놀유니버스·투어패스·VPASS 재판매다.
4. **비짓제주 사이트 검색 누락.** 75%만 찾았다. 나머지는 OPEN API로 `contentsid`를 확인해야 한다.
5. **차단.** 카카오는 연결 재설정이 간헐적으로 나왔고, Klook·KKday는 403이었다. 대량 요청을 하면 IP가 막힐 수 있다.
6. **상업화와 맞물림.** 제휴 링크로 바꾸는 순간 비짓제주 상업 이용 확인(`docs/licensing-visitjeju.md` §7-2)이 먼저 필요하다.
7. **표본 오차.** 60곳이면 비율 추정 오차가 대략 ±12%p다. 먹기 6곳은 표본에 없다.
