# seoulist SEO 사후 분석 — 왜 검색어 경쟁에서 졌나

작성 2026-10-01. 대상: 같은 사용자의 이전 프로젝트 seoulist(Seoul Dangol, 영어·일본어 서울 맛집 정적 사이트, 약 950쪽). 저장소 `/home/user/seoulist`를 읽기 전용으로 읽었다.
목적: P의 여행 SEO 시스템(`.claude/agents/seo-analyst.md`)이 같은 실패를 반복하지 않게 규칙을 고르는 것. 인용 수치는 전부 파일에서 왔고 경로를 붙였다.

## 1. 한 줄 요약

**온사이트 계기는 정교했지만, 「이길 수 있는 검색어인가」를 페이지를 만든 뒤에야 쟀고, 외부 링크 0건인 새 도메인이 헤드 검색어를 노렸다.** 신규 사이트 부스트(약 4주)가 그 사실을 가렸고, 걷히자 콘텐츠 검색어가 50~80위로 밀렸다.

## 2. 무엇을 노렸나

`docs/SEO-GEO-STRATEGY.md` §2(2026-07-20, 발행 전)의 수요 지도, 우선순위 순:

1. 로컬 진정성 헤드 — `where do locals actually eat in seoul`, `non touristy restaurants seoul` (홈·허브가 랜딩)
2. 음식 × 서울 카테고리 미드테일 — `best gukbap seoul`, `korean bbq seoul locals` (카테고리 12쪽)
3. 음식 × 동네 롱테일 — hood·area·dish 프로그래매틱 층
4. 개별 식당 이름 — place 상세 약 450쪽
5. 실용 질문 — 예약·가격 가이드

헤드와 미드테일이 1·2순위였다. 「경쟁(Sikr 등)은 근거·신선도·투명성이 전무 — 우리 구조가 유리하다」(§0)는 **SERP를 보지 않은 판단**이었다.

## 5. 진단 루프는 왜 효과가 작았나

- 진단 4회, 개입 18건. 2026-09-04 기준 **실행률 38%(5/13)**, 3회 이상 이월 3건(`.claude/agents/seo-analyst.md` ⓪). 「AI 인용 관측 로그 돌리기」는 5회 연속 이월(진단 2026-09-01T1541).
- 개입 대부분이 메타 설명 절단·JA 카피·가격 메모 결측 같은 **온사이트 미세 조정**이었다 — 이미 이기고 있는 place 층이거나, 카피로 안 뒤집히는 허브 층이었다.
- 개입이 사람 기억에 걸려 있어 큐(`data/seo-queue.json`)를 9월에야 만들었다.

## 6. 시스템에 없던 것

| 없던 것 | 결과 | P의 여행에서 |
|---|---|---|
| **착수 전 경쟁 판정** — `keyword-mine.mjs`는 「재고 5곳 이상이면 page-candidate」, 즉 「답할 수 있나」만 물었다(`docs/KEYWORD-DIFFICULTY.md` §0) | 헤드 허브를 만들고 나중에 lost-shape로 판정 | keyword gate를 **페이지 작업 전에** 강제(`scripts/seo/keyword-gate.mjs`, 검증기가 content·landing 개입에 target 검색어를 요구) |
| 검색어 **모양** 판정 | 사후 측정에서 「가게 이름 포함」 AUC 0.775(이김), 「지역+업태 일반형」 0.328(짐)이 가장 강한 신호였다 | `head` 표시 + K3(헤드·포털 벽) 킬. 세부 지역 × 기분 × 대표 지명 롱테일로 간다 |
| 사람이 보는 SERP 기록 | 사후에 「상위 10 대형매체 수」를 재 봤지만 AUC 0.604로 승패를 못 갈랐다(같은 문서 §3) — **숫자 한 축으로는 안 된다** | SERP는 점수 하나가 아니라 「누가·어떤 형식으로·같은 개념이 있나」를 사람이 적는 정성 기록. 숫자 예측력이 증명된 것은 모양 축뿐이라는 점을 루브릭에 적었다 |
| 네이버 | 독자가 영·일본어라 네이버를 「잘못된 계기」로 뺐다(`docs/SEO-GEO-STRATEGY.md` §10) — 그 프로젝트에서는 맞는 판단 | P의 여행은 한국어 — 네이버가 본선이다. 플레이스·블로그 블록은 비키고 웹문서·오프사이트로 간다(`references/naver.md`) |
| 백링크·브랜드 신호 | 외부 인용 0건 → 절벽. 오프사이트 계획은 있었지만 이행 0% | 오프사이트를 `queue_kind: offsite` 개입으로 큐에 올리고 게시 URL로 채점 |
| 의도 적합성 | `breakfast in seoul`처럼 우리 재고는 있지만 검색자가 원하는 형식이 다른 검색어를 노렸다 | intent_fit 축 + K1 |
| 얇은·중복 페이지 경계 | 이중언어 950쪽 프로그래매틱. JA 허브 4층 활성 0장(진단 2026-09-01T1541 period_note) | 재고 10곳 미만 조합은 안 만든다(K4). 1단계는 허브 + 지역 15쪽만, 기분 조합은 target만 |
| 포지션 | 「로컬이 가는 서울 맛집」은 수많은 매체가 쓰는 말이다 | P·무계획·지금·기분 — 남이 안 쓰는 각도(엔티티 문장 고정) |

## 7. 그대로 가져온 것 (작동했다)

- 크롤 감사를 dist 전수로 오프라인에서 돌리는 계기(`seo-crawl.mjs`), 게이트가 아닌 계기판(exit 0).
- 진단 기록 JSON 단일 출처 + 렌더 + 검증기(정렬 규칙·자격·채점 불가 표현 차단).
- 지난 진단 채점을 리포트 첫 절로, 실행률로 개입 수 상한.
- 사전등록·널 모델 채점 산술(`score.mjs`) — 단, 기준선이 생긴 뒤에만.
- 「1회 관측을 성과로 읽지 않는다」, llms.txt는 KPI가 아니다, 유료 SERP API 금지.
- query 차원으로 페이지 총량을 계산하지 않는다(익명화로 노출 72%가 사라짐, `docs/KEYWORD-DIFFICULTY.md` §9).
