# ADR-0069: 걸어서는 도보 길찾기 · 섬 카드는 배 타는 곳까지 · 길찾기 링크 실측과 실기기 점검표

Status: Accepted (2026-10-01)

## Context

ADR-0067은 모든 카드의 `길찾기`를 카카오맵 **자동차** 길찾기(`map.kakao.com/link/to/이름,위도,경도`)로 열었고, 한계 셋을 Consequences에 남겼다.

1. 걸어서 가는 카드도 자동차 길찾기다. 웹 링크로 수단을 「도보」로 지정하려면 출발지가 필요하다고 봤다.
2. 우도·비양도 같은 섬 카드는 카카오가 배편 구간을 어떻게 안내하는지 정하지 못한다.
3. 실기기(iOS Safari·카카오톡 인앱·Android Chrome, 앱 있음/없음) 확인은 배포 뒤로 미뤘고, 302 응답까지만 봤다.

출발지(지금 위치)를 링크에 넣으면 개인정보 안내(「위치는 기기 밖으로 나가지 않아요」)와 어긋난다. 출발지 없이 되는 길이 있는지가 먼저다.

### 카카오맵 실측 (2026-10-01, curl + Playwright, UA 5종 + PC)

UA: iOS Safari 18, Android Chrome 128, 삼성 인터넷 26, 카카오톡 인앱(iOS·Android), PC Chrome. 리다이렉트(302)와 카카오 페이지의 스크립트 이동까지 따라갔다.

| 링크 | 모바일 5종(모두 같음) | PC |
|---|---|---|
| 자동차 `map.kakao.com/link/to/이름,위도,경도` (지금) | 302 → `map.kakao.com/?target=car&rt=,,X,Y…` → (스크립트) `m.map.kakao.com/scheme/route?sp=&sn=&ep=위도,경도&en=이름&by=car` → 302 `applink.map.kakao.com/route?…` → (스크립트) **`kakaomap://route?sp=&sn=&ep=…&by=car`** | `map.kakao.com/?target=car&rt=,,X,Y&rt2=이름`(자동차 탭, 도착지 채움) |
| 도보 `m.map.kakao.com/scheme/route?ep=위도,경도&en=이름&by=foot` (공식 모바일웹 스킴) | 302 → `applink.map.kakao.com/route?…&by=foot` → (스크립트) **`kakaomap://route?ep=…&en=…&by=foot`** | `applink…` → `map.kakao.com/?rt=,,X,Y&rt2=이름&fromAppLink=true`(길찾기, 도착지 채움) |
| 도보 웹 `map.kakao.com/link/by/walk/이름,위도,경도` | 302 → `?target=walk&rt=X,Y,,` — 점 하나가 **출발지**로 들어간다 | 같음 |
| `link/to/…?by=foot` | `by`를 무시하고 자동차(`target=car`) | 같음 |

- 자동차 링크는 이미 카카오가 스스로 `scheme/route?sp=&…&by=car`로 보내고 있었다(ADR-0067 조사 때는 302 한 번에 스킴으로 갔고, 지금은 `map.kakao.com/?target=car`를 한 번 거친다). 도보 스킴은 같은 길에서 `by`만 다르다.
- **출발지 없이 된다**: `sp`를 비우면 앱은 현재 위치에서 출발한다(카카오 URL Scheme 문서). 링크에는 도착지 좌표·이름만 들어간다.
- 앱이 없는 폰: 두 링크 모두 같은 카카오 연결 페이지(「연결중입니다」 · `카카오맵 앱 설치` · `설치없이 지도보기`)에서 멈춘다. `설치없이 지도보기`는 `map.kakao.com` 첫 화면이라 도착지가 빠진다 — 자동차 링크도 원래 그랬다. iOS Safari가 `kakaomap://` 실패에 오류 대화상자를 띄우는지는 헤드리스로 알 수 없다(실기기 점검표).

## Decision

### 1. 걸어서 → 카카오맵 도보 길찾기

- `walkDirectionsUrl(spot)` = `https://m.map.kakao.com/scheme/route?ep={위도},{경도}&en={이름}&by=foot`. `sp` 없음. 좌표가 없으면 자동차와 같은 이름 검색.
- **언제 도보인가**: 얼마나가 `걸어서`이고 그 장소가 기준에서 걸어서 범위(15분) 안일 때, 또는 카드가 `걸어서 약 N분`이라고 말할 때(진짜 위치에서 1km 안, ADR-0067의 「걸어서 카드도 자동차」 한계). `걸어서`여도 범위 밖에서 채운 카드(빈손 없음 규칙)는 자동차다.
- 글자는 그대로 `길찾기`. 스크린리더 이름은 `{이름}, 카카오맵 도보 길찾기`.
- 저장한 곳 줄도 같은 규칙(지금 기준·지금 얼마나). 줄은 재사용되므로 그릴 때마다 링크를 고친다.

### 2. 섬 카드 → 배 타는 곳까지

- 섬은 좌표 상자로 가른다(`islandOf`, S33의 상자에 차귀도·추자도를 더함). 기준이 그 섬 위가 아니면(또는 위치를 모르면) `길찾기`는 그 섬 배가 뜨는 곳으로 가는 자동차 길찾기이고 글자는 **`배 타는 곳까지 길찾기`**. 스크린리더: `{이름}, 배 타는 곳 {터미널}까지 카카오맵 자동차 길찾기`. 터미널이 걸어서 범위 안이면 도보.
- 기준이 같은 섬 위면 보통 `길찾기`(장소로). 섬에서 본섬 장소(배 타고 나가야 함)는 지금처럼 장소로 가는 자동차 길찾기 — 이번 범위 밖.
- 섬 → 배 타는 곳(카카오맵 장소 검색으로 고정, 2026-10-01):

  | 섬 | 상자(위도·경도) | spots.json | 배 타는 곳 | 좌표 | 카카오 장소 id |

### 3. 길찾기 링크 실측 자동화와 실기기 점검표

- **`npm run check:links`**(`scripts/check-links.ts`): 위 UA 5종 + PC로 자동차·도보·배 타는 곳 링크를 실제 브라우저(Playwright)로 열어 카카오의 리다이렉트·스크립트 이동을 따라가고, 카카오의 앱·웹 연결 페이지 `applink.map.kakao.com/route?…`에 도착지·수단이 맞게 들어가고 `sp`가 비어 있음을 고정한다(PC: 자동차·배 타는 곳은 도착지가 채워진 `map.kakao.com/?target=car…`, 도보는 같은 연결 페이지). 그 페이지의 앱 호출 `kakaomap://route?…`(같은 쿼리)는 앱 없는 헤드리스 브라우저에서 보일 때도 안 보일 때도 있어 보이면 출력만 한다. 네트워크가 필요하므로 `npm test`(vitest)에 넣지 않는다. 카카오가 바꾸면 이 검사가 먼저 깨진다.
- 링크 모양은 vitest가 지킨다(D8~D10): 도보 링크 모양, 섬 85곳 모두 배 타는 곳, 터미널은 본섬·제주 안, **어떤 링크에도 출발 좌표가 들어가지 않음**, 앱에서 걸어서 카드는 도보·섬 카드는 `배 타는 곳까지 길찾기`. e2e `DR-ferry`: 320·390에서 한 줄·44px·가로 넘침 0.
- 자동화할 수 없는 것(앱 설치 여부, iOS의 스킴 실패 대화상자, 인앱 브라우저의 스킴 처리)은 **`docs/device-check.md`**(5분, 8칸 표)로 사용자가 실기기에서 본다.

## Consequences

- ADR-0067 Consequences의 한계 1(걸어서도 자동차)·2(섬)는 이 결정으로 바뀐다. 3(실기기)은 자동 실측 + 점검표로 줄었지만 실기기 확인은 여전히 사람이 한다.
- 개인정보 안내 문장을 바로잡았다: 링크에는 가려는 곳(섬이면 배 타는 곳)의 번호·이름·좌표만 들어가고 지금 위치는 넣지 않는다. 출발지는 카카오맵이 그 기기에서 정한다.
- 앱 없는 폰에서 `설치없이 지도보기`가 도착지를 잃는 것은 카카오 쪽 동작이다. 자동차 링크도 같다. 우리가 UA를 보고 링크를 가르지 않는다(ADR-0067 1-1 그대로).
- 데이터 문제(고치지 않음, 보고만): spots.json의 「비양도」(섬 자체) 핀이 본섬 협재 쪽(33.3819, 126.2497)에 있어 섬으로 잡히지 않는다 — 그 카드는 섬 안내 없이 핀으로 길찾기를 연다. 서우봉 핀처럼 데이터 정정 목록에 올린다.
- 상세: `specs/drive-and-agents.md` 5·6절.
