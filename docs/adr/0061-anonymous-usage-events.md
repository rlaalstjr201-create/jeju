# ADR-0061: 익명 사용 기록으로 인기도 측정

Status: Accepted (2026-09-30)

Superseded in part by ADR-0078 (2026-10-03): 「수집 주소가 빌드 설정에 없으면 아무것도 보내지 않는다」는 운영 빌드에서 금지로 바뀌었고, 「쿠키 안 보냄」은 자체 기록에만 남는다(GA4·네이버 애널리틱스는 쿠키를 쓴다).

## Context

만족도 점수(ADR-0060)는 원본 글을 근거로 한 추정이다. 실제 여행자가 무엇을 저장하고 지도를 여는지가 더 정확한 인기 신호다. 지금 앱은 로그인이 없고(ADR-0026) 모든 값이 기기에만 있으며, 외부 요청은 사진과 링크 이동뿐이다.

## Decision

1. **보내는 것**: 장소 단위 익명 이벤트만. `shown`(카드 노출), `save`/`unsave`(하트), `map`(카카오맵 열기), `book`(예약 링크), 그리고 `mood`·범위·기준 종류(여기/숙소/지역, 날짜 모드 여부).
2. **보내지 않는 것**: 좌표, 숙소 위치, 기기·사용자 식별자, 쿠키, IP 저장. 서버는 IP를 기록하지 않는다.
3. **방식**: `navigator.sendBeacon`으로 묶어 보낸다. 오프라인이면 버리고, 실패해도 앱 동작에 영향 없음. 수집 주소가 빌드 설정에 없으면 아무것도 보내지 않는다.
4. **고지**: 저장 목록 각주 또는 첫 화면 하단에 한 줄로 "어디가 좋았는지 익명으로 세어요"를 알린다. 끄기 설정을 둔다.
5. **서버**: 호스팅 결정 전이므로 클라이언트와 이벤트 형식·받는 쪽 최소 구현(일별 장소×이벤트 카운터)만 만든다. 호스트가 정해지면 붙인다.
6. **인기도 반영**: 모인 카운트는 빌드 때 집계해 점수에 섞는다(ADR-0060 5).

## Consequences

- "외부 요청은 사진과 링크뿐"이던 원칙(ADR-0058 KEEP)을 이 이벤트 전송만큼 넓힌다.
- 상세는 `specs/usage-events.md`.

## Amendment 1 (2026-10-20, specs/busan.md 7, plans/busan.md S7 M6): 여행지와 시작 화면

- 맥락에 `dest`(`jeju`|`busan`)를 더한다. 출시 스위치를 켠 앱만 보낸다. 장소 이벤트의 카운터 키는 그대로다(장소 id 머리말이 여행지를 말한다).
- 이벤트 이름에 `start_view`(시작 화면이 1초 넘게 보임)와 `start_done`(`how`·`why`·`dest`)을 더한다. 장소·위치는 없다. 카운터 id는 `start:view`, `start:<how>:<why>:<dest>`.
- 받는 쪽은 앱보다 먼저(같은 배포 포함) 바뀐다. 옛 앱 묶음(`dest` 없음)과 새 앱 묶음을 모두 받고, 모르는 필드·값은 지금처럼 묶음을 통째로 거절한다. D1 표(`counters`)는 바꾸지 않는다.
