# ADR-0112: 지금 주변 문화생활 — 서울시 문화행사 층, 첫 판

Status: Accepted (2026-11-04, 주인 「서울시 데이터랑 팝업으로 먼저 진행해 … 정보의 홍수에 빠지면 안되니까」, Plan Review MAJOR 4 반영).
Spec `specs/now-culture.md`, plan `plans/now-culture.md`(판 2).

## Context

- 맞대결 01·02에서 진 이유는 「지금·여기」 정보였다. 트렌드 01~06에서 팝업은 무료 수집 + 주 1회 AI 검수로 재현율 61.3%·정밀도 96.8%에 닿았다(재측정 필요).
- 서울시 문화행사 API는 오늘 열린 행사가 약 200건이고, 그중 절반 가까이가 신청제 강좌·4달 넘는 상설 전시다. 그대로 보이면 정보의 홍수가 된다.
- API의 날짜 칸은 「그날 시작하는 행사」만 거른다. 「그날 열려 있는 행사」는 전체(약 2만 건, 1,000건씩 약 20회)를 훑어야 한다.

## Decision

1. **층**: 장소 카드와 다른 「기간이 있는 것」 층. 첫 판은 서울시 문화행사 갈래만. 팝업은 다른 날짜 재측정 통과 뒤, 공연(KOPIS·인디·라이브클럽)은 키 뒤에 같은 꼴로 붙인다.
2. **적게**: 홈 최대 2개, 목록 시트 최대 6개. 넘겨 보기 없음(장소 카드의 「다른 3곳 보기」 ADR-0058과 다른 층). 같은 종류 둘까지, 같은 장소 하나, 같은 제목 회차는 하나.
3. **거르기**: 신청·회차 강좌, 어린이 단체·유아 전용, 좌표가 이상한 행(서울 밖·뒤바뀜·구 불일치)을 뺀다. 기간이 확실하지 않으면 넣지 않는다.
4. **지금**: 끝 날짜와 읽힌 시간은 앱이 지금 시각으로 다시 거른다. **시간을 모르는 실내 행사(전시 등)는 19:00~09:00에 뺀다** — ADR-0111 3의 시간대 규칙을 서울 문화행사 층에 넓힌다(ADR-0111 결정 6의 「제주만」은 장소 카드에 대한 것으로 그대로).
5. **순서**: 가까움(걸어서 15분 안 > 차로 15분 안; 그 밖은 홈에 올리지 않음, 범위 시트 ADR-0060과 별개) → 지금성(오늘만·이번 주 끝남 > 한 달 > 4달 > 상설) → 열림 확실 → 누구나·무료.
6. **받는 길**: Pages Function `GET /api/culture?city=seoul`이 서울 API 전체를 훑어 거른 목록을 돌려준다. 키는 Cloudflare 비밀값 `SEOUL_OPEN_API_KEY`(비 소식 `/api/rain`과 같은 방식).
   엣지 캐시는 KST 날짜별(하루 한 번 훑기), 응답 `Cache-Control: max-age=3600`. 서울 API가 실패하면 204 — 앱은 줄을 숨긴다(낡은 목록을 보이지 않음).
   위치는 보내지 않는다(서울 목록 전체를 받고 앱이 거리로 거름). 서비스 워커 미리받기에 넣지 않는다.
7. **품질 게이트**: 화면 전에 사전등록 측정(plan §4-2: 장면 6 × 시각 3, 눈가림, 후보 풀·대조 목록, 평균 4점·쓸모없음 1 이하·놓침 1 이하). 통과해야 화면을 만든다.
8. **코드 자리**: `functions/api/culture.ts`(+ `functions/_lib/culture-filter.ts`), 앱 `src/culture.ts`(순수 함수), 화면은 따로 받는 청크(ADR-0100 진입 예산).

## Consequences

- 매일 배포가 필요 없다(함수가 그날 처음 요청 때 훑는다). 서울 API 하루 호출은 엣지 위치 수 × 약 20회.
- 개인정보 안내(네 언어)에는 「서울 문화행사 목록을 받는다(위치는 보내지 않음)」만 더한다.
- 출처 표시: 「정보: 서울시 문화행사(서울 열린데이터광장)」.
- 배포 때 Cloudflare 비밀값 등록은 주인 승인 후 한다.
