# ADR-0083: 노을 볼 곳 — OSM 해안선 계산 + 원문 확인으로 `sunsetView`, 오늘 판 노을 줄

Status: Accepted (2026-10-04). ADR-0075 2의 「노을(이슈 01이 끝난 뒤)」 자리를 채운다. 주인 지시(2026-10-04 「묻지 말고 끝까지」)로 아래 결정은 에이전트가 정했다.

## Context

ADR-0075는 오늘 판 둘째 줄의 우선순위를 비 → 노을 → 장날로 정해 두었지만 노을 데이터가 없었다. 소개글에 노을 단어가 있는 곳만 쓰면 32곳이고 노을과 무관한 곳도 섞인다(`mockup-fixes.md` §1). 시험 스크립트(`sunset-check.mjs`)는 해 지는 방향으로 선을 그어 바다로 나가는지 보는 방법이 가장 잘 맞았다.

새로 낼 ADR인지, ADR-0075 개정인지: 새 데이터 출처(OSM, ODbL)·새 판정 기록·새 출하 필드가 함께 들어와서 ADR-0080(철)·ADR-0065(실내)처럼 따로 낸다. ADR-0075에는 이 ADR을 가리키는 개정 한 줄만 단다.

## Decision

1. **해안선**: OSM `natural=coastline`을 한 번 받아 `apps/web/data/coast/jeju-coast.geojson`으로 고정한다(5m 단순화, 출처·쿼리·해시는 같은 폴더 README). 빌드는 받지 않는다. 출처 줄에 「© OpenStreetMap contributors」를 단다(홈 아래 출처 줄은 노을 묶음이 있을 때, 저장한 곳 화면 아래 「정보」 줄은 늘).
2. **계산**: 해 지는 방위 셋(242°·264°·298°)마다 ±10° 세 줄 중 하나가 300m 안에 바다로 나가고 20km 안에서 본섬·자기 섬에 다시 닿지 않으면 그 방위가 보인다. 언덕 높이는 모른다.
3. **판정**: 계산 후보(실외이거나 원문에 바다 단어) ∪ 원문 노을 단어 ∪ 오름 후보를 원문으로 판정한다. 기준은 판정 전에 커밋하고, 애매하면 뺀다. 무작위 5%를 다른 서브에이전트가 블라인드로 한 번 재판정해 85% 이상이면 싣는다. 못 미치면 싣지 않는다.
4. **데이터**: 확인된 곳에만 `sunsetView: number[]`(보이는 방위). 오름 후보와 계산 밖의 원문 노을 곳은 세 방위 모두(높이·원문이 계산을 대신한다). 앱은 그날 방위에 가장 가까운 것을 쓴다. 붙이기는 멱등 `scripts/sunset.mjs`, `build-spots.mjs`에서는 철 뒤.
5. **오늘 줄**: 지금 모드, 기준 있음, 비 소식 없음, 해 지기 2시간 30분 전부터 해 질 때까지, 그날 방위가 보이는 곳이 차로 45분 안 3곳 이상일 때만 「노을 볼 곳 N곳 · 차로 45분 안 ›」. 누르면 장날 줄처럼 아래 「노을 볼 곳」 묶음(가까운 순 최대 5곳, 길찾기 링크)으로 내려간다. 비가 오면 노을 줄·묶음 모두 없다.
6. **카드에는 넣지 않는다**: 메타 줄에 이미 실내·철·장날 글자가 있다. 노을은 시간이 정해진 정보라 오늘 줄로만 알린다.
7. **기록**: 장날 줄처럼 누름 이벤트를 따로 만들지 않는다.

## Consequences

- 줄이 없는 동안 홈은 이전과 같다. 시계는 창이 열리고 닫히는 순간 두 번만 다시 그리게 한다.
- 높은 곳(사라봉·군산오름 등)은 계산으로 못 잡아 원문(오름 후보)에 기댄다. 원문에 없으면 빠진다.
- 국토지리정보원 해안선(공공누리)으로 바꿀지는 확인 못 했다. 바꾸면 이 ADR을 고친다.
- 판정 수·감사 결과는 `apps/web/review/sunset/REPORT.md`.
