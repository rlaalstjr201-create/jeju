# ADR-0075: 홈 개편 A′ — 오늘 판, 기분 줄 사진, 아래 두 묶음. 결과 화면 작은 고침

Status: Accepted (2026-10-03). ADR-0029 Consequences의 「첫 화면은 그대로 조용하게」와 SPEC §1-1의 위 5 : 아래 2 빈칸을 대체한다.

Superseded in part by ADR-0092 (2026-10-16): 6의 「기분 5개」 → 6개(기분 줄 4 → 5, 「유명한 데 가 보고 싶어」). 첫 탭 흐름·카드 3장은 그대로.

Superseded in part by ADR-0094 (2026-10-18): Amendment 1의 「홈은 위치 권한을 먼저 묻지 않는다」 가운데 여행지를 모르는 **첫 방문**은 시작 화면의 「내 위치로 시작하기」를 누를 때 묻는다. 여행지를 아는 뒤의 방문은 그대로.

## Context

배포 뒤 주인 피드백: 첫 화면이 비어 보이고 덜 만든 것 같다.

UX 감사(`docs/research/ux-audit/report.md`, 기준 `ux-audit-criteria.md`)의 결과:
- 우리 앱은 결과 화면 덕에 81.9점이었다.
- 하지만 홈은 첫 화면 밀도 1점, 5초 이해 2점, 사진이 색을 맡나 2점이었다.

목업 판정(`mockup-judgment.md`)은 요소마다 「답습 / 조건부 / 도움」을 가렸다.
- 2판 A′(`apps/web/design/proto-d/a2.html`)는 조건부 요소를 고친 안이다.
- 사용자가 A′를 골랐다(2026-10-03). 문제 해결책(`mockup-fixes.md`)도 모두 받아들였다.

## Decision

1. **홈 위쪽 빈칸을 없앤다.**
   - 빈칸 대신 위에서부터 이렇게 놓는다: 앱 이름 한 줄 → **오늘 판** → 질문 + 설명 한 줄(「하나 고르면 근처 3곳을 골라 드려요」) → 기분 4줄 → 아무거나.
   - 흰 바탕과 3색(ADR-0070)은 그대로다.
2. **오늘 판**의 두 줄:
   - 첫 줄은 날짜이고, 같은 줄에 회색으로 접힌 정보가 붙는다.
   - 둘째 줄은 **누를 수 있는 줄 최대 하나**다. 우선순위는 놓치면 사라지는 순서다: 비 소식(ADR-0076) → 노을(`.scratch/home-refresh/issues/01`이 끝난 뒤) → 오늘 장날.
   - 행동이 없는 정보(해 지는 시각 등)는 회색 글자로만 둔다.
   - 해 지는 시각은 기기 안에서 계산한다. 외부 요청은 없다.
3. **기분 줄 사진**:
   - 줄마다 그 기분에서 **지금 기준으로 실제 먼저 나올 2곳**의 사진 2장(52px)을 붙이고, 「예: 이름, 이름」을 쓴다.
   - 기준을 모를 때는 섬 전체의 상위 2곳을 쓴다. 기준을 모르는 경우는 GPS 기준이고 이 세션에 아직 위치가 없을 때다. 「예:」는 약속이 아니라 보기라는 표시다.
   - 고르는 규칙은 결과와 같다(`pick.ts` `pool`, 범위·실내·날짜 포함).
   - 위치를 묻는 시점은 바꾸지 않는다. 지금처럼 기분을 누를 때 묻는다.
4. **아래 두 묶음** (스크롤해야 보인다):
   - 「오늘 장 서는 곳」: 기준이 있으면 차로 30분 안만 넣고, 없으면 오늘 서는 장 전부를 지역 이름과 함께 넣는다. 없으면 묶음째 숨긴다.
   - 「다른 동네 둘러보기」: 지금 동네를 뺀 지역 사진 타일이다. 이미 있는 지역 페이지(`/jeju/<slug>/`, ADR-0072)로 연결한다. 사진은 늦게 불러온다(lazy).
5. **결과 화면**:
   - 큰 카드의 「길찾기」를 연파랑 바탕 버튼으로 바꾼다(높이 48). 작은 카드는 지금 그대로다.
   - 실내만 켜져 있으면 머리줄에 「· 실내만」을 붙인다.
   - 고르는 방식을 한 줄로 쓴다. 범위·실내에 맞춰 문장을 바꾼다.
   - 큰 카드와 「아니면」 사이를 넓힌다.
6. **그대로 두는 것**: 기분 5개와 첫 탭 흐름, 카드 3장, 가격·평점·배지 없음, 로그인 없음, 뒤로 가기 동작(홈이 첫 기록이다 — e2e S17~S20), 슬롭 체크리스트(SPEC §14).

## Consequences

- 첫 화면 사진이 0장에서 8장으로 는다. 모두 비짓제주 CDN 핫링크이고, 결과 화면과 같은 출처·같은 이용 확인 범위다(ADR-0072 Amendment 1).
- 홈이 `spots.json`을 읽어야 사진·예시를 그린다. 데이터가 오기 전에는 사진을 그리지 않는다(회색 자리 없음, SPEC §14). 줄 높이가 자리를 잡아 글자와 버튼은 바로 쓸 수 있다(이른 탭 스크립트는 그대로 둔다).
- SPEC §1-1·§6 홈 절과 design.md 「5:2 여백」을 이 ADR에 맞춰 고친다.
- 사용자 시험(`mockup-judgment.md` 5절)은 배포 뒤 이 화면으로 한다. 통과 기준을 못 넘으면 이 ADR을 다시 연다.

## Amendment 1 (2026-10-03): 위치를 모를 때의 홈 (정합성 감사 D1)

정합성 감사(`docs/coherence-audit-2026-10-03.md` 1~4번): GPS 기준이고 이 세션에 위치가 없으면, 「내 위치 근처」 라벨과 「지금 내 위치 근처에서」 문장 아래에 섬 전체 1위 장날(예: 중문)과 섬 전체 상위 2곳 예시가 놓여 먼 곳이 「내 근처」로 읽혔다. 사용자 결정 (a).

- **권한이 이미 `granted`면 홈에서 묻지 않고 위치를 읽는다.** Permissions API가 `granted`라고 할 때만, 홈이 열릴 때(앞으로 돌아왔을 때 포함) 한 번 읽는다. 기분을 누를 때와 같은 위치 읽기(같은 시간 제한)이고, 읽으면 이 세션의 GPS 기준이 되어 예시·장날 줄·비 소식이 모두 실제 근처가 된다. 읽기에 실패해도 아무것도 바꾸지 않는다(`지역 고르기`로 바꾸지 않음).
- **권한이 `granted`가 아니면 홈에서는 절대 묻지 않는다.** 처음 묻는 시점은 기분을 누를 때 그대로다(3, SPEC 6.3).
- **위치가 없는 동안**: 오늘 판에 장날 줄을 올리지 않는다. 아래 「오늘 장 서는 곳」 묶음은 줄마다 지역 이름이 붙으므로 그대로 둔다. 기분 줄 예시의 머리말은 「예: A, B」 대신 「제주 인기: A, B」다. 위치가 생기면 「예:」로 돌아간다.
- 3의 「위치를 묻는 시점은 바꾸지 않는다」는 그대로다. 이 보완은 *묻지 않고 읽기*만 더한다.

## Amendment 2 (2026-10-04): 노을 줄

2의 「노을」 자리는 ADR-0083이 채운다. 우선순위 비 → 노을 → 장날은 그대로이고, 비가 오면 노을 줄은 접히지 않고 아예 없다.
