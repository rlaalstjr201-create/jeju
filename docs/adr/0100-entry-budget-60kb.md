# ADR-0100: 한국어 진입 JS+CSS 예산을 gzip 50,000 B에서 60,000 B로

Status: Accepted (2026-10-27, 주인 결정). ADR-0093 12·ADR-0058(JS+CSS gzip ≤ 50KB KEEP)의 한도 값만 바꾼다. 「프레임워크 없음·웹폰트 0」은 그대로다.

## Context

- 한국어 진입 JS+CSS가 gzip 49,555 B로, 50,000 B 예산에 445 B만 남았다(36.5KB → 43.9KB → 48.2KB → 49.6KB로 다국어와 부산이 들어오며 찼다).
- 주인이 여차나의 방향을 밝혔다: 범위를 전국으로 넓혀 「내 위치 기반으로 지금 주변에서 할 만한 것」을 추천받는 앱. 이를 위해 첫 화면을 사진 중심의 깔끔한 UI로 고치고, 공유 링크처럼 사람을 모으는 장치를 넣으려 한다. 둘 다 JS와 CSS를 늘린다.
- 이 한도는 처음 로딩을 가볍게 하려고 스스로 둔 값이지 기술적 한계가 아니다(ADR-0058).

## Decision

1. 한국어 진입 JS+CSS gzip 예산을 **60,000 B**로 올린다(Vite가 보이는 kB, 1000 B 기준 그대로). 값은 `scripts/jeju-baseline.ts`의 `BUDGET`에 있다.
2. 올린 만큼을 다 쓰자는 뜻이 아니다. 새 기능은 먼저 눌렀을 때 따로 받는 청크로 나누고(ADR-0098 방식), 첫 화면에 얹는 것은 그다음에 정한다.
3. 시작 화면 인라인 블록 상한(2,000 B)은 이 ADR이 건드리지 않는다.

## Consequences

- 첫 로딩에서 내려받는 코드가 최대 10KB까지 늘 수 있다. 느려졌는지는 Lighthouse로 다시 재야 한다(이 ADR은 재지 않았다).
- 전국 확장 자체는 이 ADR의 범위가 아니다. 범위·데이터·추천 방식은 grilling과 별도 ADR로 정한다.
