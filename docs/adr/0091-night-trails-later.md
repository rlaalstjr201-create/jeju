# ADR-0091: 해가 진 뒤에는 산·오름·숲길 같은 야외 산길을 뒤로 미룬다

Status: Accepted (2026-10-16, 주인이 「가」를 고름 — 뒤로 미루고 한 줄로 알림. 빼지는 않음).

## Context

- 첫 사용자 평가 3명 모두(`docs/research/heuristic-audit-02/02-synthesis.md`) 자정(00:25) 「지금」 결과에 어승생악 오르기가 나온 것을 큰 문제로 꼽았다. 지금 고르기는 시각을 보지 않는다.
- 운영시간은 데이터에 넣지 않는다(ADR-0025·0027·0058). 그러나 해 지는·뜨는 시각은 계산할 수 있다(`src/sun.ts`, ADR-0083). 날짜로 정해지는 규칙(장날·철·노을)만 반영한다는 원칙과 맞는다.
- 주인 선택지: 가) 뒤로 미루고 한 줄 알림, 나) 아예 빼기, 다) 표시만. **가**.

## Decision

1. **야외 산길**(`trail`): 걷는 것이 주인 곳 중 시내에서 떨어진, 밤에 어두운 자연 산길 — 오름, 산·봉우리 오르기(○○악·○○봉 등), 숲길·숲 탐방로·자연휴양림·곶자왈, 계곡 탐방로, 산간 둘레길. **아님**: 해변·해안 산책로·포구, 시내 공원·광장·마을 돌담길, 차로 바로 닿는 전망대, 정원·테마파크 같은 운영 시설, 실내.
2. **판정**: 노을 볼 곳(ADR-0083)과 같은 길 — 원문(이름·태그·소개)으로 판정(`review/night/trail-NN.json`) → 예시를 모르는 평가자가 표본을 다시 판정(`review/night/audit-NN.json`) → 기준을 넘은 회차만 붙인다(`scripts/night.mjs`, 출하 `spots.json`에 `trail: true`, 멱등, `build:spots` 안 씀). 판정 기준·검사 기준은 `specs/night-trails.md`에 측정 전 고정.
3. **밤**: 기준점(지금 위치·숙소·동네 중심)에서 **오늘 해 진 뒤 ~ 내일 해 뜨기 전**(해 뜨는 시각은 `sun.ts`에 같은 방식으로 더함). 「지금」일 때만 — 날짜를 고른 날(날짜 모드)에는 시각이 없으니 적용하지 않는다.
4. **뒤로 미루기**: 밤이면 고르기·「다른 3곳 보기」·홈 「예:」에서 야외 산길을 다른 후보 뒤로 보낸다(빼지 않음 — 다른 후보가 모자라면 나온다). 넓히기·60분 가드·순환 규칙은 그대로.
5. **알림**: 밤이고 이번 결과의 후보에 야외 산길이 있어 순서가 바뀌었으면 상태 줄에 `밤이라 산길은 뒤로 미뤘어요.` 한 줄. 안 바뀌었으면 말하지 않는다.
6. 기록·분석에는 새 항목을 더하지 않는다.

## Consequences

- 밤에 「좀 걷고 싶어」는 해안 산책로·시내 길·실내가 먼저 나온다. 산간 동네는 밤에도 산길이 나올 수 있다(빼지 않으므로) — 그때도 상태 줄이 알린다.
- 판정이 틀리면 엉뚱한 곳이 밀린다. 그래서 검사 기준을 통과한 회차만 붙인다.
