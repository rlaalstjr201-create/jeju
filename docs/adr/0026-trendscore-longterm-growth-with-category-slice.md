# ADR-0026: trendScore 정의 — 장기 증가율 기반 + 카테고리 슬라이스

Status: Accepted (2026-05-19)

## Context

ADR-0023·0024에서 비짓제주를 1차 소스로, 데이터 소스 매트릭스를 확정했다. D-CUR-3에서 trendScore 도입 자체는 결정됐으나, 공식·시간 윈도우·집계 단위는 미결 상태였다.

v1 대상인 4박5일 여행자는 "2주 전 신상"보다 "1년 누적 증가세"가 실질적으로 유효하다. 1~3개월 lag은 약점이 아니라 반짝 노이즈를 자동 필터하는 장치로 해석된다.

## Decision

- **trendScore 공식**: z-score((최근 6개월 평균 방문자) / (이전 6개월 평균 방문자) - 1)
- **데이터 소스**: 빅데이터\_지역별 방문자수\_GW (data.go.kr, KT/SKT 이동통신 기반)
- **집계 단위**: 시·군·구 또는 읍·면·동 격자
- **카테고리 슬라이스 적용**: 격자 × 업종 단위로 계산. "한경면 카페업 +45%"처럼 동일 격자 내 업종별 신호를 분리한다.
- **최소 시계열 요건**: 12개월 미달 Spot은 trendScore = null (큐레이터 인지 수단 필요).
- **음수 허용**: 식어가는 격자에 패널티를 부여해 popularSpots 트랙에서 down-rank.
- **1~3개월 lag**: "장기 검증 필터"로 해석. 인스타·실시간 SNS는 v1 자동 신호에서 제외.

## Consequences

**Positive:**
- 4박5일 여행자 시점에 유효한 trend만 통과. 도착 후 이미 식은 단기 노이즈를 걸러낸다.
- 카테고리 슬라이스로 격자→업종 신호 정확도 향상 (해법 ① "카테고리 슬라이스").
- 광고·인플루언서 노이즈를 구조적으로 차단해 ADR-0010 큐레이터-thesis를 보호한다.

**Negative / Risk:**
- 신생 Spot(1년 미만)은 trendScore = null. 큐레이터가 인스타 수동 큐레이션(v1.5)으로 보완하기 전까지 인지 수단이 없다.
- 카테고리 슬라이스는 동일 격자에 동업종 후보 Spot이 여러 개일 때 "어느 Spot이 +45% 기여했는지" 특정 불가. 큐레이터 보조 신호로만 활용하며 단독 승인 근거로 쓰지 않는다.

## Alternatives Considered

**단기 트렌드 (1~3개월 window):** 기각.
- 사용자 도착 시점(1~2개월 뒤)에 이미 식어있을 가능성이 높고, 반짝 이벤트·인플루언서 방문과 구분이 안 된다.

**인스타·SNS API 자동 통합:** 기각.
- TOS·정책 불안정으로 데이터 수급이 언제든 끊길 수 있고, 광고 노이즈 필터링 비용이 크다. v1.5 수동 큐레이션 도구로 미룬다.

**격자 통합 trend만 (업종 미분리):** 기각.
- "이 동네는 뜨는데 어디지?" 모호함이 그대로 남는다. 카테고리 슬라이스로 신호 정확도를 높이는 이점이 크다.
