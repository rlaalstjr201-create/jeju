# ADR-0085: 저장 목록 흐름을 기록에 더한다 (시각 없이)

Status: Accepted (2026-10-09). ADR-0061의 이벤트 목록을 넓힌다. 「시각·기기 번호 없음」은 그대로다.

## Context

날짜·저장 흐름을 바꿀지 판단하는 근거를 실제 사용자 기록에서 얻기로 했다(2026-10-09 주인: 사람을 모집한 시험 대신, 업데이트 뒤 GA4·자체 기록으로 확인). 가상 여행자 실험(`docs/research/p-persona-sim-01/40-report.md`)은 지금 앱에서 밤에 「지금」으로 담은 곳이 다음 날 「지난 날」로 접혀 끊긴다는 구조 문제를 냈다. 하지만 지금 기록에는 저장 목록을 열었는지, 목록에서 길찾기를 열었는지, 담은 지 며칠 지났는지가 없다. 자체 기록 전체도 아직 하루치(기분 탭 2회)다.

## Decision

1. 이벤트를 더한다: 저장 목록 열기(`open`), 목록 정리(`arrange`), 그리고 길찾기의 출처(`from: 'saved'`)와 그 줄을 담은 지 며칠(`age` 0·1·2+), 「지난 날」 묶음이었는지(`past`). 상세는 `specs/saved-flow-events.md`.
2. **밤·낮이나 시각은 보내지 않는다.** 「밤에 담은 하트」를 직접 세는 대신, 끊김을 일으키는 상태(♥ 0인데 접힌 줄이 있음, 접힌 줄에서 연 길찾기, 하루 이상 지난 줄에서 연 길찾기)를 센다. 개인정보 안내의 약속을 바꾸지 않기 위해서다.
3. 「담은 날」은 기기 안에만 둔다. 서로 다른 날의 행동을 한 사람으로 잇는 번호는 만들지 않는다. 그래서 「다음 날 이어짐」은 전체 비율로 근사한다.
4. D1 표 구조는 그대로 두고, 장소가 없는 값은 `tap`처럼 고정 문자열 id로 센다.

## Consequences

- 개인정보 안내에 보내는 항목 한 줄이 늘어난다.
- GA4 보고서에 나오려면 맞춤 측정기준 등록이 필요하다(사람 몫).
- 근사의 한계: 사람 단위가 아니어서 「같은 사람이 밤에 담고 다음 날 열었다」를 확정하지 못한다. 흐름을 바꾼 뒤 같은 항목으로 전후를 비교하는 데 쓴다.
