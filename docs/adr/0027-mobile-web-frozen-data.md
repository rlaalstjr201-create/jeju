# ADR-0027: 폰 우선 웹(PWA) + 고정 데이터로 새로 만든다

Status: Accepted (2026-09-30)

## Context

목적은 "실제 여행자가 쓰는 것"이다(앱 완성 경험보다 우선). 밤에 "내일 뭐하지?" 하는 사람이 앱을 새로 설치하는 경우는 드물고, 검색·SNS 링크 하나로 바로 열리는 웹이 그 순간에 맞다. ADR-0025의 기능(기분 버튼, 위치, 카드, 외부 링크, 로컬 저장)은 모두 모바일 웹으로 가능하다.

기존 구조(API 서버, DB, Expo 앱)는 큐레이션 시절의 로그인·일정·추천 엔진을 끌고 오고, 수집 파이프라인이 계속 붙을 자리가 된다.

## Decision

- **플랫폼**: 폰 화면 기준 웹 + PWA(홈 화면 추가 시 앱처럼 열림). 스토어 앱이 필요해지면 같은 웹 코드를 Capacitor로 감싼다. Flutter·Codemagic·TestFlight는 그때까지 보류.
- **데이터**: 기존 DB의 스팟 데이터를 JSON 파일로 한 번 뽑아 고정한다. 서버 없음. 추가 수집 없음 — 수집 파이프라인이 붙을 자리 자체를 없애 구조로 강제한다.
- **코드**: 새 폴더에 새로 만든다. 기존 `apps/api`, `apps/mobile`은 지우지 않고 둔다.

## Consequences

- 호스팅은 정적 파일 수준(비용·운영 거의 0).
- 데이터가 낡아도 갱신하지 않는다. 틀리기 쉬운 정보(가격·운영시간)는 카드에 넣지 않고 외부 링크에 맡긴다(ADR-0025).
- 기존 Expo 앱과 API는 이 방향에서 쓰지 않는다.
