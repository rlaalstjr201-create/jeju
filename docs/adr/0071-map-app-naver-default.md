# ADR-0071: 지도 앱은 네이버지도가 기본 · 카카오맵 · TMAP은 설정에서 고른다

Status: Accepted (2026-10-01)

## Context

ADR-0025·0067·0069는 카드의 장소 링크와 `길찾기`를 모두 카카오맵으로 열었다. 사용자는 **네이버지도를 기본**으로 하고, 카카오맵·TMAP을 쓰는 사람은 설정에서 바꾸게 하기로 정했다. 조건(사용자 결정):

- 설정은 저장한 곳 화면 맨 아래 한 줄. 기기에 기억(localStorage, try/catch), 백업 링크에도 담는다. **첫 화면 버튼 수는 그대로.**
- 길찾기(자동차 · 도보 · 섬이면 배 타는 곳)는 각 앱 형식으로 좌표 + 이름에서 만든다. **출발지(지금 위치)는 링크에 넣지 않는다**(ADR-0069 원칙 그대로).
- 앱이 없을 때 오류로 끝나면 안 된다. TMAP에 웹 대체가 없으면 「앱 스킴만 + 미설치 안내」와 다른 길 중에서 고르고 이유를 남긴다.
- 장소 정보(카드 이름·사진 탭): 네이버는 `이름 제주` 검색(데이터에 네이버 장소 id가 없다), 카카오는 지금의 카카오 장소 페이지, TMAP은 정해서 남긴다.

### 실측 (2026-10-01, curl + Playwright, 프록시 경유)

UA: iOS Safari 18, Android Chrome 128, 삼성 인터넷 26, 카카오톡 인앱(iOS·Android), PC Chrome 128. 302와 각 지도 페이지의 스크립트 이동까지 따라갔다.

| 링크 | 모바일 | PC |
|---|---|---|
| 네이버 웹 길찾기 `map.naver.com/p/directions/-/{경도},{위도},{이름},,/-/car` (`-` = 출발지 없음, 좌표는 WGS84 그대로 받는다) | 301 `map.naver.com/?elng=…&elat=…&eText=이름&menu=route&routeType=1&pathType=0&appMenu=route&app=Y` → 302 `m.map.naver.com/?…` → 302 `appLink.nhn` → 302 **`m.map.naver.com/appLink.naver?…`**(네이버 앱·웹 연결 페이지) → (스크립트) **`app.map.naver.com/launchApp/?…&fallbackUrl=m.map.naver.com/?…&app=N`** | 200, 그 길찾기 페이지(도착지 채움) |
| 같은 링크 `…/-/walk` | 같은 길, `routeType=4&pathType=3` | 200, 도보 |
| `app.map.naver.com/launchApp/…` | iOS 유니버설 링크(`apple-app-site-association`의 `/launchApp/*`, `com.nhncorp.NaverMap`)·안드로이드 앱 링크(`assetlinks.json`, `com.nhn.android.nmap`). **앱이 없으면** `fallbackUrl`(`m.map.naver.com/?…&app=N`) → `m.search.naver.com` 「빠른길찾기」, 도착지 좌표·이름과 수단(`by^car`/`by^walking`)이 그대로 들어 있다 | 경로형(`launchApp/route/car?dlat=…`)은 500. 공개 문서 없음 → 직접 쓰지 않는다 |
| 네이버 앱 스킴 `nmap://route/car?dlat=&dlng=&dname=&appname=` | 앱이 있으면 가장 빠르나, 없으면 iOS Safari 「주소가 유효하지 않음」, 인앱은 막거나 무시 | 열리지 않음 |
| 네이버 검색 `map.naver.com/p/search/{이름 제주}` | 같은 연결 페이지(`appTargetPage=search&appSchemeName=nmap`) | 200, 검색 결과 |
| TMAP 앱 스킴 `tmap://route?goalname=&goalx={경도}&goaly={위도}` | 앱이 있으면 TMAP 길안내. 없으면 iOS Safari 오류 대화상자, 안드로이드 크롬은 아무 일 없음 — 웹으로 따라갈 수 없다(스킴은 네트워크로 실측 불가, 모양만 고정) | 열리지 않음 |
| TMAP 웹 실행 `apis.openapi.sk.com/tmap/app/execution` · `…/routes` | **`appKey` 필수**(키 없이 401). SK open API 가입·키 발급이 필요하고 키가 페이지 소스에 그대로 드러난다 | — |

- 네이버는 카카오(ADR-0069)와 같은 모양이다: https 링크 하나를 주면 네이버가 앱·웹을 가른다. 게다가 **앱이 없을 때도 도착지·수단이 남는다**(카카오는 `설치없이 지도보기`가 도착지를 잃는다).
- 네이버 연결 페이지는 스크립트로 `launchApp`(유니버설 링크)으로 넘어간다. 사용자 탭이 아닌 이동에서 iOS가 앱을 여는지는 헤드리스로 알 수 없다 — 안 열면 웹 길찾기(도착지 채움)로 떨어지고, 연결 페이지의 `Go to NAVER Maps App` 버튼이 남는다. 실기기 점검표에 넣는다.

## Decision

### 1. 지도 앱 설정

- `MapApp` = `naver` | `kakao` | `tmap`, 기본 `naver`. 저장 키 `jeju.mapApp`(store `get`/`set`의 try/catch, 막히면 이번 방문 메모리). 모르는 값은 `naver`.
- **저장한 곳 화면 맨 아래 한 줄**(`링크로 백업` 아래, 출처 위): `지도 앱  네이버지도 · 카카오맵 · TMAP`, `.tbtn` 세 개 + `aria-pressed`. 고른 것은 굵기 + 3px `--main` 밑줄(선택 탭과 같은 방식, 면 없음 — ADR-0070 4). 첫 화면에는 없다.
- 누르면 결과·저장한 곳 카드의 링크·글자가 바로 바뀐다. 다른 탭에서 바꾸면(`storage`) 따른다.
- **백업 링크**: 네이버지도가 아니면 `#s=…&m=kakao` / `&m=tmap`(비 와요 `&r=1`과 같은 방식, 기본이면 링크는 지금과 같다). 링크를 열면 그 앱으로 바뀌고 저장된다. 모르는 `m` 값은 무시.

### 2. 길찾기 링크 (출발지 없음)

| 앱 | 자동차 · 배 타는 곳 | 도보 |
|---|---|---|
| 네이버지도(기본) | `https://map.naver.com/p/directions/-/{경도},{위도},{이름},,/-/car` | 같은 링크 `/-/walk` |
| 카카오맵 | `https://map.kakao.com/link/to/{이름},{위도},{경도}`(ADR-0067) | `https://m.map.kakao.com/scheme/route?ep=…&en=…&by=foot`(ADR-0069) |
| TMAP | `tmap://route?goalname={이름}&goalx={경도}&goaly={위도}` | **네이버지도 도보 링크** |

- 이름은 `cleanName`, 네이버는 쉼표·슬래시를 공백으로(경로 구분자). 좌표가 없거나 제주 밖이면 그 앱의 이름 검색(TMAP은 네이버 검색).
- 도보·섬 판단(`goLink`)은 ADR-0069 그대로. 바뀌는 것은 링크 모양과 스크린리더 이름의 앱 이름(`{이름}, 네이버지도 자동차 길찾기`, `…, 배 타는 곳 {터미널}까지 TMAP 자동차 길찾기`)뿐이다. 화면 글자 `길찾기`·`배 타는 곳까지 길찾기`는 그대로.
- **네이버는 웹 길찾기 링크 하나**를 쓴다(`nmap://`나 `launchApp`을 직접 쓰지 않는다). 앱 설치·OS·인앱 구분을 네이버가 하고, 앱이 없어도 도착지가 남은 웹 길찾기로 끝나며, PC에서도 열린다. `launchApp` 경로형은 문서가 없고 PC에서 500, `nmap://`는 앱이 없으면 오류다(ADR-0067 1-1의 「UA를 보고 스킴을 고르지 않는다」 그대로).

### 3. TMAP: 앱 스킴만 + 안내

- TMAP은 **앱 스킴만** 쓴다. 웹 대체는 `appKey`가 필요한 SK open API뿐이라 고르지 않았다(키 발급·노출, 무료 운영 원칙 ADR-0063). 안드로이드 `intent://…;S.browser_fallback_url=…`는 iOS에 없어 UA로 링크를 갈라야 하므로 하지 않는다.
- **미설치 안내**: TMAP을 고르면 설정 줄 바로 아래에 `TMAP은 앱이 있어야 열려요. 걸어서 가는 길은 네이버지도로 열어요.`(`role="status"`). TMAP은 사용자가 일부러 고르는 선택지이고 기본이 아니므로, 고르는 순간에 조건을 말해 두는 것으로 「앱 없는 사람이 모르고 오류를 만나는」 경우를 막는다. 그래도 앱 없이 누르면 iOS Safari는 오류 대화상자를 띄운다 — 이것은 브라우저 동작이라 막을 수 없고, 안내 문장과 기본값(네이버)이 대책이다.
- **TMAP의 도보는 네이버지도 도보**: TMAP 공개 스킴(`route`)에 도보 수단 지정이 문서로 확인되지 않는다. 1km 안 카드에 자동차 길안내를 여는 것보다 낫다. 스크린리더 이름도 `네이버지도 도보 길찾기`라고 실제 앱을 말한다.

### 4. 장소 정보(카드 이름·사진 탭)

- 네이버지도: `https://map.naver.com/p/search/{이름 제주}`(이름에 제주·서귀포가 있으면 그대로). 네이버 장소 id는 모으지 않는다(데이터 추가 수집 없음).
- 카카오맵: 지금 그대로 `place.map.kakao.com/{kakaoPlaceId}`, 없으면 카카오 검색.
- **TMAP: 네이버 검색**. TMAP에는 웹 장소 페이지가 없고(앱 스킴뿐), 정보 확인용 탭이 앱 미설치 오류로 끝나면 안 된다. 기본 앱과 같은 네이버로 둬서 TMAP 사용자는 「정보는 네이버, 길안내는 TMAP」이 된다.
- 카드 문구: 첫 카드 메타 끝의 `카카오맵`은 **장소 링크의 앱 이름**이 된다(`네이버지도`, `카카오맵`; TMAP이면 `네이버지도`). 카드 링크 스크린리더 이름 `{이름}, 네이버지도에서 보기`.
- 사용 기록(ADR-0061) 이벤트 이름 `map`은 그대로(「지도 앱으로 나갔다」).

### 5. 문서·검사

- 개인정보 안내·`llms.txt`: 「카카오맵 링크」 → 「외부 지도 앱 링크(네이버지도·카카오맵·TMAP)」, 링크에 지금 위치를 넣지 않는다는 문장 유지. 고른 앱은 기기에만, 백업 링크에는 기본이 아닐 때만.
- `npm run check:links`: 네이버·카카오 × 자동차·도보·배 타는 곳 × UA 5 + PC를 실제 브라우저로 따라간다. 네이버는 연결 페이지 `m.map.naver.com/appLink.naver?…`에 도착지(`elng`/`elat`/`eText`)·수단(`pathType` 0/3)이 맞고 출발지(`slat`/`slng`/`sText`)가 비었는지, PC는 그 길찾기 페이지가 200으로 열리는지. `launchApp` 이동은 보이면 출력. TMAP 3건(자동차·도보·배 타는 곳)은 `goLink`가 만드는 링크 모양을 고정(스킴은 따라갈 수 없다).
- **2026-10-01 이 환경(프록시 경유) 실행 결과**: Chromium이 프록시에서 자주 끊겨(`ERR_TOO_MANY_RETRIES`) 한 번의 실행이 25분 제한에 걸렸다. 브라우저 36건 중 앞의 12건(네이버 자동차·도보)만 돌았고 **ok 7 · STOP 5(중간 페이지에서 끊김, 네트워크) · FAIL 0**, 카카오 18건은 이번에 닿지 못했다(링크는 ADR-0069 실측 그대로). TMAP 모양 3건 ok. 같은 때 curl로 네이버 18건(자동차·도보·배 타는 곳 × UA 5 + PC)의 302 사슬을 따로 따라가 **18건 모두** 연결 페이지 `appLink.naver`(도착지·수단 맞음, 출발지 없음) / PC 200에 닿았다. 네트워크가 안정된 곳에서 다시 돌린다.
- `docs/device-check.md`: 지도 앱별 칸 추가(네이버 앱 있음/없음, TMAP 앱 있음/없음).

## Consequences

- 카드를 처음 쓰는 사람은 네이버지도로 간다. 카카오맵을 쓰던 사람은 저장한 곳 맨 아래에서 한 번 바꾸면 된다(기기에 남는다).
- 네이버 장소 정보는 검색 결과라 동명 장소가 섞일 수 있다(`이름 제주`로 좁힌다). 카카오 장소 페이지만큼 정확하지 않다. 네이버 장소 id를 모으는 것은 데이터 추가 수집이라 이번 범위 밖.
- TMAP을 고르고 앱이 없으면 `길찾기`가 iOS에서 오류 대화상자로 끝난다(안내로 미리 알림). TMAP의 웹 실행 API를 쓰려면 appKey 발급과 노출을 먼저 정해야 한다.
- 네이버 연결 페이지가 스크립트로 앱을 여는 동작이 iOS에서 막히면 웹 길찾기로 떨어진다(도착지는 남는다). 실기기 점검표로 확인한다.
- 데이터: spots.json의 「비양도」(섬 자체) 핀이 본섬 협재 쪽에 있던 것(ADR-0069 Consequences)을 카카오맵 장소 「비양도」(7920396) 33.41028, 126.22735로 옮겼다(네이버지도 장소 「비양도」 33.41040, 126.22705와 약 30m). `review/copy/corrections-02.json`(멱등 `apply-corrections.mjs`, `build-spots.mjs`가 같은 기록을 적용; `lat`·`lng`를 고칠 수 있는 필드에 더함). 이제 섬 상자 안이라 `길찾기`는 한림항 비양도행 도선대합실(`배 타는 곳까지 길찾기`)로 간다. 섬 스팟 85 → 86(비양도 5 → 6).
- ADR-0067 1-3(「카카오맵 문구는 그대로」)과 ADR-0069의 링크 모양은 카카오맵을 골랐을 때의 규칙으로 남는다.
