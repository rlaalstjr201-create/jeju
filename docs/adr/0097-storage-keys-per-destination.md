# ADR-0097: 저장소 키 — 머리말 `jeju.` 유지, 여행지별 키는 꼬리 `.busan`

Status: Accepted (2026-10-19, `plans/busan.md` 2판 ADR #6, S5에서 씀). ADR-0063(기기에만 저장)과 ADR-0087(가 본 곳 `jeju.visited`)을 개정한다. 용어는 `docs/context.md`의 **여행지**.

## Context

- 기기 저장 키는 모두 `jeju.`로 시작한다(`src/store.ts` `KEYS`). 이미 쓰는 기기에서 키 이름을 바꾸면 저장한 곳·기준이 사라지거나 옮기는 코드가 필요하다.
- 부산이 생기면 기준·동네·숙소는 여행지마다 따로여야 한다(spec 1.4: 제주 숙소가 부산 전환으로 지워지지 않는다). 저장·가 본 곳은 한 목록으로 두고 id 머리말로 여행지를 안다(spec 6).

## Decision

1. 머리말 `jeju.`는 그대로 쓴다. 새 키 `jeju.dest`(`'jeju' | 'busan'`)에 고른 여행지를 기억한다. 켠 빌드만 쓰고 읽는다.
2. 여행지에 딸린 키는 셋이다: 기준 `jeju.basis`, 동네 `jeju.region`, 숙소 `jeju.stay`. 제주는 지금 키 그대로, 부산은 꼬리 `.busan`(`jeju.basis.busan` 등). 읽기·복구는 지금 여행지의 키만 하고 다른 여행지 키는 건드리지 않는다(검토 m1). 동네·숙소 값은 그 여행지 것만 받는다(`parseRegion(v, dest)`·`parseStay(v, dest)`).
3. 나머지(저장 `jeju.saved.v2`, 가 본 곳 `jeju.visited`, 지도 앱·기록·설정, 세션 키)는 두 여행지가 같이 쓴다. id 머리말이 여행지다(`bs-` = 부산, UUID = 제주, `src/dest.ts` `destOfId`).
4. 다른 여행지 id는 지우지 않는다. 「데이터에 없는 id를 뺀다」는 그리기에서만이다. 백업 링크를 합칠 때도 지금 여행지 데이터에 없더라도 다른 여행지 id는 남긴다(검토 m2). 저장한 곳 화면 맨 아래에 다른 여행지 줄(`부산에 저장한 곳 N곳`).

## Consequences

- 꺼진 빌드와 지금 제주 기기는 키가 하나도 바뀌지 않는다(`check:jeju`의 저장소 비교 통과).
- 출시 뒤 스위치를 꺼도 저장소는 지우지 않으므로 부산 id와 `.busan` 키가 남는다. 다시 켜면 그대로 쓴다.
- 여행지가 늘면 같은 꼬리 규칙(`.<dest>`)을 쓴다.

## Amendment 1 (2026-10-30, `plans/nationwide-app.md` 6, U8): 자동 지역 키

- `jeju.dest`에 `'nation'`(자동 지역 전체)이 더해진다. 자동 지역 스위치가 켜진 빌드만 읽는다. 끈 빌드와 옛 빌드는 null로 읽어 제주로 열고, 키는 지우지 않는다(다시 켜면 그대로 쓴다, plans 13 R10).
- 여행지에 딸린 세 키는 같은 꼬리 규칙이다: `jeju.basis.nation`·`jeju.region.nation`·`jeju.stay.nation`. 동네 값은 시군구 코드(`51150`)다.
- 새 키 `jeju.sgg`: 자동 지역에서 마지막으로 쓴 시군구 코드(`/^\d{4,8}$/`). 자동 지역에서만 쓴다. 위치를 아직 못 읽었을 때 그 시군구 파일을 받고, 그 중심을 약한 출발점으로 쓴다.
- 저장 `jeju.saved.v2`·가 본 곳 `jeju.visited`는 그대로 같이 쓴다. 자동 지역 id는 `nt-<contentid>`이고 다른 여행지 id와 섞인다. 4의 「다른 여행지 id는 지우지 않는다」가 `nt-`에도 그대로다.
- 제주 기기의 키는 하나도 바뀌지 않는다(`check:jeju` 저장소 비교).

## Amendment 2 (2026-10-30, 배포 전 리뷰 최종 검토 f-1·f-4): 오늘 판 줄 자리 `jeju.row`

- 새 키 `jeju.row`: `[여행지, from, to, from, to, …]`(ms). 다음 14일 동안 오늘 판에 누를 줄(장날·노을 볼 곳·비 소식)이 서는 때를 합친 구간이다(`src/home.ts` `rowTimes`). `index.html` 첫 스크립트가 기억한 여행지(`jeju.dest`)로 열 때만 읽어, 지금이 그 구간 안이면 데이터 전에 줄 자리를 잡는다(`yc-row`). 켠 빌드만 쓰고 읽는다.
- 2의 「여행지별 키(꼬리 `.<dest>`)」와 다른 모양이다: 키는 하나이고 여행지는 값 첫 칸에 담는다. 첫 스크립트가 한 번 읽고 끝내도록 한 것이고, 첫 칸이 기억한 여행지와 다르면 자리를 잡지 않는다.
- 값은 앱이 목록과 기준에서 계산해 낸 시각뿐이다(좌표·장소 id 없음). 줄이 없으면 키를 지운다. 기준이 내 위치이면 쓰지 않고 지운다: 위치는 방문마다 새로 읽어 목록보다 늦기 쉬워, 잡은 자리를 놓았다가 줄이 다시 붙는 두 번의 이동이 된다(f-1).
- 이 기기 브라우저 저장소에만 있고 보내지 않는다(ADR-0063). 따로 지우지 않아도 14일이 지나면 저절로 맞지 않는다.

## Amendment 3 (2026-10-30, ADR-0102 Amendment 2·배포 전 리뷰 2 n-1): 강원의 마지막 시군구 `jeju.sgg.gangwon`

- 새 키 `jeju.sgg.gangwon`: 강원(검수한 곳, 시군구 여럿)에서 마지막으로 쓴 시군구 코드. `jeju.sgg`에 꼬리 규칙(`.<dest>`)을 붙인 모양이고, 자동 지역의 `jeju.sgg`는 건드리지 않는다. 시군구를 정하는 순서는 ADR-0102 Amendment 2 3.
