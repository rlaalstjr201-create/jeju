# ADR-0104: 한 점의 시군구는 시군구마다 둔 점 여럿 가운데 가장 가까운 점으로 정한다

Status: Accepted (2026-10-31, 배포 전 리뷰 4 m-1). ADR-0101의 판정 규칙(`plans/nationwide-app.md` 1.1 「가장 가까운 시군구 중심」, R3 「시군구 경계 판정 오차 — 받아들임」)과 ADR-0102 2의 「가까운 시군구 중심」을 바꾼다. 경계 다각형을 쓰지 않는다는 것, 35km·섬(`ISLANDS` 25km)·한국 테두리(`inKorea`)·제주 상자·부산 경계는 그대로다. R3을 받아들였던 기록은 지우지 않는다.

## Context

- `regionOf`(`src/nation.ts`)는 시군구마다 점 하나(그 시군구 곳 좌표의 중앙값)를 두고 가장 가까운 점의 시군구를 골랐다. 넓고 긴 군에서는 군청 소재지와 대표 관광권이 통째로 이웃 시군구로 갔다. 평창 곳 464곳 중 64.4%만 평창으로 나왔고, 유명한 곳은 28곳 중 16곳만 평창이었다. 대관령양떼목장·횡계·선자령은 강릉으로, 평창군청은 영월(자동 지역)로 갔다(리뷰 4 m-1).
- 같은 일이 전국에서 일어났다. 자동 지역 곳 26,288곳 가운데 자기 시군구로 나오는 곳은 82.1%였다.
- 판정은 시도 파일을 받기 전에 해야 한다. 판정 결과로 어느 파일을 받을지 정하기 때문이다. 그래서 「가까운 곳 k개의 다수결」은 쓸 수 없다. 그 방식은 전국 파일(gzip 약 1MB)이 모두 있어야 한다. 참고로 표본 1/10에서 재면 1-NN이 96.6%, 5-NN이 95.7%다.
- 시군구 경계 다각형은 받을 곳이 없다. 저장소에 경계 원본이 없고, 새로 받으려면 외부 데이터가 필요하다.

## Decision

1. **시군구마다 점 최대 8개.** `scripts/nation/build.mjs`가 시군구 곳 좌표로 k-평균(k = `ANCHORS` = 8)을 돌려 점을 만든다. 첫 점은 중앙값이고, 다음 점은 이미 고른 점에서 가장 먼 곳이다. 그 뒤 30번 고쳐 앉힌다. 난수가 없어 같은 입력이면 같은 바이트가 나온다. 곳이 8개 이하면 곳 좌표를 그대로 쓴다. 곳 하나만 맡은 점은 버린다. 좌표가 틀린 레코드 하나가 바다 건너 남의 시군구에 점을 만들지 않게 하려는 것이다(신안군·영광군 레코드에 충남 앞바다 좌표가 있었다).
2. **싣는 꼴.** `index.json`의 시군구 행에 `p`를 더한다. `p`는 중앙값(`lat`·`lng`, 그대로 둠)에서 떨어진 값을 0.001°(약 110m) 단위 정수로 적은 `[위도 차, 경도 차, …]`다. 앱(`parseIndex`)은 이를 점 `a`로 읽는다. `p`가 없거나 읽을 수 없으면 중앙값 하나로 판정해 예전과 같다. 차는 ±5,000(5°)까지 받는다. 신안군·옹진군처럼 섬이 1° 넘게 퍼진 군이 있기 때문이다.
3. **판정.** `nearestSgg`는 모든 시군구의 모든 점 가운데 가장 가까운 점의 시군구를 고른다(35km 안, 부산·제주 행 제외). 그 밖은 그대로다. 그 점이 없으면 `ISLANDS`, 그다음이 `inKorea`다.
   - 35km는 이제 중심이 아니라 바깥쪽 장소 가까이 있는 점에서 잰다. 그래서 시군구가 잡히는 땅이 넓어졌다(0.05° 격자에서 null → 시군구 1,115점, 시군구 → null 1점, 모두 `inKorea` 안). 휴전선 북쪽도 동해안 북쪽 끝이 38.64°에서 38.87°로 올라가 금강산(38.66, 128.10)이 자동 지역 고성군으로, 거문도·가거도 남쪽 바다가 여수시·신안군으로 잡힌다. 화면에 영토를 말하는 문구는 없고 개성 → 파주도 전부터 그랬다(배포 전 리뷰 anchors MINOR-1).
   - 화성시(41590) 중심은 화성시 효행구(41593)로 판정된다. 같은 땅에 옛 시 코드와 새 구 코드가 함께 있는 화성 약점과 같은 일이고, 자동 지역은 고른 `s.sgg`를 그대로 써서 지금 보이는 차이는 없다(MINOR-2).
4. **강원의 시군구.** `regionOf`가 검수한 곳을 돌려줄 때 어느 시군구인지도 함께 준다(`{ k:'dest', dest, sgg }`). `release.ts` `areaOfPoint`가 강원의 동네(시군구)를 이 값으로 정하고, 비 소식 격자(`state.ts` `rainArea`)도 이 값을 쓴다. 예전에는 강원 다섯 시군구의 중심 가운데 가장 가까운 것을 따로 골라서, 횡계가 강원이면서 「강릉」이 됐다.
5. `filesFor`(이웃 파일 40km)와 비 소식 격자의 시군구 중심은 그대로 중앙값을 쓴다.

## 잰 값 (오프라인, `npx tsx apps/web/scripts/nation/region-accuracy.ts`, 2026-10-31)

곳마다 그 좌표를 앱과 같은 함수로 판정해 자기 시군구로 나오는 몫을 쟀다. 네트워크와 API는 쓰지 않았다.

| | 중심 하나(전) | 점 8개(후) |
|---|---:|---:|
| 자동 지역 곳 26,288 | 82.1% | 94.8% |
| 같은 셈, 반으로 나눠 다른 반에서(홀짝 id, 점을 만든 곳과 잰 곳이 다름) | 81.7% | 92.2% |
| 강원 검수한 곳 1,650 (자기 시군구) | 83.2% | 98.1% |
| 강원 검수한 곳이 강원으로 | 89.6% | 98.7% |
| 강릉 548 / 속초 195 / 춘천 272 / 양양 171 / 평창 464 | 95.6 / 100 / 80.5 / 78.9 / 64.4% | 98.9 / 100 / 96.3 / 95.9 / 98.3% |
| 평창 유명한 곳 28 | 16 | 27 |
| 부산 곳 994 → 부산, 제주 곳 2,964 → 제주 | 100%, 100% | 100%, 100% |
| `index.json` raw / gzip(9) | 20,309 / 4,780 B | 33,916 / 10,937 B |

- k 고르기(같은 코드, k만 바꿈): k=4는 91.6%(반 나눔 89.8%)에 gzip 8,255 B, k=6은 93.4%(91.4%)에 9,665 B, k=8은 94.8%(92.2%)에 10,937 B다. 색인은 자동 지역을 쓸 때만 받는 파일이다. 시도 파일 하나(51.json gzip 124KB)에 비하면 6KB는 작다. 그래서 k=8로 정했다. 진입 번들에는 들지 않는다.
- 나빠진 곳도 있다. 전에는 맞고 지금은 틀린 곳이 517곳, 전에는 틀리고 지금은 맞는 곳이 3,851곳이다. 강화군은 100%에서 89%로 내려갔고, 정읍·나주·진도는 5~6%p 내려갔다. 점이 많은 이웃이 경계 너머까지 덮기 때문이다.
- 남는 약점이 있다. 화성시는 28%다. 데이터에 「화성시」와 새 일반구(만세구·효행구 등)가 함께 있어 같은 땅에 두 코드가 겹친다. 남양주시는 65%다. 경계 다각형 없이는 더 줄이기 어렵다.
- 대표 지점: 대관령양떼목장·횡계·선자령 강릉 → 평창, 평창군청 영월 → 평창, 남이섬 가평 → 춘천, 산정호수 철원 → 포천, 두물머리 하남 → 양평, 땅끝마을 완도 → 해남. 진부·봉평·월정사·문경새재·도담삼봉·노고단·중산리·광한루는 전과 같이 맞다. 섬 규칙 시험(독도·백령도·대청도·연평도·흑산도·홍도·가거도·거문도·어청도·여서도·추자도·마라도)과 `inKorea` 시험도 그대로 통과한다.

## Consequences

- `data/nation/index.json`만 바뀌고 시도 파일 14개는 바이트가 같다(`node scripts/nation/build.mjs`, 커밋된 입력만 읽음). 색인 버전(`__NATION_V__`)이 바뀌어 기기는 새 색인을 한 번 받는다.
- 시군구 경계 다각형이 생기면 다시 본다. 그때 이 점들은 다각형이 없는 곳의 대비책으로 남길 수 있다.
- 경계 근처에서 틀리는 일은 줄었지만 없어지지 않았다(전국 5.2%). 카드는 여전히 거리로 고르므로(R3) 틀려도 이름 줄과 목록 파일이 이웃 것일 뿐이다.
