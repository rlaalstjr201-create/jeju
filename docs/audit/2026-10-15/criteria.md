# 출시 전 점검 — 기준 (2026-10-15, 측정 전 고정)

주인 요청: 실제 사람들이 쓰기 전에 코드 꼬임·렉·버그·멱등성·라이트하우스·빌드·기능별로 고치기 쉬운 구성인지 점검.
측정·실행은 한 번씩만 한다. 결과를 보고 기준을 바꾸지 않는다.

## 1. 라이트하우스 (docs/perf/lighthouse-criteria.md와 같은 방법)
- `node docs/perf/lh.mjs docs/perf/lighthouse-2026-10-15.json https://yeochana.com` 1회(3쪽 × 3번, 중앙값). 장소 쪽 하나는 따로 1회 3번(관찰용, 비교 기준 없음).
- 통과: 성능 90·접근성 95·권장 95·SEO 100 이상, LCP ≤ 2.5s, CLS ≤ 0.1, TBT ≤ 200ms. 10-05 결과(`lighthouse-after.json`)보다 점수 2점 넘게 떨어진 항목 없음.
- 알려진 예외: 홈 권장 사항 77(네이버 애널리틱스 제3자 쿠키, ADR-0078). 이것만으로는 미달로 치지 않는다.

## 2. 렉 (운영 주소, Playwright, 휴대폰 375×812, CPU 4배 느림)
- 지역 기준 딥링크로 열어 GPS 없이 잰다. 동작마다 5번, 중앙값.
- 통과: 기분 누름 → 카드 3장 그려짐, 「다른 3곳 보기」 → 새 3장, 하트 누름 → 눌림 표시, 시트 열기 — 각각 200ms 이하(INP 「좋음」 기준).
- 「다른 3곳 보기」 30번 뒤: DOM 노드 수가 처음 결과 화면의 1.5배 이하, JS 힙 증가 5MB 이하.
- 첫 화면에서 우리 코드(제3자 스크립트 제외)의 50ms 넘는 긴 작업 0~1개.

## 3. 버그·멱등성·보안
- 찾은 것은 재현 절차(입력 → 잘못된 결과)가 있어야 한다. 추측은 「의심」으로 따로 적는다.
- 심각도: 막음(저장한 것 잃음·엉뚱한 장소/길찾기·앱 멈춤·개인정보가 나감) / 큼(흐름이 막히거나 틀린 화면) / 작음.
- 멱등성 점검 대상: 저장소 읽기-고치기-쓰기(두 탭), 이벤트 중복 집계(`shown`·`open`·`src:` 도착·beacon 재전송), `/api/events`·`/api/feedback`·`/api/rain` 같은 요청 두 번, D1 카운터 upsert, 딥링크·백업 링크가 두 번 적용(새로고침·뒤로 가기), 서비스워커 갱신 반복, 설문 두 번 보내기, 마이그레이션 재실행.
- 출시 전에 고칠 것: 「막음」과 「큼」 중 재현된 것. 고칠 때 테스트를 같이 넣는다.

## 4. 빌드·배포
- 운영 설정(`SITE_URL=https://yeochana.com`)으로 빌드가 통과하고, 분석 ID 셋·`_headers`·서비스워커·`spots.json?v=해시`·아이콘(새 로고)·sitemap·404·랜딩이 맞다.
- 운영 사이트가 마지막 배포 빌드와 같다(해시 JS·CSS 이름 대조).
- gzip JS+CSS ≤ 50KB.

## 1·2 재측정 (주인 승인 2026-10-15 「렉 고치고 다시 재봐」, 고치기 전 고정)

- 렉: 2절 미달(시트 열기 224ms, 첫 화면 긴 작업 5개)을 고친 뒤 운영에 배포하고, **같은 스크립트**로 한 번 잰다. 스크립트 `tools/perf.mjs` sha256 `85ebf85711737029578f22388a52c0e70e9f7a8ba56b8197fb1f1c890dcff0f8`(1차 측정과 같은 파일). 기준은 2절 그대로.
- 라이트하우스: 1차는 도구 오류(Windows EPERM)로 무효. `docs/perf/lh.mjs`는 그 오류 처리만 고쳤다(sha256 `6e9a30fa7ca42b46f37cefd151e8b093cb39b92c1e5d2ec9e754cc1a0731ef71`). 렉 개선 배포 뒤 1절 방법으로 한 번. 기준은 1절 그대로.
- 결과가 미달이어도 다시 재지 않는다. 남은 원인과 고칠 길을 적고 멈춘다.

## 5. 코드 구성 (기능별로 고치기 쉬운가)
- 기능 → 파일 지도. 한 기능을 고칠 때 손대는 파일 수, 가장 큰 파일·함수, 순환 의존, 안 쓰는 export.
- ADR 목록을 먼저 확인하고 이미 정한 구조를 다시 따지지 않는다. 결과는 `architecture_review.md`(워크플로 8단계 산출물)로 남기고, 출시 전에는 고치지 않는다(제안만).
