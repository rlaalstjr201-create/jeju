## B1 (큼) 숙소 링크를 카카오톡에서 열고 「브라우저로 열기」를 누르면 숙소·꼬리표가 넘어가지 않는다

- **위치**: `apps/web/src/render.ts:980-983`(`shareUrl`), `:1002`, `:1010-1011`(카카오톡 `inapp-open` 링크), `apps/web/src/app.ts:549-552`(`inappCopy`), `apps/web/src/keep.ts:120-122`(`appHome`), `apps/web/src/app.ts:491-501`(쿼리를 곧바로 지움).
- **재현**: UA에 `KAKAOTALK`가 있는 상태로 `/?stay=33.4631,126.3105&src=aewol-gh1`을 연다(첫 방문이라 인앱 안내가 뜸). 상태는 `basis: 'stay'`, 「숙소 근처」로 맞게 열린다. 그런데 안내의 「브라우저로 열기」 주소가 `kakaotalk://web/openExternal?url=http%3A%2F%2F…%2F` — 쿼리 없는 첫 화면 주소다. 인스타그램 등(복사 방식)도 복사되는 글이 `http://…/`뿐이다. 주소창에서도 이미 쿼리가 지워져 있어 카카오톡 메뉴의 「다른 브라우저로 열기」도 같다. 넘어간 브라우저(저장소가 비어 있음)는 「내 위치 근처」로 열리고 첫 기분에서 위치 권한을 묻는다.
- **왜 문제인가**: ADR-0089 2(「위치 권한을 묻지 않는다」, 기준 = 숙소)가 앱이 스스로 권하는 경로에서 깨진다. 숙소 링크의 주 통로가 카카오톡이고(ADR-0089 Context), 인앱 안내는 첫 방문마다 뜬다. 또 넘어간 손님의 기분 누름·길찾기는 `src:` 카운터에 안 잡혀, 미리 정한 판단 기준(기분 누름 ÷ 들어옴 ≥ 60%, ADR-0089 5)이 실제보다 낮게 나온다. SPEC 6.14(「넘기는 주소에는 백업 조각만」)가 ADR-0089 이전 문장이라 생긴 틈이다.
- **고칠 방향(최소)**: 넘기는 주소를 만들 때 숙소가 링크에서 온 것(`stay.source === 'link'`)이면 `?stay=<위도>,<경도>`를, 이번 세션 꼬리표가 있으면 `&src=<꼬리표>`를 붙인다(`shareUrl`과 `inappCopy`가 같은 함수를 쓰게). 넘어간 쪽은 새 세션이라 `open`이 한 번 더 셀 수 있다 — 감수할지, 표시(예: `#s=` 뒤 플래그)를 달아 도착 `open`을 건너뛸지는 주인 결정. SPEC 6.14·ADR-0089에 한 줄 더한다. 테스트: 카카오톡 UA + 숙소 링크 → `inapp-open` href와 복사 글에 `stay`·`src`가 있는지.
- **재현 여부**: 재현함(`scratchpad/audit-bugs/inapp-stay.test.ts`, 3개 통과).

## B2 (작음) 줄 카드·저장 목록의 저장된 하트가 밝은 화면에서 3:1에 못 미친다

- **위치**: `apps/web/src/style.css:300`(`.heart[aria-pressed="true"] { color: var(--accent) }`), `:332-334`(`.card.row`의 바탕이 `--fill`), SPEC 2.2 대비 표.
- **재현**: `contrast.test.ts`와 같은 계산으로 `--accent #f06400` on `--fill #f2f4f6` = **2.92:1**(기준 3, WCAG 1.4.11). 결과의 둘째·셋째 카드, 그리고 저장한 곳 화면의 모든 줄 하트가 이 짝이다. 어두운 화면은 6.82로 통과. 어두운 화면의 다른 새 짝(꼬리표·아무거나·첫 장 길찾기·면 위 보조 글자·시트 안 날짜 칸 테두리 4.14 등)은 모두 통과했다.
- **왜**: ADR-0088 전에는 줄 카드가 흰 바탕이라 3.22였다. ♥ N 칩은 같은 이유로 `--acc-ink`로 바꿨는데(표에 「`--accent`면 2.92」라고 적혀 있음) 줄 카드 하트는 빠졌다. 표에도 「저장된 하트 on `--bg`」만 있다.
- **고칠 방향**: `.card.row .heart[aria-pressed="true"] { color: var(--acc-ink); }` 한 줄(밝게 5.37 / 어둡게 9.08, 칩과 같은 값). SPEC 2.2 표에 줄을 더하고 `contrast.test.ts`에 같은 단언.
- **재현 여부**: 재현함(계산, `scratchpad/audit-bugs/contrast.mjs`).

## B3 (작음) 다른 탭에서 바꾼 「뺀 곳」을 이 탭이 모르고, 누르면 반대로 된다

- **위치**: `apps/web/src/app.ts:1034-1049`(`storage` 처리에 `jeju.visited` 없음), `apps/web/src/store.ts:517-524`(`toggleVisited`는 저장소 기준으로 뒤집음), `app.ts:738-744`.
- **재현**: 탭 A에서 결과 3장을 띄운다. 탭 B가 그중 X를 「가 봤어요」로 뺀다(같은 `localStorage`, A에 `storage` 이벤트). A의 `state.visited`는 그대로 `[]`, X의 버튼도 안 눌린 채다. A에서 X의 「가 봤어요」를 누르면 상태 줄이 「…를 다시 넣었어요.」, 저장소는 `[]` — 빼려던 곳이 도로 들어간다. A의 「다른 3곳 보기」·홈 「예:」에도 새로고침 전까지 X가 계속 나온다.
- **왜**: 하트·지도 앱·기록은 `storage` 이벤트로 맞추는데 뺀 곳만 빠졌다. 읽기-고치기-쓰기는 지키지만 화면이 낡아 「뒤집기」가 사용자 뜻과 어긋난다(점검 항목 「두 탭」).
- **고칠 방향**: `Store`에 다시 읽는 `visited()`를 두고, `storage` 처리에 `if (s.key === KEYS.visited || s.key === null) dispatch({ type: 'visited', ids: store.visited() })` 한 줄(하트와 같은 방식).
- **재현 여부**: 재현함(`scratchpad/audit-bugs/visited-twotab.test.ts`).

## B4 (작음) 「설정 · 지도 앱 · 의견」으로 들어가도 저장 목록 열기로 센다

- **위치**: `apps/web/src/app.ts:901-908`(settings → `openSaved()`), `:620-624`(`count('open', …live0, past)`).
- **재현**: 지난 날에만 저장이 있는 상태(♥ 0)에서 홈의 「설정 · 지도 앱 · 의견」을 누르면 `{"e":"open","live0":true,"past":true,…}`가 나간다.
- **왜**: `open`은 「저장 목록(♥ N)을 열 때」다(specs/saved-flow-events.md). ADR-0086이 흐름을 바꿀지 볼 지표가 바로 「♥ 0인데 지난 날이 접힌 채 목록을 연 비율」(`open:live0:past`)인데, 지도 앱을 바꾸거나 의견을 보내려고 들어온 사람까지 분자에 들어간다.
- **고칠 방향**: settings 경로에서는 `open`을 세지 않는다(`openSaved({ count: false })` 같은 인자 하나). 테스트: 설정 탭 → `open` 0건, ♥ N 탭 → 1건.
- **재현 여부**: 재현함(`scratchpad/audit-bugs/settings-open.test.ts`).

## B5 (작음) 320px에서 「뺀 곳」 목록이 가로로 넘친다

- **위치**: `apps/web/src/style.css:236`(`.visited-list li`가 flex, 이름 `span`에 `min-width: 0` 없음), `render.ts:954`.
- **재현**: 데이터에 있는 「24시얼큰시원생고기김치찌개노형점」을 뺀 뒤, 폭 320에서 설정 → 뺀 곳 → 펼치기. 이름이 줄어들지 않아(224px, `keep-all`이라 끊을 곳 없음) 「다시 넣기」 버튼 오른쪽 끝이 331px — 페이지가 가로로 11px 밀리고 버튼이 잘린다(밝게·어둡게 같음, 375에서는 없음). 스크린숏 `scratchpad/audit-bugs/visited-320.png`.
- **왜**: `overflow-wrap: break-word`는 최소 폭을 줄이지 않는다. specs/hide-visited.md S3(「320·390 가로 넘침 0」)에 어긋난다. e2e HV1은 짧은 이름으로만 재서 놓쳤다.
- **고칠 방향**: `.visited-list li > span { min-width: 0; overflow-wrap: anywhere; }` — 같은 DOM에 넣어 320에서 넘침 0을 확인했다. e2e에 긴 이름 한 곳을 넣는다.
- **재현 여부**: 재현함(`scratchpad/audit-bugs/layout.mjs`, `saved-dump.html`).

## B6 (작음) GA4가 늦게 붙어 첫 동작과 유입 꼬리표를 놓친다

- **위치**: `apps/web/src/analytics.ts:65`, `:74`, `:105`(GA4는 `load` 때 설정), `:109`(그 전 이벤트는 버림), `apps/web/src/app.ts:491-501`(쿼리를 마운트 때 지움), `apps/web/src/main.ts:66`.
- **재현**: (1) `/?utm_source=chatgpt.com`으로 열고 `load` → GA4 `config`의 `page_location`이 `http://…/`(utm 없음). (2) 랜딩의 앱 링크 `/?area=aewol&mood=walk` → 자체 기록은 `tap`·`shown`×3인데 GA4에는 이벤트 0건.
- **왜**: 모듈이 `load` 전에 돌며 쿼리를 지우고 기분까지 누른 다음에야 GA4가 설정된다. 랜딩 앱 링크(모두 `mood=` 포함)로 온 첫 `mood_tap`은 GA4에 늘 빠지고, AI 답변 링크의 `utm_source`도 사라진다. 자체 기록은 맞다. (참고: 쿼리를 지운 덕에 `stay=` 좌표가 GA4로 가지 않는 것은 지켜야 한다.)
- **고칠 방향**: 모듈 시작 때 `utm_*`만 따로 읽어 `page_location`에 붙이고(`stay`·`src`는 절대 넣지 않음), `add()` 전 이벤트는 버리지 말고 쌓아 두었다가 보낸다. 측정 문제라 출시를 막지는 않는다.
- **재현 여부**: 재현함(`scratchpad/audit-bugs/utm.test.ts`, `ga-early.test.ts`).

## 의심 (재현 못 함, 확인 방법만)

- **S1. 서비스워커 갱신 새로고침이 백업 합치기 물음을 지운다.** `main.ts:80-83`의 `idle()`은 첫 화면·시트 없음·로딩 아님만 본다. 백업 링크로 연 직후 `#s=`는 이미 주소에서 지워졌고 물음은 메모리에만 있어서, 그때 새 서비스워커가 넘어오면(예전 워커 + 느린 망으로 예전 셸을 받은 경우) 새로고침과 함께 물음이 사라진다. 고칠 방향: `idle()`에 `!s.keep.restore` 조건. 실기기에서 배포 직후 느린 망으로 백업 링크를 열어 확인.
- **S2. 메신저가 숙소 링크를 쉼표에서 끊거나 끝 문장부호를 붙이면 조용히 버려진다.** `deeplink.ts:52-58`은 `stay`에 쉼표를, `src`에 `[a-z0-9-]`만 받는다. 카카오톡·문자 앱이 `33.4631,`에서 링크를 끊거나 문장 끝 `.`을 링크에 넣으면 `stay`/`src`가 버려져 일반 첫 화면이 된다(오류 없음). `docs/partner/qr-card.html`이 만든 링크를 본인 카카오톡·문자로 보내 눌러 보면 바로 확인된다.

## 멱등성 점검 결과 (criteria 3절 대상)

- 저장소 읽기-고치기-쓰기(두 탭): 하트·백업 합치기·설문 기록은 맞다. 뺀 곳은 B3.
- 이벤트 중복: `shown`은 같은 3장·복원·새로고침에서 다시 안 센다. `src:` 도착 `open`은 세션당 1회, 새로고침·뒤로 가기에서 다시 안 센다. beacon은 묶음당 한 번, 재전송 없음. `open`의 다른 오염은 B4.
- `/api/feedback` 두 번: 400ms 가드 + `feedbackSent`로 한 번. 시트를 닫았다 다시 열면 새 답(설계대로). `/api/rain`: 한 번에 하나, 30분 재사용. 숙소 링크로 기준이 바뀌는 첫 마운트에서 옛 동네로 한 번 더 묻는 것은 답이 버려질 뿐 화면 영향 없음.
- D1 카운터: `ON CONFLICT … n = n + excluded.n`, 묶음 안에서 먼저 합산. 중간 실패 시 일부만 오르지만 클라이언트가 재전송하지 않아 두 번 세지 않는다(서버 쪽은 훑어만 봄).
- 딥링크·백업 링크 두 번 적용: 쿼리·`#s=`를 마운트 때 지우고 「첫 화면 항목일 때만」 적용 — 새로고침·뒤로·앞으로 모두 다시 적용 안 됨(기존 테스트로도 확인).
- 서비스워커 갱신 반복: `controllerchange`는 새 워커당 한 번, 새 코드면 새로고침 안 함 — 반복 없음. 남는 것은 S1.
- 마이그레이션 재실행: v1→v2 저장 목록은 v2 키가 없을 때만, 지역·숙소 옛 값 고쳐 쓰기는 다시 해도 같은 값.

## 확인했지만 문제 없던 흐름

뒤로/앞으로·새로고침의 화면·시트 복원(시트 항목 소비, 결과·저장 목록 복원, 앞으로 가기로 옛 결과·`다른 날로` 항목), 데이터 실패·오프라인·늦게 온 목록, 한국 시간 자정 넘김(날짜 줄·지금으로 되돌림·지난 날·노을 타이머), 저장소 막힘·용량 초과(메모리로 이어 감), 빈 결과, 데이터에서 사라진 id(♥ N·저장 목록·세션 복원·백업), 기분·탭 빠른 연타와 늦은 응답(요청 id), 딥링크 + 백업 링크 함께, GPS 거절·지연·제주 밖, 시트 포커스 가둠·되돌림, 320px의 결과·홈·기준 시트(넘침 0), 어두운 화면 대비, 날짜 모드에서 카드 순서가 다음 뽑기부터 바뀌는 것(specs/date-mode.md 3, 설계대로).
