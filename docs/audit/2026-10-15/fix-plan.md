# 출시 전 고칠 것 (2026-10-15)

근거: `bugs.md`(B·S), `idempotency-security.md`(K·S·Q), 기준 `criteria.md` 3절(「막음·큼」 중 재현된 것은 반드시). 숙소 시범 숫자를 틀리게 만들 수 있는 것과, 오늘 바꾼 것에서 생긴 작은 퇴행도 함께 고친다. 고칠 때마다 테스트를 넣는다.

## 반드시 (큼, 재현됨)
- **F1 (B1)** 인앱 안내의 「브라우저로 열기」·복사 주소가 숙소 링크를 이어 준다: 숙소가 링크에서 왔으면(`stay.source === 'link'`) `?stay=<위도>%2C<경도>`, 이번 방문 꼬리표가 있으면 `&src=<꼬리표>`, 그리고 `&relay=1`. `relay=1`로 들어온 방문은 꼬리표를 이어받되 도착 `open`을 다시 세지 않는다(같은 사람이 두 번 세지지 않게). 백업 조각(`#s=`)은 지금처럼 뒤에. SPEC 6.14·ADR-0089에 한 줄. 카카오톡 자체 메뉴 「다른 브라우저로 열기」는 주소창 주소를 쓰므로 여전히 이어지지 않는다(남는 한계로 기록).
- **F2 (K1)** 백업 「합치기」는 이 기기의 저장을 밀어내지 않는다. 합친 뒤 500을 넘으면 링크 쪽을 덜 넣고, 못 넣은 수를 알린다(문구는 기존 합치기 안내 방식, check:slop 통과).
- **F3 (K2)** 개인정보 안내의 GA4 문단과 자체 기록 목록을 코드와 맞춘다(GA4: 카드 보임·저장 목록 열기·정리, 세부 종류·다른 날 여부·철·저장한 지 며칠·지난 날 여부·정리 종류 / 자체: 실내만·철). `GA_NAME`·`gaParams`가 내보내는 키를 고정하는 테스트(늘면 안내도 같이 고치게). 적용 날짜를 2026년 10월 15일로.
- **F4 (K3)** 「문의」의 비공개 저장소 링크(방문자에게 404)를 앱의 「의견 보내기」 안내로 바꾼다. deploy 테스트에 「privacy에 비공개 저장소 링크 없음」. (공개 메일 주소는 주인 결정 대기)

## 시범 숫자를 지키려고
- **F5 (Q1)** 길찾기·예약 링크를 센 직후 기록을 바로 보내고(`flush`), `pagehide`에서도 보낸다. 줄을 비우고 보내므로 두 번 가지 않는다.
- **F6 (B4)** 홈 「설정 · 지도 앱 · 의견」으로 들어온 것은 저장 목록 `open`으로 세지 않는다.
- **F7 (idem S1)** 수집기는 `d`가 서버의 제주 날짜 ±1일 밖이면 400. `countSince`에 위쪽 경계.
- **F8 (B3)** `jeju.visited`도 `storage` 이벤트로 다른 탭과 맞춘다.

## 오늘 바꾼 것의 퇴행·작은 것
- **F9 (B2)** 회색 면 위 저장된 하트(줄 카드·저장 목록) 대비 ≥ 3: `--acc-ink`. SPEC 2.2 표·대비 테스트.
- **F10 (B5)** 「뺀 곳」 목록 긴 이름이 320에서 넘치지 않게(`min-width: 0`, `overflow-wrap: anywhere`). e2e에 긴 이름.
- **F11 (idem S3)** `/api/events`는 길이 머리가 없으면 411, 8KB까지만 읽는다(`/api/feedback`과 같게).
- **F12 (idem S4·bugs S1)** 서비스워커 갱신 새로고침은 의견 시트에 글이 있거나 백업 합치기 물음이 떠 있으면 미룬다.
- **F13 (idem S6)** GA4 `page_location`에서 쿼리를 직접 뺀다(실행 순서에 기대지 않게).
- **F14 (idem S7)** `_headers`에 `/*` — `X-Frame-Options: DENY`, `Permissions-Policy: camera=(), microphone=(), payment=()`만(Cache-Control은 넣지 않음). deploy.md·deploy 테스트.
- **F15 (bugs S2)** 숙소 링크의 쉼표를 `%2C`로 만든다(`docs/partner/qr-card.html`). 앱이 `%2C`를 읽는 테스트.
- **F16** `docs/adr/README.md`에 0086~0089.
