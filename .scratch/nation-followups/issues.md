# 자동 지역 배포 전 리뷰 — 남은 것 (2026-10-30)

Status: needs-triage

출처: `apps/web/review/nation/predeploy-review.md`(배포 전 독립 리뷰, ADR-0058). M-1·m-1·m-2·m-3·m-7과 전북 이름 NIT는 고쳤다. 아래는 적어 두기만 한 것이다. 줄 번호는 리뷰 당시(HEAD d975cbbc) 기준.

## m-4 다른 시도에 저장한 자동 지역 장소가 저장 목록에서 사라져 보임 (데이터는 남음)

- 위치: `src/state.ts` 저장 목록(로드한 목록에 없는 id는 숨김), `src/render.ts` 다른 여행지 줄(`DESTS` = 제주·부산만).
- 재현: 강릉에서 3곳 저장 → GPS로 경주로(목록 = 47 파일+이웃) → ♥ 0, 목록 비어 보임. 제주·부산 화면에도 「다른 곳에 저장한 곳 N곳」 줄이 없다.
- 고칠 길: 저장 항목에 시군구를 같이 두거나, 최소한 `nt-` 저장 수를 「다른 곳에 저장한 곳 N곳」으로 보이고 누르면 그 장소의 파일을 받는다.

## m-5 한국 안·제주 부산 밖의 숙소 링크(`?stay=`)가 제주로, 숙소 없이 열림

- 위치: `index.html` 인라인(제주 상자 밖 stay는 모두 `d='busan'`), `src/main.ts` `nationFirst`, `src/deeplink.ts`(`releasedDestOf` null이면 stay 버림), `src/app.ts`.
- `plans/nationwide-app.md` 125줄(「`?stay=`가 한국 안·검수한 곳 밖이면 자동 지역 숙소」)이 구현되지 않았다. 회귀는 아님.
- 같은 인라인의 제주 상자(33–33.7)에는 이번에 `inJeju`에 더한 추자도가 없다: 추자도 숙소 링크도 부산 몫을 먼저 받는다(열리는 곳은 앱이 다시 가린다).
- 고칠 길: `nationFirst` 조건에 「stay 링크가 있고 부산 안이 아님」을 더하거나, 부산 몫이 들어온 뒤 stay가 부산 밖이면 `loadNation()`을 기다린 뒤 `readDeepLink`.

## m-6 GPS로 시군구 경계를 넘을 때마다 순환이 처음부터

- 위치: `src/app.ts` `followGps`(같은 nation이라도 sgg가 다르면 `switchDest`), `src/state.ts` dest 액션(`histories`·`shown`·`cards` 비움).
- 서울은 구 중심이 3–5km 간격이라 걸으며 「더 보기」를 누르면 구가 바뀌고 본 카드가 다시 나온다. 제목 「여차나:서울 종로」↔「서울 중구」도 깜박인다.
- 고칠 길: 같은 시도(또는 같은 `filesFor` 집합) 안의 이동이면 sgg만 바꾸고 `histories`·`shown`은 남긴다.

## f-3 느린 망에서 10초 뒤 「지금 여기서」 카드를 숨겼다가 다시 넣어 크게 밀림; `online`이 목록을 다시 묻지 않음

- 출처: 같은 리뷰의 「최종 검토」(HEAD f1454815). 위치: `src/app.ts` `warm`(165–170), `src/data.ts` `get()`의 timeout, `src/app.ts` `online` 처리(1281 무렵).
- 10초 timeout은 기다림이 끝났을 뿐 내려받기는 계속된다. 느린 망에서는 진짜 실패가 아닌데 `listFailed`가 서서 빈 상자가 빠지고, 나중에 onLoad로 약 129px 카드가 기분 칸 위에 다시 들어온다(커밋의 측정 CLS 0.2235). 영구히 숨지는 않는다.
- 오프라인 실패 뒤 `online` 이벤트는 `retryFailedLoad`만 부르고 목록을 다시 묻지 않아, 기분을 누르기 전까지 「지금 여기서」·장날 줄 없이 머문다(전에는 빈 회색 상자로 머묾 — 나빠지진 않음).
- 고칠 길: 실패(reject)와 timeout을 나눠 timeout이면 빈 상자를 두고 진짜 실패에만 숨긴다. `online`에서 `listFailed`이고 목록이 없으면 `warm()`도 부른다. 지금 동작이 의도한 맞바꿈이라면 그대로 두고 그렇게 적는다.

## NIT

- `index.html` 인라인: `dest=`가 아무 `[a-z]{2,10}`나 받아 `?dest=foo`면 시작 화면 없이 제주로 연다(앱 쪽 `isDest`가 걸러 안전하지만 시작 화면은 건너뜀).
- 부산 몫 청크만 실패하고 자동 지역 몫은 성공하면 부산 안 점이 `regionOf`에서 `dest: busan` → `sggOf` null → `releasedDestOf` null. 이제 문구는 「이 근처는 아직 장소 자료가 없어요」(자동 지역)나 「부산 밖」(부산)이 되지만, 부산 안에서 부산을 못 쓰는 것은 그대로. 드묾.
- `nationFirst`가 첫 방문마다 앱 마운트 전에 index(4.9KB gz)+청크를 최대 4초 기다린다. 라이트하우스 첫 방문 LCP 3.6→4.7초에 일부 보탤 수 있다(재지 않음).
- 개성(북한) 점은 파주시로 판정(해 없음). 백령도 섬 점 25km 안에 북한 옹진반도 해안 일부가 들어 옹진군이 될 수 있음(같은 종류, 해 없음).
- 서울 시군구 하나에 11+41+28 파일 ≈ 380KB gzip, 원본 2.6MB JSON 파싱+정규화가 중저가 폰에서 긴 작업이 될 수 있음.
- SW precache가 `nation-part-*.js`·`busan-*.js`를 제주 기기에도 받는다(기존 부산 몫과 같은 구조).
- 섬 판정: 여수시의 초도·손죽도는 가장 가까운 중심이 고흥군이라 고흥군이 된다(한국 밖은 아님). 시군구별 반경(그 시군구 레코드의 가장 먼 거리)을 index에 넣으면 섬 점 목록(`ISLANDS`) 없이 풀린다 — index를 다시 만들어야 해서 이번에는 하지 않음.
- 중국어 시도 이름: 전북만 全北特别自治道로 바꿨다. 京畿·江原(짧은 이름)과 忠清北道(긴 이름)가 섞인 것은 그대로(일본어는 道를 모두 정식 이름으로 맞춤).
- 비 소식 `?grid=` 허용 칸은 `functions/_lib/grids.ts`가 `data/nation/index.json`을 함수 번들에 넣어 시작할 때 만든다(239곳). index가 바뀌면 같이 바뀐다.
