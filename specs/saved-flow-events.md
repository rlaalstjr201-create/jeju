# Light Spec: 저장 목록 흐름 기록

근거: ADR-0085(이 스펙과 함께 발행), ADR-0061·ADR-0078(사용 기록), `docs/research/p-persona-sim-02/00-design.md` 4단계·0-8, `docs/research/p-persona-sim-01/40-report.md` 「실제 데이터로 먼저 확인할 것」.

## 왜

날짜·저장 흐름을 바꿀지(1차 시뮬레이션 제안 B)는 실제 사용자 기록으로 확인하기로 했다(2026-10-09 주인 결정: 사람 모집 시험 대신, 업데이트 배포 뒤 실제 사용자의 GA4·자체 기록으로 본다). 그런데 지금 기록으로는 핵심 질문 셋 중 하나만 답할 수 있다.

| 질문 | 지금 기록 | 빠진 것 |
|---|---|---|
| Q1 날짜를 고른 상태에서 하트를 누르는 비율 | GA4 `place_save`의 `dated`로 됨. 자체 기록(D1)엔 안 남음 | D1 쪽 |
| Q2 담아 둔 곳을 다음 날 다시 꺼내 쓰나, 「지난 날」로 접힌 게 끊는가 | 안 됨 | 저장 목록 열기, 목록에서 연 길찾기, 담은 지 며칠, 접힌 줄이었나 |
| Q3 위로/아래로/다른 날로/펼치기를 쓰나 | 안 됨 | 저장 목록 정리 동작 |

이 스펙은 이 빈칸만 채운다. 지금 흐름(날짜 먼저)에서도, 나중 흐름(B)에서도 같은 질문을 같은 항목으로 잴 수 있게 한다.

## 지키는 것 (바뀌지 않음)

- **시각은 보내지 않는다.** 개인정보 안내의 「기록에는 시각이나 기기 번호를 넣지 않아요」를 그대로 지킨다. 밤·낮 구분도 보내지 않는다. 「며칠 지났나」는 날짜끼리의 차이(0·1·2 이상)로만 보낸다.
- 좌표·기기 번호·사람을 잇는 번호 없음. 서로 다른 날의 행동을 한 사람으로 묶지 않는다(기기 안에서 계산한 값만 보냄).
- 기록 끄기가 이것도 끈다. 오프라인이면 버린다. 앱 동작은 기록에 기대지 않는다.

## 기기 안에만 두는 것

- 저장 항목(`SavedEntry`)에 **담은 날** `at: Day`를 더한다(지금은 「어느 날에 둘지」 `date`만 있다). 기기 저장소에만 있고 보내지 않는다.
- 백업 링크(`keep.ts`) 형식은 바꾸지 않는다. 백업에서 되살린 항목과 이 기능 전에 담은 항목은 `at`이 없다 → 그 항목에서 난 이벤트는 `age`를 빼고 보낸다(추측해 채우지 않는다).

## 이벤트 (ADR-0061 형식에 더함)

| 이벤트 | 언제 | 더하는 필드 |
|---|---|---|
| `open` (새) | 저장 목록(♥ N)을 열 때. 같은 화면에서 다시 그려질 때는 다시 안 셈. 홈 「설정 · 지도 앱 · 의견」으로 같은 화면에 온 것은 세지 않음(설정하러 온 것, 2026-10-15 출시 전 점검 F6) | `live0: true`(♥ 숫자가 0일 때만), `past: true`(접힌 「지난 날」 줄이 있을 때만) |
| `map` (있음) | 길찾기를 열 때 | 저장 목록에서 열었으면 `from: 'saved'`. 그때만 `age: 0｜1｜2`(그 줄을 담은 날부터 오늘까지 날 수, 2는 2일 이상), `past: true`(그 줄이 「지난 날」 묶음에 있었으면) |
| `arrange` (새) | 저장 목록에서 정리 동작을 할 때 | `op: 'up'｜'down'｜'move'｜'past'`(past = 지난 날 펼치기/접기). `id` 없음 |
| `save` (있음) | 그대로 | 바뀌지 않음(`dated` 이미 있음) |

- `from`이 없으면 지금처럼 카드에서 연 것이다(기존 기록과 호환).
- `open`·`arrange`에는 장소 `id`가 없다(`tap`처럼). 그 밖의 맥락 필드(`range`·`basis`·`dated`·`d`)는 지금 규칙대로 붙는다.
- B 흐름이 들어오면 `arrange.op`에 「날짜에 두기」 값을 더한다(그때 스펙에서).

## 받는 쪽 (D1 `yeogwi-events`, 표 구조 그대로)

카운터 열쇠는 지금처럼 `(날짜, id, 이벤트)`다. 장소가 없는 이벤트는 `tap`이 `mood:walk`를 쓰듯 **값을 이은 고정 문자열**을 id 자리에 넣는다.

- `open` → id `open` + 붙은 값(`live0`, `past`)을 정해진 순서로: 예 `open:live0:past`
- `arrange` → id `arrange:<op>`
- `map` + `from: 'saved'` → 기존 장소 카운터(장소 id × `map`)는 그대로 올리고, 덧붙여 id `saved:a<age, 없으면 x>:<past면 p, 아니면 ->`(예 `saved:a1:p`, `saved:ax:-`)를 이벤트 `map`으로 한 번 더 올린다.
- `save` → 기존 장소 카운터 그대로, 덧붙여 id `save:dated` 또는 `save:now`를 이벤트 `save`로(Q1을 D1에서도 보게).
- 검사(`events/validate.ts`): 새 필드는 위 표의 이벤트에만, 값은 위 목록만. 그 밖은 묶음 전체를 거부한다(지금 원칙). 시각처럼 보이는 문자열은 어느 필드에도 들어갈 수 없다.
- 덧붙인 카운터 id 목록은 고정이다(`saved:a0:-` … `arrange:past` 등 열 몇 개). 집계 보고서가 장소 이름표와 섞지 않게 접두어(`open`·`arrange:`·`saved:`·`save:`)로 가른다.

## GA4

- `map_open`에 `from`·`age`·`past`, 새 이벤트 `saved_open`(`live0`·`past`), `saved_arrange`(`op`).
- 이 매개변수들과 기존 `dated`는 GA4 「맞춤 측정기준(이벤트 범위)」으로 등록해야 보고서에 나온다 — **주인 몫**(GA4 관리 화면). 기존 `season` 등록 오타 문제와 같이 처리.

## 보고서 (`npm run analytics:report`)

지금 보고서에 「저장 목록 흐름」 절을 더한다. 7일·28일 각각:

- Q1 `save:dated` / (`save:dated` + `save:now`)
- Q2-a 저장 목록 열기 중 `live0`이면서 `past`인 비율(♥ 0인데 접힌 게 있는 상태로 연 비율)
- Q2-b 목록에서 연 길찾기의 `age` 분포(0·1·2+·모름)와 그중 `past` 비율
- Q2-c 다음 날 이어짐 근사: (목록에서 연 길찾기 중 age ≥ 1) / (`save` 전체) — 사람 단위가 아니라 전체 비율이라 근사임을 같이 적는다
- Q3 `arrange` op별 횟수와 `open` 대비 비율
- 표본이 작으면(열기 30회 미만 등) 「참고만」이라고 쓴다. 0은 0으로, 기록이 없는 기간은 「데이터 없음」으로(없음을 0으로 바꾸지 않음).

## 개인정보 안내 (`public/privacy.html`)

보내는 항목 목록에 한 줄: 「저장 목록을 열었는지, 저장한 곳을 며칠 뒤에 열었는지(날 수만), 목록을 정리했는지」. 「시각이나 기기 번호를 넣지 않아요」는 그대로 둔다.

## 성공 기준

- F1 검사: 새 필드가 표의 이벤트에만·정해진 값으로만 통과하고, 다른 이벤트에 붙거나 값이 틀리면 묶음이 거부된다(단위 테스트). 시각 문자열(`"21:30"`, ISO 시각)은 어느 필드로도 통과하지 못한다.
- F2 앱: 저장 목록 열기 1회 → `open` 1건(다시 그리기로 늘지 않음). `♥ 0`+접힌 줄 상태에서 열면 `live0`·`past`가 붙는다(단위 + e2e).
- F3 앱: 목록에서 길찾기 → `map`에 `from: 'saved'`, 그 줄의 `age`·`past`가 맞다. 카드에서 연 길찾기에는 `from`이 없다(단위).
- F4 날 수: 어제 담은 항목은 오늘 `age` 1, 사흘 전은 2, `at` 없는 항목은 `age` 없음. 날짜 경계는 앱의 제주 날짜(`dayOf`)를 따른다(단위, 시계 주입).
- F5 `at`은 기기 저장소에만 있고 보내는 이벤트·백업 링크 어디에도 없다(단위). 예전 저장 목록·백업을 읽어도 깨지지 않는다.
- F6 기록 끄기면 새 이벤트도 0건(e2e, 기존 U3 확장).
- F7 D1: 덧붙인 카운터가 표대로 올라가고 기존 장소 카운터 수는 그대로(핸들러 단위 테스트).
- F8 GA4: `gaParams`가 새 매개변수를 넘기고 위치·날짜·지역 이름은 여전히 안 넘긴다(단위).
- F9 보고서: 고정 입력으로 Q1~Q3 표가 기대대로 나오고, 작은 표본·데이터 없음 문구가 맞다(단위).
- F10 기존 단위·e2e·`check:slop`·번들 예산 통과. 배포 뒤 smoke와 `/api/events` 204 그대로.

## 범위 밖

- 흐름 변경(B) 자체, 하트·저장 목록 화면 변경 — 이 스펙은 기록만 더한다.
- 사람 단위 추적, 세션 번호, 시각대.
- GA4 맞춤 측정기준 등록(주인 몫, 위).
