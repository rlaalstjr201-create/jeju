# Light Spec — 지금 주변 문화생활 (now-culture)

상태: 초안 (2026-11-04). 근거: `docs/research/trend-seoul-01`~`06`(팝업 재현율 61.3%·정밀도 96.8%에 닿은 수집·검수 방식),
맞대결 01·02(범용 AI에 진 이유가 「지금·여기」 정보), 주인 요청(2026-11-04): 「여러 문화 생활도 포함하는건데 예를 들어 뮤지컬이라던가 단순한 공연이라던가」.

## 1. 무엇을 하나

여행자가 지금 있는 곳 근처에서 **오늘·이번 주에 하는 문화생활**을 보여 준다. 장소 카드(상설)와 다른 층이다: 기간이 있고, 끝나면 사라진다.

세 갈래:

| 갈래 | 예 | 출처 | 갱신 |
|---|---|---|---|
| 공연 | 뮤지컬·연극·콘서트·클래식·무용·국악 | KOPIS 공연예술통합전산망 API | 매일 자동 |
| 전시·행사 | 전시·축제·무료 공연·강좌 | 서울시 문화행사 API, TourAPI 행사(필요 시 한국문화정보원 공연전시 API) | 매일 자동 |
| 팝업·비정형 | 팝업스토어·플리마켓·야시장·버스킹·클래스 | 네이버 블로그·뉴스, 유튜브(무료 한도) → 규칙 후보 → **주 1회 AI 검수** | 수집 매일, 검수 주 1회 |

## 2. 범위 (첫 판)

- 서울만. 그중 팝업·비정형은 성수·홍대부터(검증된 곳). 공연·전시·행사는 서울 전 구(공식 자료라 지역 제한이 필요 없음).
- 유료 외부 AI API는 쓰지 않는다(주인 조건). 검수는 Claude Code 예약 작업(구독 사용량)으로 한다.

## 3. 화면 (모바일 375px 기준)

- 홈에 「오늘 근처에서 하는 것」 줄 하나: 가장 가까운 2~3개. 예: 「뮤지컬 ○○ · 오늘 19:30 · 걸어서 10분」, 「○○ 팝업 · 11/16까지 · 차로 5분」.
- 누르면 목록(가까운 순, 오늘 끝나는 것 먼저 표시), 각 줄에 기간·시각·출처 링크(예매·공지)와 길찾기.
- 지금 끝났거나 아직 안 연 것은 보이지 않는다(ADR-0111과 같은 원칙).

## 4. 데이터 흐름

- 서버(예약 작업)가 구마다 `culture/<구 코드>.json`을 만든다: 공연·전시·행사(매일), 팝업(주 1회 검수 결과).
- 앱은 **지금 있는 구(와 이웃 구)의 파일만** 받는다. 장소 데이터처럼 전부 받지 않는다.
- 각 항목: 이름·갈래·장소 이름·좌표·시작일·종료일·(공연이면) 오늘 회차 시각·링크·출처.

## 5. 개인정보

- 구 파일을 요청하면 「어느 구에 있는지」가 서버 접속 기록에 남는다. 개인정보 안내에 적어야 한다(지금 안내는 시도 파일만 적음).
- 좌표는 보내지 않는다(구 코드만).

## 6. 성공 기준

- 다른 날짜(다음 주)로 재측정: 팝업 재현율 60% 이상, 정밀도 70% 이상(트렌드 06과 같은 방식, 새 기준 목록).
- 공연: KOPIS 자료와 앱 목록이 그날 서울 공연 표본 20개에서 일치(기간·공연장).
- 화면: 375px에서 홈 줄 1개, 목록은 한 손으로 넘김.

## 7. 열린 질문

- OQ1 이름: 이 층을 무엇이라 부를지(「오늘 근처에서 하는 것」 가안). context.md에 용어로 올린다.
- OQ2 KOPIS 키(주인 신청 중). 한국문화정보원 API를 추가로 쓸지.
- OQ3 기분 버튼과의 관계: 별도 줄로 둘지, 「놀러 가고 싶어」 안에 섞을지.
- OQ4 팝업 검수 예약 작업의 실행 주기·비용(구독 사용량) 측정.
- OQ5 제주·부산으로 넓히기(공연·전시는 공식 자료라 쉬움).
