# Light Spec: 정적 랜딩 — P를 위한 제주 무계획 여행 + 장소 페이지

상태: **결정됨(2026-10-01)** — Open Question 6개를 사용자가 정했다. 결정 기록 `docs/adr/0072-static-landing-and-place-pages.md`, 구현 계획 `plans/seo-landing.md`.
근거: `docs/seo/audit-01.md` (b), `docs/seo/keyword-research-01.md`, `docs/research/competitors-01.md` 4(a) #1·#2·#3, `.claude/agents/seo-analyst.md` §0·§2·§5.

## 왜

앱은 JS가 `spots.json`을 읽어 카드를 그린다. 빌드 결과에는 HTML이 홈·개인정보 안내 2장뿐이고 홈의 정적 본문은 161자였다(`npm run seo:crawl`).
그래서 검색어가 도착할 페이지가 없고, JS를 실행하지 않는 AI 크롤러(OAI-SearchBot·PerplexityBot·ClaudeBot 등)는 P의 여행이 무엇이고 어떤 곳을 고르는지 읽을 수 없다.
경쟁 조사(competitors-01 (a)#1)에서 오늘제주의 주 유입 경로가 장소별 정적 페이지였고, seoulist에서도 이긴 층은 개별 장소 쪽이었다(`docs/seo/seoulist-postmortem.md` 3절: 상세 446쪽 중 79% 노출). 그래서 허브·지역에 더해 **장소 페이지**를 만든다.

기분 슬러그: rest · walk · new · food (화면 이름과 1:1, `docs/context.md`).

## 장소 주소

- `/jeju/<지역 슬러그>/<장소 슬러그>/`. 지역은 앱과 같은 `nearestArea`(가장 가까운 지역 중심).
- 장소 슬러그는 이름을 로마자로(국어의 로마자 표기법 글자 대응 + 연음·ㄹㄹ만, 정확한 발음 표기가 아니라 읽히는 주소), 단어는 `-`, 영문·숫자는 그대로, 60자 안. 예: 「버거307 협재점」 → `beogeo-307-hyeopjaejeom`.
- **한글 경로는 쓰지 않는다**: 카카오톡·메신저로 공유하면 `%ED%98%91…`로 깨져 보인다(OQ5와 같은 이유).
- **안정**: `data/landing/slugs.json`(id → 슬러그·첫 지역)에 한 번 적은 주소는 바뀌지 않는다(이름을 고쳐도). 겹치면 `-2`, `-3`, 기분 슬러그(`rest`·`walk`·`new`·`food`·`any`)는 쓰지 않는다. 장소가 빠져도 그 슬러그는 다시 주지 않는다. 새 장소는 `npm run landing:slugs`로 주소를 받고 커밋한다 — 주소가 없는 장소가 있으면 빌드가 멈춘다.
- 장소가 다른 지역으로 옮겨지면(좌표 정정) 첫 주소 → 새 주소 301을 `dist/_redirects`에 쓴다.

## 페이지 내용

**허브 `/jeju/`**
- 첫 문단 = 엔티티 한 줄 정의(해요체). 이어서: 일정·코스를 짜 주지 않는다 · 지금 있는 곳과 기분 하나로 3곳 · 이동 시간·범위로 고른다.
- 기분 5개(화면 이름 그대로) + 한 줄 뜻.
- 세부 지역 15곳 링크 — 이름 + 대표 지명(「조천(함덕)」) + 장소 수. 조합 페이지 링크.
- 「앱에서 지금 3곳 보기」 → `/`(ADR-0090 7: 「받기」는 앱 설치로 읽혀 「보기」로).

**지역 `/jeju/<지역>/`**
- title: `{지역}({대표 지명}) 근처, 지금 갈 만한 곳 · 여행계획짜기 귀찮아:제주`(대표 지명이 장소 이름이 아닌 신제주「공항 근처」·우도「배로 가는 섬」은 이름만).
- h1: `{지역} 근처에서 지금 뭐 할까`. 첫 문단: 그 지역 한 문장(우리가 쓴 문장, `scripts/landing.ts` AREA_LINE) + 「기분 하나만 고르면 근처 3곳」. 「순서는 지역 중심 기준, 앱은 지금 있는 곳에서 다시 고른다」.
- 기분별 절 4개(쉬기·걷기·새로운 거·먹기[식사·카페 합쳐서]): 만족도 점수 → 지역 중심 거리 → id 순 상위 **5곳**, 각 사진·이름(장소 페이지 링크)·이유·「구경 · 실내 · 장날 2·7일 · 애월 중심에서 차로 약 N분」, 절마다 딥링크.
- 「비 오는 날, {지역} 실내」 절(ADR-0065, `docs/seo/2026-10-16-generic-search.md` a1): 실내(`indoor`)인 쉬기·새로운 거(식사·카페 제외)를 기분 절과 같은 정렬로 상위 **5곳**, 그 동네 실내 곳 수, 딥링크 `/?area=<지역>&indoor=1`. 그런 곳이 **10곳 미만인 동네는 절을 그리지 않는다**(지금 우도). 절이 있으면 description 끝이 「…먹기마다, 비 오는 날 실내까지 먼저 갈 만한 곳을 모았어요.」. 새 쪽은 만들지 않는다.
- 그 지역 전체 장소 이름 목록(기분별), 이웃 지역 3곳(중심 거리 순), 허브 링크.

**장소 `/jeju/<지역>/<장소>/`**
- title `{이름}, {지역}({대표 지명}) 근처 {식사|카페·디저트|구경|체험|걸을 곳|쉬어 갈 곳} · 여행계획짜기 귀찮아:제주`, h1 이름.
- 사진(핫링크, OQ2) + 「사진: 비짓제주(제주관광공사)」, 우리 이유 문장.
- 사실: 동네(지역 링크, 지역 중심에서 이동 시간), 기분(화면 이름 + 하위 탭), 비 오는 날(실내 여부, ADR-0065), 오일장 장날(ADR-0066, 있을 때), 섬이면 배 타는 곳(ADR-0069).
- 기본 지도 앱(네이버지도, ADR-0071) 길찾기(`goLink`, 출발지 없음, 섬이면 배 타는 곳까지)와 장소 검색 링크.
- 「앱에서 근처 3곳 보기」(ADR-0090 7) → `/?area=<지역>&mood=<기분>`.
- 가까운 곳: 같은 지역에서 가장 가까운 **5곳**(이름·종류·「걸어서 약 N분」/「차로 약 N분」/「같은 우도 안이에요」).
- 빵부스러기(여행계획짜기 귀찮아:제주 › 제주 무계획 여행 › 지역 › 이름), 출처, 「영업 여부와 시간은 지도 앱에서 확인」.
- **비짓제주 소개 원문(introduction)·요약·태그는 싣지 않는다.** 이름·좌표·우리 이유 문장·종류·실내·장날만.

**기분 조합 `/jeju/<지역>/<기분>/`**(2단계)
- 그 지역 그 기분 상위 **12곳**(검색어에 「체험」이면 체험 탭, 「구경」이면 구경 탭만), 지역 중심 기준 거리 문구. 제목은 target 검색어의 말(「성산 근처 체험, 지금 할 만한 곳 · 여행계획짜기 귀찮아:제주」).

## 지킬 것

- **라이선스**(`docs/licensing-visitjeju.md`, ADR-0023·0072): 비짓제주 소개·요약·태그 원문 금지(빌드가 대조, L4). 사진은 핫링크만, 다운로드·자체 캐시·재호스팅 없음. 모든 페이지 하단 `정보·사진: 비짓제주(제주관광공사) · visitjeju.net`(사진 없는 모드는 `정보:`). 광고·제휴 링크 없음.
- **화면과 같은 구조화 데이터**: 허브 `CollectionPage`+`ItemList`(지역 15)+`BreadcrumbList`, 지역 `TouristDestination`+기분별 `ItemList`(ListItem → `TouristAttraction`/`Restaurant`/`CafeOrCoffeeShop`, name, description=이유, geo, url=장소 페이지, image)+`BreadcrumbList`, 장소 `TouristAttraction`/`Restaurant`/`CafeOrCoffeeShop`(name, description=이유, `GeoCoordinates`, url, hasMap=네이버 검색, image, containedInPlace=지역)+`BreadcrumbList`. **`aggregateRating` 없음**(점수는 리뷰 평점이 아니고 화면에도 없다, ADR-0060). `image`는 사진 모드에서만.
- canonical 자기참조(SITE_URL이 있으면 절대 URL), `lang="ko"`, description은 이유 문장 + 한 문장.
- 앱 셸과 같은 토큰의 자체 CSS(`src/landing.css` → `dist/jeju/landing.css`), 스크립트 없음(JSON-LD만).
- `sitemap.xml`은 사이트맵 색인이다(`docs/seo/2026-10-16-generic-search.md` a4, GSC에서 사이트맵별 색인 수를 읽으려고): `sitemap-core.xml`(`/`·`/privacy`·`/jeju/`·지역 15·조합 — 지금 19쪽) + 동네별 장소 `sitemap-<지역>.xml` 15개. 합치면 `/`·`/privacy`·`/jeju/`·지역·조합·장소 전부(지금 2,940 URL). `lastmod` = 쪽마다 본문이 마지막으로 바뀐 날(`data/landing/lastmod.json`, 단추 글자는 세지 않는다), 색인 파일은 하위 파일 안의 가장 늦은 날. 한 파일이 45,000 URL을 넘으면 `sitemap-<이름>-2.xml`로 잇는다. SITE_URL이 있으면 `robots.txt`에 `Sitemap:` 줄을 빌드가 더한다. `llms.txt`는 허브를 링크한다.
- 서비스워커는 `/jeju/**`(페이지·CSS)를 캐시하지도 셸로 답하지도 않는다(앱 셸이 아니다).
- 404: `/jeju/` 아래 없는 주소는 호스트의 `404.html`(noindex, SPA 폴백 없음, ADR-0063)이고, 그 페이지에 「처음 화면으로」와 「동네별로 둘러보기」가 있다. 빠진 장소의 주소는 404로 둔다(검색엔진이 색인에서 뺀다). 지역이 바뀐 장소만 301.
- 문구는 `check:slop` 규칙을 통과한다 — 생성기의 문구(`scripts/landing.ts`)와 CSS(`src/landing.css`)를 검사한다. 장소 이름은 검사하지 않는다(고유명사).

## 품질 기준 (얇은 페이지 방어) — 빌드가 어기면 멈춘다

seoulist 사후 분석의 「빈 틀 다발」을 막는 기준이다. `scripts/build-landing.mjs`가 전 페이지를 재고 하나라도 어기면 exit 1.

| # | 기준 | 지금(2026-10-01 빌드) |
|---|---|---|
| Q1 | 이유 문장이 자기 원문(`review/input`의 intro·summary·comment)과 **20자 이상 연속으로 같으면 장소 페이지를 만들지 않는다**(앱에는 남는다. 이유를 고치면 다음 빌드에 생긴다) | 9곳 제외(연정식당·귤하르방 동문시장점·무지개요트·한라생태숲·제주올레 20코스·하도해변·제주빅볼랜드·라온골프클럽·바다다이브) |
| Q2 | 모든 랜딩 HTML 본문에서 원문 **20자 연속 0건**(장소 이름은 사실이라 빼고 비교) = L4 | 0건 |
| Q3 | 랜딩 페이지 **모든 쌍**의 `<main>` 본문 5글자 조각 Jaccard **< 0.80**(128 MinHash로 전 쌍을 추정, 0.15 안쪽은 정확히 계산) | 최고 0.777(가파도 식당 2곳) |
| Q4 | 장소 페이지마다 `<main>` 조각 중 **30% 이상이 자기 것**(장소 페이지 절반 이상에 나오는 조각 = 틀, 그 밖 = 자기 것) | 최저 47.0% |
| Q5 | 장소 페이지마다 가까운 곳 **3곳 이상** | 전부 5곳 |
| Q6 | 사진은 `api.cdn.visitjeju.net` 핫링크만(파일 0), `LANDING_PHOTOS=0`이면 0장, 모든 페이지에 출처 표시 | 통과 |

기준값(20자·0.80·30%·3곳)은 첫 빌드 전에 정했다. 첫 측정은 Q3을 **페이지 전체**(머리·발 포함)로 재서 5쌍이 0.80을 넘었다(최고 0.822, 모두 몇십 m 안에 붙은 같은 종류 — 가파도 식당 2곳, 남원 ATV 2곳 등: 가까운 곳 목록이 거의 같다). 머리·발은 모든 쪽이 같은 틀이라 중복 판정에서 걷어 내는 것이 맞다고 보고 비교 대상을 `<main>` 본문으로 바꿨다(문턱은 그대로). 한 번 바꾼 것이므로 다시 바꾸려면 ADR로 한다.
Q3이 걸리면: 붙어 있는 두 장소 중 하나의 이유 문장을 더 구체적으로 쓰거나, 둘을 한 장소로 합칠지 큐레이션에서 본다. 문턱을 올리지 않는다.

## 어떻게 만들었나
