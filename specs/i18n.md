# Light Spec — 영어·중국어(简体)·일본어 (ADR-0093)

## 1. 목표

외국인 여행자가 자기 언어로 같은 흐름(기분 → 카드 3장 → 길찾기 → 저장)을 쓴다. 한국어 화면·속도는 그대로다.

## 2. 언어 고르기·바꾸기

- 순서: `?lang=` → 이 기기에 기억한 `lang` → 브라우저 언어 목록(한국어나 `-KR`이 하나라도 있으면 한국어, 아니면 처음 나오는 en·zh*·ja, 아니면 en). ADR-0093 2.
- 스위치: 첫 화면 맨 아래 한 줄(지금 아닌 세 언어)과 설정의 `언어` 줄. `/?lang=xx` 링크.
- 한국어가 아닐 때 화면은 그 언어 문구가 들어올 때까지 최대 3초 가린다. 문구 파일을 못 받으면 한국어로 연다.

## 3. 무엇을 옮기나

- 앱 화면의 모든 문구: index.html 고정 문구, `COPY`·기분 이름·이동 시간·날짜·장날·철·지도 앱 이름·예약 링크 문구·동네 이름과 대표 장소, 접근성 이름(aria-label), 문서 제목.
- 장소: 출하 2,938곳의 소개글(이번), 이름(표기 기준 주인 결정 뒤).
- 옮기지 않는 것: `/jeju/**` 랜딩, `<noscript>`, meta description·OG·JSON-LD, manifest 이름, 지도 링크 안의 검색어(한국어 이름).
- 개인정보 안내: 세 언어 번역본 `/privacy-en`·`/privacy-zh-Hans`·`/privacy-ja`(한국어판이 기준, 번역본은 검색 제외).

## 4. 문체

언어별 `docs/i18n/style-{en,zh-Hans,ja}.md`. 각 파일에 말투, 한국 고유 개념 처리, UI 용어집(근거·「판단」·「확인 실패」 표시), 날짜·이동 시간 꼴, 장소 글 규칙이 있다. 한국어 문장 구조를 옮기지 않고 그 언어 여행 앱이 쓰는 말로 다시 쓴다(주인 요구).

## 5. 장소 글 파이프라인

1. `node scripts/i18n-places.mjs --export` → `review/i18n/source/batch-NNN.json`(150곳씩 20묶음, id·이름·소개글·기분).
2. 번역: 묶음마다 언어마다 따로(Claude 서브에이전트, 유료 API 없음), 그 언어 문체 가이드를 읽고 `review/i18n/<lang>/reasons-NNN.json`(`{ id: 소개글 }`)에 쓴다. 이름은 기준이 정해진 뒤 `names-NNN.json`.
3. `node scripts/i18n-places.mjs` → `public/i18n/places.<lang>.json`. 빈 글·한글 남음·끝 마침표·너무 긴 글은 싣지 않고(그 곳은 한국어로 보인다) 개수를 찍는다.

## 6. 품질 검수 (사전 등록, 번역 전 2026-10-17)

- **표본**: 출하 장소를 `sha256(id + "i18n-qa-01")` 순으로 줄 세운 앞 60곳, 세 언어 공통(`review/i18n/qa/sample-01.json`, 번역 전에 고정). UI 문구는 표본이 아니라 전부 본다.
- **검수자**: 언어마다 번역자와 다른 서브에이전트 하나. 그 언어 원어민 편집자 역할로 한국어 원문·번역문·문체 가이드를 보고 곳마다 아래 범주별로 판정하고 근거를 한 줄 적는다.
- **오류 범주**:
  - (가) 다른 곳: 번역이 다른 장소를 말하거나 사실(무엇이 있는지·어디인지)을 바꿈.
  - (나) 뜻 틀림: 뜻을 잘못 옮기거나 원문에 없는 사실을 더하거나 있는 사실을 뺌.
  - (다) 한국어 남음: 번역문에 한글이 남음(전수 자동 검사도 같이).
  - (라) 이름 어긋남: 소개글 속 지명·용어가 용어집·카드·UI 표기와 다름.
  - (마) 번역투: 한국어 구조·어순이 새어 나옴, 어색한 직역, 맞지 않는 말투, 원어민이 안 쓰는 용어. **따로 집계**한다.
- **오류율**: (가)~(라) 중 하나라도 있는 곳 수 / 60, 그리고 (마) 있는 곳 수 / 60. 언어마다 따로 보고한다.
- **한 번만 잰다**: 검수는 한 번 돌리고 그 숫자를 보고한다. 찾은 오류는 고쳐도 되지만 보고하는 오류율은 고치기 전 숫자다. 통과할 때까지 다시 재지 않는다.
- 기준선 없음, 통과선 없음: 숫자는 출시 판단 재료로만 쓴다.

## 7. 성공 기준

- tsc 0, vitest 통과, `check:slop` 0, 운영 빌드 성공, 한국어 방문 JS+CSS gzip ≤ 50KB, 전체 e2e 통과, seo:crawl 0.
- e2e(375×812, en·zh-Hans·ja 각각): 첫 화면, 기분 하나의 카드 3장, 기준 시트, 저장한 곳에서 화면에 보이는 글자에 한국어 UI 문구가 없다(장소 고유명사·`한국어` 링크 제외), 글이 넘치거나 잘리지 않는다, 길찾기는 기본으로 네이버지도로 간다. 한국어 e2e는 그대로 통과.
- 스크린샷: `apps/web/design/qa/i18n/`(언어별 첫 화면·결과).
- 번들 숫자(2026-10-17 운영 빌드, gzip): 한국어 방문 JS 42.47 + CSS 5.69 = **48.16KB**(이전 46.74KB, +1.42KB. 그중 약 0.58KB는 동적 import에 Vite가 붙이는 preload 도우미). 다른 언어는 여기에 언어 청크(en 4.95·zh-Hans 5.27·ja 5.57) + 공용 `apply` 0.75KB를 더 받는다(53.9~54.5KB). 장소 글 파일 en 131·zh-Hans 129·ja 140KB(gz, 그 언어일 때만, `spots.json` 다음에).
