# 서울 카카오 대조 S3b — 사전등록 (구마다 kakao-<구 코드>-01)

등록: 2026-10-31, 서울 판정 전·호출 전 커밋. 근거: 강원 `review/gangwon/kakao-criteria.md` 1~5절(= 부산 `review/busan/kakao-criteria.md`, 같은 규칙·코드·임계값), ADR-0106 7, ADR-0050, `docs/research/busan-data-sources.md` 1-5(저장은 장소 ID·place_url만). 이 문서는 결과를 본 뒤 바꾸지 않는다. 강원과 다른 것은 **이름 머리말**, **하루 한도를 강원 로그와 합쳐 세는 것**, 대상·파일 이름뿐이다. 코드는 `apps/web/scripts/curated/kakao.mjs`(머리말은 `scripts/curated/rounds.mjs` `cityHeads`).

## 1. 대상

- 감사를 통과한 구의 판정(`review/seoul/judge-<구 코드>-06/out-*.json`, `fixes`는 상관없음)에서 `keep: true`인 곳 전부. 뺀 곳은 부르지 않는다. 감사에 떨어진 구는 부르지 않는다.
- 장소의 이름·좌표·종류는 `review/seoul/scope.json`(TourAPI 원문)에서, 기분은 판정에서 읽는다.

## 2. 호출 (곳마다 1회)

- 강원 2절 그대로: 카카오 로컬 키워드 검색, `query` = 괄호와 그 안 글자를 지운 `title`, `x`·`y` = TourAPI 좌표, `radius` = 거리 한도, `size=15`, `page=1`. 곳마다 한 번. 다시 부르는 것은 응답을 못 받았을 때만(429·5xx·네트워크 오류, 1초·2초 쉬고 최대 3번). 401·403이면 바로 멈추고, 20곳 넘게 부른 뒤 실패가 5%를 넘으면 멈춘다.
- **하루 한도**: KST 하루 1,200회. 같은 키를 쓰므로 `review/seoul/kakao-calls.log`와 `review/gangwon/kakao-calls.log`의 그날 줄을 **합쳐** 센다. 닿으면 멈추고 다음 날 같은 명령으로 이어 간다(이미 쓴 곳은 부르지 않는다 — 같은 실행의 이어 하기이고 다시 재기가 아니다).
- **차례**: 감사를 통과한 구를 구 코드 순(110 종로 → 140 중구 → 170 용산 → 200 성동 → 215 광진 → 230 동대문 → 260 중랑)으로 하나씩 돌린다. 한도에 닿아 끝나지 않은 구는 다음 날 이어 간 뒤에 출하한다(그때까지 자동 지역).
- 로그 `review/seoul/kakao-calls.log`에 `KST날짜\t시각\tid\t결과`. 키·응답 본문은 어디에도 남기지 않는다. 키는 저장소 루트 `.env`의 `KAKAO_REST_API_KEY`이고 스크립트가 안에서 읽는다. 키가 없거나 401·403이면 이 단계는 **확인 실패**로 적고 멈춘다(「없음」으로 적지 않는다).

## 3. 맞는 곳 고르기 (규칙만)

강원 3절 그대로(거리 음식점 300m·그 밖 1,000m, 분류 거르기, 이름 다듬기, `exact`·`contains`, 시설 꼬리, 가장 가까운 곳, 폐업 낱말 → `closed`). 다른 것은 **머리말**뿐이다: 이름 다듬기 뒤 두 이름 모두 앞의 `서울특별시`·`서울시`·`서울`·구 이름(`종로구`)·구 낱말(`종로`, 중구는 `중구`) 가운데 하나를 뗀 값도 함께 본다(강원의 `강릉시`·`강릉` 자리). 응답의 이름·좌표·주소·분류는 판정에만 쓰고 저장하지 않는다.

## 4. 저장 (`review/seoul/kakao-<구 코드>-01.json`)

- 곳마다 `{ id, query, status, rule, kakaoPlaceId, placeUrl }`만. **카카오의 이름·좌표·주소·분류·거리는 저장하지 않는다.**
- 머리에 `criteria`(이 파일), `city`(구 코드), 대상 수, 상태별 수, 규칙별 수.

## 5. 결과에 따라

- 강원 5절 그대로: `matched` → `kakaoPlaceId`(같은 ID를 둘 이상이 가지면 `exact` 한 곳만), `closed` → 출하하지 않음, `unmatched` → 폐업으로 보지 않고 ID 없이 출하.
- 통과 기준(구마다): `matched` ≥ 50%. 못 넘으면 그 구의 결과를 빌드 입력으로 쓰지 않고, 규칙을 고치지 않고 수치와 가설을 `REPORT.md`에 적고 그 구는 자동 지역 그대로 둔다. 다시 돌리려면 주인 승인.
- 구마다 한 번이다. 맞은 수를 늘리려고 검색어·거리·이름 규칙을 바꿔 다시 부르지 않는다. 사람 손으로 ID를 붙이거나 고치지 않는다.
