# 서울 장소 영업 유형 기준 01 — S1.5 (2026-11-05) — 실행 전 고정

주인 원칙: 지금 갈 수 없는 곳은 추천하지 않는다. 서울 장소(`data/seoul/spots-seoul.json`, 2,748곳)에는 영업시간도 종류 칸도 없어서, 지금은 `src/state.ts`의 이름 규칙(`viewingShut`·`openSpots`, ADR-0117 Amendment 4·5)으로만 밤의 관람형을 뺀다. 이름에 박물관·미술관이 없는 관람형은 밤에도 남는다(`review/browse/predeploy-review-shelves.md` 「재검토」 R1). 이 기준은 장소마다 영업 유형 라벨을 붙여 그 구멍을 메운다.

## 1. 대상 — 먹기를 뺀 1,154곳
- 대상: `mood`가 `new`(838곳: sight 738·do 100), `rest`(192곳), `walk`(124곳).
- 뺌: `food` 1,594곳(meal 1,312·cafe 282). 식당·카페 영업시간은 가게마다 다르고 자주 바뀌어 모델 지식으로 유형을 매길 수 없다. 이번 범위 밖.
- `rest`·`walk`를 넣는 까닭: 지금 이름 규칙은 둘을 늘 열린 것으로 보지만, 실제로는 문 닫는 곳이 섞여 있다(예: 서울식물원·푸른수목원·국립중앙박물관 전통염료식물원·남산서울타워·스파레이·문화비축기지·국립산림과학원 홍릉시험림). 공원·길이 대부분이라 판정 부담은 작다.
- `data/seoul/fun-seoul.json`(즐길 거리 304곳)은 이번 대상이 아니다.
- 입력 원본의 sha256은 `input/index.json`에 적었다. 판정 전에 원본이 바뀌면(build:spots 등) 입력을 다시 만들고 이 기준을 새 번호로 낸다.

## 2. 라벨 (하나만 고른다)

| 라벨 | 뜻 | 앱이 쓰는 시간 |
|---|---|---|
| `day-viewing` | 문·매표가 있고 낮에만 들어가는 곳. 대략 10시 전후에 열고 17–19시에 닫는다 | 10:00–18:00 (닫기 30분 전부터 뺌, 지금 규칙과 같음) |
| `palace` | 조선 궁궐·종묘 | 09:00–18:00 |
| `always` | 문이 없거나 늘 열린 곳, 또는 24시간 여는 곳 | 늘 |
| `evening` | 20시 넘어서까지 여는 곳 | 판정자가 적은 `open`–`close` |
| `unknown` | 위 넷 중 무엇인지 확신하지 못함 | 지금 이름 규칙 그대로 |

판단 규칙과 예시:
- `day-viewing`: 박물관·미술관·갤러리·기념관·전시관·과학관·문학관·옛집·고택(관람형)·식물원·수목원·성당·사찰 경내 전시시설·체험관·공방 체험처럼 입장 시간이 있는 낮 시설. 이름에 그런 말이 없어도 무엇인지 알면 이 라벨(예: 학고재, 푸투라서울, 리움, 윤동주문학관, 서울식물원 온실). 목·금·토 야간 개장처럼 일부 요일만 늦게 여는 곳도 평일 기준으로 `day-viewing`.
- `palace`: 경복궁·창덕궁·창경궁·덕수궁·경희궁·종묘. 왕릉(선정릉 등)·궁 이름이 든 공원·길은 `palace`가 아니다 — 왕릉은 아는 시간대로 `day-viewing`/`evening`, 모르면 `unknown`; 경희궁공원·덕수궁 돌담길은 `always`.
- `always`: 공원·광장·한강공원·하천·산·둘레길·골목·거리·마을·다리·전망 쉼터처럼 문이 없는 곳. 24시간 찜질방·24시간 시설도 여기. 공원 안에 문 닫는 시설이 있어도 장소가 공원 자체면 `always`. 산은 밤에 위험해도 열려 있으면 `always`(위험은 이 기준이 다루지 않음).
- `evening`: 공연장·극장·아트센터·아쿠아리움·전망대(남산서울타워·롯데월드타워 서울스카이)·테마파크·쇼핑몰·시장·스파·방탈출·볼링 등 놀이 시설처럼 20시 넘어 닫는 곳. `open`·`close`를 `HH:MM`으로 반드시 적는다(자정 넘으면 `25:00`처럼). 공연장은 공연이 끝나는 대략의 시각을 닫는 시각으로 적는다.
- `unknown`: 이름만으로 무엇인지 모르거나, 무엇인지 알아도 시간대를 확신하지 못하면. 소개글(`reason`)과 이름이 서로 다른 곳을 가리키는 듯해도 `unknown`. 「아마」라면 `unknown`이다 — 틀린 라벨은 열린 곳을 숨기거나 닫힌 곳을 보여 주지만, `unknown`은 지금 규칙으로 돌아갈 뿐이다.

## 3. 다루지 않는 것 (이번 범위 밖)
- 휴관일(월요일 휴관 등)·명절 휴무·계절별 시간 차이·임시 휴관·폐업. 라벨은 「여는 날」의 시간대만 말한다.
- 입장 마감 시각과 닫는 시각의 차이(앱은 닫기 30분 전부터 뺀다).
- 위험·야간 안전·조명.

## 4. 판정자 입력
`input/batch-NN.json`(20묶음, 58곳씩, 마지막 52곳). 장소마다 데이터에 있는 칸만 준다:
`id`, `name`, `area`(구), `lat`, `lng`, `mood`, `sub`(있으면), `indoor`, `reason`(기존 소개글), `famous`·`walkin`(참일 때만).
주소 칸은 데이터에 없다. 구와 좌표로 같은 이름의 다른 곳과 가린다. 판정자는 웹 검색 없이 모델 지식만 쓴다.

## 5. 출력 — `out/batch-NN.json`

```json
{
  "batch": "01",
  "items": [
    { "id": "nt-2733967", "label": "day-viewing", "open": null, "close": null, "why": "한 줄 근거" },
    { "id": "nt-…", "label": "evening", "open": "10:00", "close": "22:00", "why": "…" }
  ]
}
```
- 입력의 모든 `id`가 한 번씩, 입력에 없는 `id`는 없다. `label`은 위 다섯 중 하나.
- `open`·`close`는 `evening`에서만 `HH:MM`, 나머지는 `null`.
- `why`는 한국어 한 줄(무엇인지 + 왜 이 라벨).

## 6. 감사 게이트
- 판정 01: 새 Opus, 묶음마다 한 번.
- 표본: `node scripts/seoul-hours/hours.mjs sample`. 씨앗 **20261106**, 라벨마다 **20곳**(적으면 전부), 다섯 라벨 합쳐 최대 100곳. 출력이 입력과 어긋나면(빠짐·중복·없는 라벨) 표본을 뽑지 않고 멈춘다.
- 감사 01: 판정을 보지 않은 또 다른 새 Opus가 `audit-01-input.json`(판정 칸 없음, id 순)을 이 기준대로 한 번 판정한다.
- 일치: 라벨이 같으면 일치. `evening`은 `close`가 60분 안쪽으로 같아야 일치.
- 통과: `unknown`이 아닌 판정 라벨 표본 전체 일치율 **90% 이상**이고, 표본이 10곳 이상인 라벨마다 **90% 이상**.
  - 전체가 90% 미만이면 아무것도 싣지 않는다.
  - 전체는 통과했는데 한 라벨이 90% 미만이면 그 라벨은 싣지 않는다(그 라벨의 곳은 `unknown`처럼 지금 이름 규칙).
  - `unknown` 표본의 일치율은 보고만 한다(게이트 아님).

## 7. 1회 실행 규칙
- 판정 01과 감사 01은 각각 한 번만 돌린다. 결과가 마음에 안 든다고 다시 돌리지 않는다.
