# 강원 판정 C2 — 사전등록 (강릉 judge-강릉-01, audit-강릉-01)

등록: 2026-10-30, 판정 전 커밋. 근거: `plans/nationwide.md` C2, 부산 선례 `review/busan/criteria.md`(같은 규칙·코드·기분·실내 규칙·임계값), `specs/busan.md` 3.3, ADR-0094·0095, `docs/context.md`(기분·이유 문장·실내·장소 범위), `design/SPEC.md` §10 이유 문장, ADR-0065 실내, ADR-0064 새로운 거 탭, ADR-0066 시장. 승인: 「주인 위임 2026-10-30 「권한 다 줄 테니 끝까지」」. 이 문서는 결과를 본 뒤 바꾸지 않는다.

**이번에 정하지 않는 것**: 유명한 곳·만족도, 카카오 ID·폐업, 예약 경로, 중복 장소 합치기(빌드 몫). 판정은 장소마다 따로 한다.

**검수자에 관한 기록**: 부산은 표본을 사람(주인)이 아니라 하위 에이전트가 검수했다. 강원도 밤사이 사람 표본 검수 없이, 독립 모델 감사(R1 다시 판정, R2 사실 확인)로 대신한다. 주인은 아침에 `REPORT.md`를 보고 확인한다. 판정자·R1·R2는 같은 계열 모델이라 공통 편향이 일치율에 드러나지 않을 수 있고, 이 한계는 보고서에 적는다.

## 1. 대상과 입력

- 대상: `review/gangwon/scope.json`에서 `city`가 **강릉**이고 상세 원문(`raw/detail/<contentid>.json`)이 저장된 곳 724곳 전부(관광지 148·문화시설 32·레포츠 56·전통시장 11·음식점 477). 다른 시(속초·양양·춘천·평창)는 상세 수집이 끝난 뒤 이 문서와 같은 규칙으로, 도시 이름만 바꿔 따로 판정한다(`judge-<도시>-01`, `audit-<도시>-01`, 씨앗·임계값 같음). 상세가 없는 곳은 판정 대상이 아니다.
- 입력: `npx tsx scripts/curated/judge.mjs prep gangwon 강릉`이 `raw/detail/*.json`에서 뽑은 `judge-강릉-01/input-NN.json`(종류·id 순, **50곳씩 15묶음**, 마지막 24곳). 곳마다 `id`(`nt-<contentid>`)·`name`·`type`·`contenttypeid`·`cat3`·`lclsSystm3`·`addr`·`overview`(공백만 정리한 원문).
- 판정 근거는 입력뿐이다. 웹 검색·모델의 바깥 지식으로 보태지 않는다. 개요가 비었거나 거의 없으면 `INSUFFICIENT_INFO`로 뺀다.

## 2. 판정 출력 (곳마다, `judge-강릉-01/out-NN.json`, 입력과 같은 순서)

```json
{ "id": "nt-…", "name": "입력 그대로", "keep": true,
  "mood": "rest|walk|new|food", "sub": "meal|cafe|sight|do (해당할 때만)", "indoor": false,
  "reason": "이유 문장", "basis": ["원문 조각", "…"], "confidence": "high|low" }
{ "id": "nt-…", "name": "…", "keep": false, "reject": "코드", "basis": [], "confidence": "high|low" }
```

- `basis`: 원문 조각 1~3개, 각 40자 이내, `overview`(또는 `name`)의 **글자 그대로** 부분 문자열(공백 차이만 허용). 이유 문장의 사실과 기분·실내 판단을 받친다. 내부용이고 출하 파일에 옮기지 않는다. 뺀 곳은 비워도 된다.
- `confidence`: 기록만 한다(상위 모델 재판정 없음, 1회 판정).

### 2.1 keep — 여행자가 일부러 갈 곳인가

뺄 때 코드:

| 코드 | 뜻 (지어낸 예) |
|---|---|
| `NOT_DESTINATION` | 여행자가 일부러 찾지 않는 곳: 동네 골목시장·주민용 소형 상가시장, 관공서형 시설(시민회관·주민센터·청사 홍보관·도서관 열람실 같은 주민 편의시설), 일반 체육시설·학원형 시설 |
| `INSUFFICIENT_INFO` | 개요가 없거나 무엇을 하는 곳인지 원문으로 알 수 없음 |
| `CHAIN_GENERIC` | 전국 체인 지점, 특색이 원문에 없는 일반 가게 |
| `CLOSED_OR_TEMP` | 원문이 폐업·이전·철거·한시 운영을 말함 |
| `OUT_OF_SCOPE` | 장소 범위 밖이 원문으로 드러남: 숙박·면세점·대형마트·일반 상점·축제·행사(기간 있는 것)·여행 코스 |
| `INAPPROPRIATE` | 여행 카드로 보이기 부적절(유흥업소 등) |

- 관광지·문화시설·레포츠는 원문이 말하는 볼거리·할 거리가 있으면 keep. 박물관·사찰·해수욕장·공원·전망대·체험시설은 대개 keep.
- 전통시장은 여행자가 구경 갈 만한 곳(이름난 시장, 먹거리·볼거리를 원문이 말함)만 keep, 주민 장보기용 동네 시장은 `NOT_DESTINATION`.
- 음식점은 원문에 대표 메뉴나 특색이 있으면 keep.

### 2.2 기분 `mood`와 `sub`

| 기분 | 고르는 곳 | `sub` |
|---|---|---|
| `rest` 푹 쉬고 싶어 | 머물며 쉬는 것이 주인 곳: 해변에 앉아 바다 보기, 공원·쉼터, 전망 좋은 곳, 온천·스파·찜질 | 없음 |
| `walk` 좀 걷고 싶어 | 걷는 것이 주인 곳: 산책로·둘레길·해안 산책로·숲길·등산로·마을길·성곽길, 걸으며 보는 유적 터 | 없음 |
| `new` 새로운 거 해보고 싶어 | 보고 배우거나 해 보는 곳: 박물관·미술관·전시관·과학관·유적·사찰 구경·테마파크·시장(`sight`), 레포츠·만들기·배우기 체험(`do`) | `sight`·`do` |
| `food` 맛있는 거 먹고 싶어 | 먹고 마시는 곳 | `meal`·`cafe` |

- 음식점(39)은 늘 `food`. `sub`는 카페·찻집·디저트·베이커리면 `cafe`(분류 `cat3` `A05020900`·`lclsSystm3` `FD05…`가 힌트), 식사면 `meal`. 원문이 분류와 다르면 원문을 따른다.
- 음식점이 아닌 곳도 원문이 먹는 것이 주인 곳(먹자골목 등)이면 `food`·`meal`일 수 있다.
- 전통시장(38)은 `new`·`sight`(ADR-0066).
- 레포츠(28)는 해 보는 것이 주인 곳이면 `new`·`do`, 걷기·등산이 주인 곳이면 `walk`.
- 둘 이상에 걸치면 원문이 가장 길게 말하는 활동 하나를 고른다.

### 2.3 실내 `indoor` (ADR-0065, 태그가 없으니 개요·분류로만)

- 음식점·카페는 `true`. 원문이 노천·야외·포장마차 중심이면 `false`.
- 박물관·미술관·전시관·공연장·실내 체험·찜질방·스파·실내 테마파크처럼 건물 안이 중심이면 `true`.
- 해변·산·공원·산책로·사찰·유적·시장 골목·수상 레저·야외 체험은 `false`.
- **애매하면 `false`**: 실외가 중심이고 실내가 일부인 곳, 실내·실외 반반, 지붕 덮인 시장이라도 원문이 실내라고 말하지 않으면 `false`.

### 2.4 이유 문장 `reason` (design/SPEC.md §10, context.md 이유 문장)

- 그 고장을 아는 동네 사람이 한 줄로 알려 주는 말. 판매원·비서·선생님 말투가 아니다.
- **원문(`overview`·`name`·분류)에 있는 사실만**. 원문에 없는 메뉴·풍경·역사·위치 관계·숫자·감각(맛·소리·냄새)·형용사를 넣지 않는다.
- 구체 명사(무엇을 보고·먹고·걷는지) 1개 이상, 형용사 1개 이하, 최상급·과장 없음.
- 끝맺음을 섞는다: `~해요`, `~이에요/예요`, 명사로 끝맺기. `~수 있어요`는 keep 전체의 20% 이하.
- 15~70자(권장 15~40), 한 문장, 끝 마침표 없음, 가운데 마침표 없음, 느낌표·물음표·대시 없음, `돈가스` 표기.
- 금지: `REASON_BANNED`(`scripts/check-slop.ts`: ~하기 좋아요·좋은, 인생샷, 힐링, 다양한, 특별한, 완벽한, 최고의, 숨은 보석·명소, 감성 넘치는, 잊지 못할, 매력적인, ~를 통해, ~에 있어서, 할 수 있습니다, 가능합니다, 되어집니다, 여유를 즐겨요, 겉바속촉, 돈까스, 아름다운, 여유를 누려요, 공간이에요)와 가격·입장료·요금·무료·영업·휴무·시각·요일·매주·평점·별점(`build-spots.mjs` 규칙).
- 지어낸 예(방향만): 원문 「바닷가 절벽 위 산책로에서 섬이 보인다」 → `절벽 위 산책로에서 바다 건너 섬이 보여요`. 원문 「순두부와 두부전골을 낸다」 → `순두부와 두부전골을 내는 집이에요`.

## 3. 판정 방법

- **판정자**: Claude 하위 에이전트(Sonnet 5.5). 유료 API 없음. 묶음마다 에이전트 하나가 `input-NN.json`을 읽고 `out-NN.json`을 쓴다. 한 묶음에 한 번.
- 에이전트가 받는 지시는 `review/gangwon/judge-brief.md`(이 문서 1~2절의 판정 규칙을 옮긴 것)와 아래 판정 지시뿐이다. 판정 지시(그대로): 「`review/gangwon/judge-brief.md`를 읽고, `review/gangwon/judge-강릉-01/input-NN.json`의 곳마다 형식대로 판정해 같은 폴더의 `out-NN.json`에 입력 순서대로 써라. 원문에 없는 사실을 쓰지 않는다. `basis`는 원문을 글자 그대로 복사한다. 웹을 찾지 않는다. 다른 묶음·다른 파일을 보지 않는다. 끝나면 `npx tsx scripts/curated/judge.mjs check gangwon 강릉 NN`으로 문제 0곳인지 보고, 걸린 곳은 걸린 칸만 고쳐라.」 묶음 안의 이 자기 검사는 판정의 일부다(4절의 형식 수리와 별개).

## 4. 기계 검사와 한 번의 형식 수리

- `npx tsx scripts/curated/judge.mjs check gangwon 강릉`: 누락 0, 남는 id 0, 값(코드·기분·sub·실내), 음식점은 `food`, 시장은 `new`·`sight`, 근거 조각이 원문 부분 문자열이고 40자 이내, 이유 문장 규칙(2.4의 기계로 잴 수 있는 것), `~수 있어요` ≤ 20%. 결과는 `judge-강릉-01/check.json`.
- 검사에 걸린 곳은 **걸린 칸만** 한 번 고친다(형식 수리, 같은 판정 기준). 고친 곳은 `judge-강릉-01/repair.json`에 전후를 남긴다. 판단(keep·기분·실내)을 바꾸는 수리는 검사 위반을 고치는 데 꼭 필요할 때만이고, 그때도 기록한다. 표본은 검사가 통과한 뒤에 뽑는다.

## 5. 독립 모델 감사 (audit-강릉-01, 1회)

- **표본**: keep된 곳 가운데 120곳(keep이 120 미만이면 전부). `scripts/curated/judge.mjs`의 `drawSample` — keep id를 문자열 오름차순으로 놓고 `mulberry32(20261030)`로 Fisher–Yates 섞기, 앞 120개. 씨앗 **20261030**. 명령 `npx tsx scripts/curated/judge.mjs sample gangwon 강릉`, 결과 `review/gangwon/audit-강릉-01-sample.json`(입력 원문만, 판정 없음).
- **다시 판정(R1)**: judge-강릉-01을 하지 않았고 보지 않은 다른 하위 에이전트. 받는 것은 표본 입력과 `judge-brief.md`의 판정 규칙(이유 문장 규칙 제외)뿐. 판정 파일·이유 문장을 보지 않는다. 곳마다 `keep`(뺄 때 `reject`), `mood`, `sub`, `indoor`를 쓴다 — **뺀다고 해도 `indoor`는 쓴다**. 결과 `audit-강릉-01-judgments.json`.
- **사실 확인(R2)**: 또 다른 하위 에이전트. 받는 것은 곳마다 원문(`name`·분류·`addr`·`overview`)과 이유 문장뿐(keep·기분·실내는 안 받음). 결과 `audit-강릉-01-facts.json`(`factError`, `note`).
- 셋(판정자·R1·R2)은 서로의 결과를 보지 않는다.

### 5.1 오류 정의

- **keep·기분 불일치**: R1이 빼거나(`keep: false`), R1의 `mood`가 첫 판정과 다름. `sub` 불일치는 기록만 한다.
- **실내 불일치**: R1의 `indoor`가 첫 판정과 다름.
- **이유 문장 사실 오류**: 이유 문장이 말하는 사실(무엇이 있다·보인다·판다·했다, 위치 관계, 숫자, 맛·감각·상태를 말하는 형용사) 가운데 하나라도 원문에 없거나 원문과 어긋남. 원문 낱말을 다른 말로 바꿔 쓴 것(같은 뜻)은 오류가 아니다. 말투·끝맺음은 사실이 아니다.

### 5.2 통과 기준 (부산과 같은 숫자)

| 지표 | 기준 |
|---|---|
| keep·기분 일치 | ≥ 90% (120곳 중 108곳 이상) |
| 실내 일치 | ≥ 95% (114곳 이상) |
| 이유 문장 사실 오류 | ≤ 3 / 120 |

`npx tsx scripts/curated/judge.mjs score gangwon 강릉`이 `review/gangwon/audit-강릉-01.json`(곳별 행, 지표, `pass`)을 쓴다. 결과와 해석은 `review/gangwon/REPORT.md`. 사람 검수 대신 이 감사를 쓰므로 주인은 아침에 REPORT를 읽고 확인한다.

## 6. 결과에 따라

- **통과**: R2가 짚은 사실 오류 이유 문장만 원문에 맞게 고쳐 `judge-강릉-01/fixes-01.json`(전후·근거)에 남긴다. 다시 재지 않는다. keep·기분·실내 불일치는 어느 쪽이 맞는지 이 회차에서 정하지 않고 기록만 한다(판정을 고쳐 일치율을 올리지 않는다).
- **실패**: 판정을 고치지 않고 붙이지 않는다(출하 입력이 되지 않음). 수치·불일치 유형·가설을 `REPORT.md`에 적고 멈춘다. 다시 돌리려면 주인 승인.
- 판정·표본·감사는 각각 한 번이다. 통과할 때까지 돌리지 않는다.
