# 자동 지역 규칙 v3: 사전등록 (rules-03, audit-03)

등록: 2026-10-31, 규칙 v3을 돌리기 전에 커밋. 근거: ADR-0074 Amendment 1(「애매하면 예약해야만 할 수 있는 곳으로 둔다」), ADR-0105, `rules-criteria-02.md`, `.scratch/mood-followups/issues.md` mf-2(독립 리뷰 M1). 승인: 주인 지시 「나머지 미비한 부분」(2026-10-31). 이 문서는 결과를 본 뒤 바꾸지 않는다.

## 0. v2와 다른 것

v2(`rules-criteria-02.md`) 3절 「`new`·`do`의 예약」에 줄을 더할 뿐이다. 기분·실내·쉬기·계곡·먹기·체인·뺄 코드는 v2와 같다. 검수한 곳이 쓰는 `scripts/walkin.mjs`는 바꾸지 않는다(v3 줄은 자동 지역 규칙 `scripts/nation/rules.mjs` `judge3`에만 둔다). 출력은 `rules-03.json`(v2 `rules-02.json`은 그대로 둔다), `scripts/nation/build.mjs`가 `rules-03.json`을 읽는다.

## 1. 대상

v2와 같다. `review/nation/scope-<시도>.json` 14개 시도 30,697곳. 입력 필드는 `title`, `contenttypeid`, `lclsSystm3`뿐이다. v3이 결과를 바꿀 수 있는 곳은 v2가 `new`·`do`·`walkin: true`로 둔 곳(계곡 NA010400 제외)뿐이다.

## 2. 더하는 줄 (v2 3절 1·2 다음, 3 앞에서 순서대로)

이름은 공백을 모두 뗀 글자로 본다.

| 무리 | 조건 | 결과 |
|---|---|---|
| N 이름 | 이름에서 `대학교`·`초등학교`·`중학교`·`고등학교`를 지운 뒤 `학교`·`아카데미`·`투어`·`체험마을`이 있음 | 예약해야만 함 |
| Y 요트 | LS020300 요트 | 예약해야만 함 |
| R 래프팅 | LS020800 래프팅 | 예약해야만 함 |
| H 승마 | LS010700 승마 | 예약해야만 함 |
| W 수상레저 | LS020100 윈드서핑/제트스키 | 예약해야만 함 |
| B 먹거리 산업관광 | EX060800 화장품/주류/먹거리이고 이름에 `양조`·`주조`·`도가`·`공장`·`브루어리`·`체험장`·`체험관`·`체험촌` | 예약해야만 함 (이름에 없으면 v2대로 예약 없이 감: 박물관·와이너리·농원·가게가 섞인 코드라서) |
| F 체험농장 | EX030300 체험농장이고 이름에 `정원`·`가든`·`테마파크`·`생태나라`·`단지`·`동물농장`·`아기동물`·`곤충`·`허브팜`이 **없음** | 예약해야만 함 (있으면 v2대로 예약 없이 감) |

- 한 곳이 여러 무리에 들면 표의 위쪽(N)이 먼저다. 결과는 같다(예약해야만 함). 무리는 감사 집계에만 쓴다.
- 예약해야만 하는 곳은 v2와 같이 `{ keep: false, reject: 'BOOKING' }`이다.
- B·F에서 「예약 없이 감」으로 남는 곳도 무리 B·F의 감사 대상이다(이름 갈래가 맞는지 재려고).

## 3. 계곡 안의 등산 코스 (조사만)

ADR-0105 Consequences·`rules-criteria-02.md` 6절의 「계곡 코드 안의 등산 코스도 놀러로 간다」. v2 keep의 NA010400 276곳 이름에 `등산로`·`탐방로`·`트레킹`·`둘레길`·`코스`·`산책`·`숲길`·`올레`가 있는 곳은 0곳이다(규칙을 돌리기 전에 셈. `구곡`은 경치 이름이지 길이 아니다). 자동 지역에는 원문이 없어 이름·코드로는 가를 수 없다. v3은 계곡을 바꾸지 않고, 고치려면 개요 원문(TourAPI 상세)을 모아 판정하는 다음 회차가 필요하다고 적는다.

## 4. 측정 (audit-03, 1회)

- **모집단**: v2 keep이고 `new`·`do`인 곳 가운데 2절의 무리 N·Y·R·H·W·B·F 하나에 드는 곳(계곡 제외). B·F는 이름 갈래와 상관없이 코드 전체.
- **표본**: 무리마다 id 문자열 오름차순 → `shuffle(목록, 20261105)`(`rules.mjs`의 mulberry32 Fisher–Yates) → 앞에서 N·Y·R·H·W·B는 25곳, F는 40곳(그보다 적으면 전부). 무리는 N, Y, R, H, W, B, F 순서로 뽑고, 앞 무리에서 이미 뽑힌 곳은 건너뛴다. 명령 `node scripts/nation/rules.mjs sample3` → `audit-03-input.json`(이미 있으면 멈춘다). 판정자에게 주는 줄: `id`, `title`, `addr1`, 종류(`contenttypeid` 이름), 분류 이름(`lclsSystm3` 이름, 코드는 주지 않음). 규칙 결과·무리는 주지 않는다. 한 줄로 섞어(씨앗 20261106) 무리를 알 수 없게 한다.
- **판정자**: 규칙과 이 문서를 보지 않은 새 하위 에이전트(Opus). 표본을 나눠 여럿이 맡을 수 있고 각자 다른 몫을 본다. 받는 것: 표본 몫과 판정 안내 `audit-03-brief.md`(이 등록과 같은 커밋). 웹 검색 없음. 출력 `{ id, walkin: true|false, unsure }`. 결과 `audit-03-out.json`.
- **지표**(`node scripts/nation/rules.mjs score3` → `audit-03.json`): 무리마다, 판정자가 `unsure`가 아닌 곳에서
  - v3 일치 = 규칙 v3의 결과(`BOOKING` = `false`, keep `do` = `true`)와 판정자 `walkin`이 같은 비율
  - v2 일치 = v2 결과(모두 `true`)와 판정자 `walkin`이 같은 비율(비교용)
- **기준**: 무리마다 따로 정한다. **v3 일치 ≥ 85%이고 v3 일치 > v2 일치**면 그 무리의 줄을 싣는다. 비교 대상(`unsure` 아닌 곳)이 10곳 미만이면 싣지 않는다.
- 모두 합친 v3 일치·v2 일치는 기록만 한다.

## 5. 결과에 따라 (미리 정함)

- 기준을 넘은 무리의 줄만 `judge3`에 남겨 `rules-03.json`을 짓고 `scripts/nation/build.mjs`로 `data/nation`을 다시 짓는다. 넘지 못한 무리의 줄은 쓰지 않는다(그 곳들은 v2대로 예약 없이 가는 놀거리). 통과·실패 무리와 수치, 틀린 곳, 가설은 `rules-REPORT.md`에 덧붙인다.
- 모든 무리가 실패하면 `data/nation`은 v2 그대로이고 `build.mjs`도 `rules-02.json`을 계속 읽는다.
- 측정은 한 번이다. 통과할 때까지 돌리지 않는다. 다시 재려면 주인 승인.

## 6. 알고 있는 한계

- 원문 없이 이름·주소·분류만 본다. 판정자도 같은 조건이라, 일치율은 「이름과 분류로 같은 답을 내는가」를 잰다.
- 무리 B·F의 이름 낱말은 v2 keep의 이름 목록을 보고 골랐다(표본을 뽑기 전). 같은 목록에서 재므로 낙관적일 수 있다.
- 예약해야만 하는 곳은 싣지 않으므로 v3이 맞으면 자동 지역 놀거리가 줄어든다. 받은 데이터에 3곳 미만인 기분은 숨는다(지금 규칙 그대로).
