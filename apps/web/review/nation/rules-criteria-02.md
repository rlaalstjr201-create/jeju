# 자동 지역 규칙 v2: 사전등록 (rules-02, audit-02)

등록: 2026-10-31, 규칙 v2를 돌리기 전에 커밋. 근거: ADR-0105 4, ADR-0074 Amendment 1, `rules-criteria.md`(v1), 검수한 곳 장소 종류 표(`review/gangwon/criteria-05.md` 0절, `criteria-04.md` 2.2.1). 승인: 주인 지시 「자동 지역 쉬기 규칙, rules v2를 사전등록하고 한 번 재라」(2026-10-31). 이 문서는 결과를 본 뒤 바꾸지 않는다.

## 0. v1과 다른 것

- 기분에 `rest`(푹 쉬고 싶어)가 생긴다. 검수한 곳 표의 「머물러 보는 바다·물가·전망 지점, 공원·쉼터, 온천·스파」를 코드로 옮겼다.
- 계곡(NA010400)은 `walk` → `new`·`do`(놀러·놀거리).
- `new`·`do`에 `walkin`(예약 없이 가는지)을 단다. 예약해야만 할 수 있는 코드·이름은 싣지 않는다(경로 자료가 없다, ADR-0074 Amendment 1).
- 출력 파일은 `rules-02.json`(v1 `rules-01.json`은 그대로 둔다). `scripts/nation/build.mjs`가 `rules-02.json`을 읽는다.
- 체인 빼기·음식점·뺄 코드(`EXCLUDED`)·실내 원칙은 v1과 같다.

## 1. 대상

v1과 같다. `review/nation/scope-<시도>.json` 14개 시도 30,697곳. 입력 필드는 `title`, `contenttypeid`, `lclsSystm3`뿐이다.

## 2. 바뀌는 표 (v1 3절에서 이 줄만 바뀐다)

| 기분 | sub | 실내 | lclsSystm3 |
|---|---|---|---|
| rest | — | false | NA010300 폭포, NA020100 강, NA020200 호수, NA020400 연못·늪, NA020500 섬, NA020700 항구·포구, NA020800 해안절경, NA020900 해변, NA030300 기암괴석, VE010200 타워·전망대, VE010800 등대, VE030100 시민공원, VE030200 소공원, VE030400 근린공원, VE030500 주제공원 |
| rest | — | true | EX050100 온천·사우나·스파, EX050200 찜질방 |
| new | do | false | NA010400 계곡 (`walkin: true`) |

v1 표의 `walk` 줄에서 위 코드가 빠진다. 나머지 `walk`(산·숲·늪·습지·국립공원·휴양림·수목원·다리·분수·댐·골목길·둘레길·성곽 등)와 `new`·`sight`, 먹기는 v1 그대로다.

## 3. `new`·`do`의 예약 (`scripts/walkin.mjs` `walkinByRule`, 순서대로)

1. 이름에 `배낚시|선상낚시|공방|클래스|강습|스쿨|템플스테이` → 예약해야만 함.
2. 예약 코드: EX010100 전통문화체험, EX020100~EX020400 공예체험, EX030100 체험마을, EX030400 체험어장, EX040100 템플스테이, EX040200 사찰문화체험, EX050300 한방체험, EX050400 힐링명상, EX050500 뷰티스파, EX050600 기타웰니스, LS010400 골프, LS020400 스노쿨링·스킨스쿠버, LS030100~LS030600 항공레저 → 예약해야만 함.
3. 현장 코드: EX030200 체험목장, EX070100 유람선, LS010300 카트, LS010800 스키, LS010900 스케이트, LS011000 썰매장, VE020100 테마파크, VE020200 워터파크, VE020300 동물원, NA010400 계곡 → 예약 없이 감.
4. 그 밖의 `do` 코드: 자동 지역에는 원문이 없어 **예약 없이 가는 곳으로 본다**(검수한 곳에서는 판정으로 보낸다).

예약해야만 하는 곳은 `{ keep: false, reject: 'BOOKING' }`이다. 예약 없이 가는 곳은 `{ keep: true, mood: 'new', sub: 'do', walkin: true, … }`이다. 출하 레코드(`data/nation/<시도>.json`)는 `sub`를 `sight|do`(먹기는 `meal|cafe`)로 싣고, `do`에는 `walkin: true`를 싣는다. 앱(`nation.ts` `normalizeNation`)은 `do`이고 `walkin`인 곳만 놀거리로 받는다.

## 4. 측정 (audit-02, 1회)

- **표본**: v1과 같은 방법(`rules.mjs sample`). `rules-02.json`의 keep에서 시도 14곳 × 14곳 + 무작위 4곳 = 200곳, 뺀 곳에서 60곳. **씨앗 20261103**(v1 20261030과 다름). 결과 `audit-02-input.json`(코드·규칙 결과 없음).
- **판정자**: 규칙과 이 문서를 보지 않은 새 하위 에이전트(Opus). 표본을 나눠 여럿이 맡을 수 있고, 각자 다른 몫을 본다. 받는 것: `id`, `title`, `addr1`, 종류 이름, 판정 안내 `audit-02-brief.md`(이 등록과 같은 커밋). 웹 검색 없음, 모르면 `unsure: true`. 결과 `audit-02-out.json`.
- **지표와 기준**:

| 지표 | 계산 | 기준 |
|---|---|---|
| 기분 일치 | 판정자가 keep하고 `unsure`가 아닌 곳 중 기분이 같은 비율 | ≥ 85% (v1과 같음) |
| 실내 일치 | 같은 대상 중 실내가 같은 비율 | ≥ 90% (v1과 같음) |
| 예약 일치 | 규칙 결과가 `do`(예약 없이 감) 또는 `BOOKING`이고 판정자가 `walkin`을 적은 곳 중 `walkin`이 같은 비율(`BOOKING`은 `false`) | ≥ 85% (기분과 같은 수) |
| 쉬기 일치 | 규칙이 `rest`인 곳 중 판정자도 `rest` | 기록만 |
| keep 일치 | 200 + 60곳 | 기록만 |

- 기분 일치의 대상은 v1처럼 규칙과 판정자가 모두 keep한 곳이다. 판정자가 예약해야만 하는 곳이라 뺀 곳은 keep 일치와 예약 일치에만 든다.
- `node scripts/nation/rules.mjs score2` → `audit-02.json`. 결과와 해석은 `rules-REPORT.md`에 덧붙인다.

## 5. 결과에 따라 (미리 정함)

- **기분 실패**: v2를 싣지 않는다. `data/nation`은 v1 그대로이고 자동 지역에는 쉬기가 없다. 수치·틀린 곳·가설을 적고 멈춘다(다시 재기는 주인 승인).
- **기분 통과, 실내 실패**: v1처럼 자동 지역의 「비 와요 → 실내만」을 끄고(`rules.indoor: false`) 기분만 싣는다.
- **기분 통과, 예약 실패**: 3절의 1·2를 쓰지 않는다. 모든 `do` 코드를 예약 없이 가는 곳으로 싣는다(v1이 예약을 묻지 않던 것과 같은 범위). 계곡·쉬기는 그대로 싣는다.
- 측정은 한 번이다. 통과할 때까지 돌리지 않는다.

## 6. 알고 있는 한계

- 원문 없이 코드만 본다. 계곡 코드 안의 등산 코스는 놀러로 가고, 공원 코드 안의 걷는 공원은 쉬기로 간다.
- 판정 안내와 규칙이 같은 장소 종류 표에서 나와, 일치율은 「같은 표를 같게 적용하는가」를 잰다.
