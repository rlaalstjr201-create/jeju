# 서울 즐길 거리 (45bcddb3) 배포 전 독립 리뷰 3

리뷰어: Claude 독립 리뷰(읽기 전용, Codex 대신 — ADR-0058). 대상: commit 45bcddb3(0abf9dd5 대비), ADR-0115(Amendment 1·2 포함), ADR-0114. 앞 리뷰: `predeploy-review-2.md`.

결론: 이대로 배포하면 안 된다. MAJOR 2건이다. (1) 줄이 7개에서 8~10개로 늘었는데 수집기는 「가로로 넘긴 줄 수」를 0~7까지만 받는다. 8줄 이상 넘긴 사람의 `browse_done`은 묶음째 400으로 버려지고, 이 이벤트가 판정의 분모(나감)와 중앙값이다. (2) ADR-0115의 출하 게이트 「줄마다 카드 6장 이상」을 테스트가 확인하지 않는다. 11-04 자료로 돌려 보면 19:00·22:00에 이 조건이 깨진다. 홈 픽 누출, 카드 시트, XSS, 링크, 개인정보는 문제가 없다.

### 1. 정확성

- **홈과 목록 시트로 새지 않음.** `picksOf`가 `pickCulture(realItems(c.items))`를 부르고, `homeBlock`·`sheetBody`는 모두 `picksOf`만 쓴다. `culture-view.ts`에서 `c.items`를 직접 읽는 곳은 `homeBlock`의 빈 목록 검사, 둘러보기 화면, 카드 시트뿐이다(grep). culture-app 테스트 「an empty list today」가 픽 0건에 입구 버튼만 있는 것을 확인한다. 이제 API 목록이 비어도 즐길 거리가 실려 입구가 늘 보인다. 의도한 것이고 테스트도 그렇게 바뀌었다. `homeBlock` 위 주석 「null when today's list is empty」는 낡았다.
- **카드 시트 조회와 상태 가드.** `state.ts:672`의 reducer는 `culture.items.some(i => i.id === browseId)`로 판단한다. `kk-<숫자>`와 `hood:<이름>`도 `culture.items`에 있으므로 그대로 통과한다. `app.ts:492`의 다시 받기 가드도 같은 배열을 본다. 분 단위 갱신(`{...s.culture, minute}`)은 items를 그대로 두고, 새 날은 `funItems(day)`로 다시 싣는다. 포커스 복귀(`culture-view.ts:172`)는 `dataset.id ===` 비교라서 `hood:` 안의 콜론과 상관없다. 동네 시트도 `h2#bc-title tabindex=-1`, 닫기 버튼, scrim(`data-action=close`)을 그대로 둔다.
- **이벤트 모양은 그대로.** `browse_open/card/link/done`의 필드는 바뀌지 않았다. 항목 id나 위치는 보내지 않는다. 동네 시트의 줄도 `a[data-blink=go]`라 `browse_link go`로만 센다. 다만 `rows` 값의 범위가 바뀌었다 → MAJOR 1.

### 1. 8줄 이상 넘기면 `browse_done`이 버려짐 (판정 분모 손실)
- 위치: `events/validate.ts:77` `whole(o.rows, 7)`, `events/handler.ts:40` `browse:rows:0…7`, `scripts/analytics-report.mjs:59` `length: 8`, `src/track.ts:71` 주석 「0–7」.
- 근거:
  - `SHELVES`가 10개이고, 11-04 자료 14:00에 실제로 8줄이 나온다(위 표). 야구철이면 9줄, G4를 실으면 10줄이다.
  - `scrolledRows()`는 옆으로 넘긴 줄의 Set 크기라 8까지 올라간다.
  - 직접 실행해 봤다. `eventProblem({e:'browse_done', rows:8, …})` → `'browse_done'`, rows 9도 같다. rows 7은 null이다.
  - `parseBatch`는 이벤트 하나만 틀려도 묶음 전체를 400으로 돌려보낸다. `track.ts`는 다시 보내지 않는다.
- 영향: 가장 오래, 가장 많이 둘러본 방문이 골라서 빠진다. 「나감 30회」「중앙값 칸 45초」 판정(ADR-0114 7, ADR-0115 7)이 아래로 치우치고, 이 사실이 어디에도 드러나지 않는다.
- 고칠 방법: 수집기 상한을 `SHELVES.length`(10)로 올리고, handler id `browse:rows:0…10`과 보고서 `length: 11`도 함께 바꾼다. 수집기를 앱보다 먼저(또는 같이) 배포한다. 급하면 앱에서 `Math.min(7, rows)`로 자르는 방법도 있지만, 그러면 값의 뜻이 「7줄 이상」으로 바뀌므로 ADR·보고서에 한 줄 적어야 한다.

### 2. 출하 게이트 「줄마다 카드 6장 이상」이 테스트되지 않고, 자료로 돌리면 깨짐
- 위치: `tests/browse.test.ts`의 it.each 9개 조합. ADR-0115 「성공 기준」 둘째 줄.
- 근거: 테스트는 `toBeGreaterThan(0)`과 「exhibit 아닌 줄 ≥ 4」만 본다. 6장 조건은 망원 14:00 g7 하나만 확인한다. 같은 자료로 돌린 결과는 이렇다.
  - 19:00 망원: 첫 줄 「오늘 무대」가 **1장**이다. 「시장·포차」 2장, 「오늘만·이번 주까지」 5장.
  - 22:00 세 곳 모두: 「시장·포차」 2장, 「전시·박물관」 2장.
- ADR 문장을 「줄이 넷 이상이고, (그) 줄마다 6장 이상」으로 느슨하게 읽으면 9조합 모두 통과한다. 22:00 망원은 동네가 딱 6장이라 간신히 넘는다. 하지만 글자 그대로는 「줄마다」다. 19:00 망원은 화면 맨 위에 카드 한 장짜리 줄이 온다.
- 고칠 방법(주인이 고를 것):
  - (a) 몇 장 미만인 줄은 순서를 뒤로 내리거나 숨긴다(예: 3장 미만이면 뒤로). 그다음 테스트에 「앞 세 줄은 6장 이상」 같은 실제 조건을 넣는다.
  - (b) ADR에 해석을 Amendment로 적고(「6장 이상인 줄이 넷 이상」), 테스트가 그것을 그대로 확인하게 한다.
  - 어느 쪽이든 결과를 보기 전에 정한 것으로 남긴다.

## MINOR

### 1. 자정 무렵 찜질방(24시간)과 종일 종류가 사라짐
- 위치: `src/fun.ts` `likelyOpen`.
- 근거: 닫는 시각이 1440 이하이면 `at = minute + travel`이 1410을 넘는 순간 false가 되고, 자정을 넘어 다시 감싸 보지 않는다. 직접 실행: 찜질방 23:35(이동 0분) → false. 23:45 화면에서 「몸으로 놀기」 줄이 통째로 없다(위 표). 이동 40분이면 22:50 이후로 빠진다. 「새벽 찜질방」이 이 줄 순서(late)의 핵심인데 그 직전 30분이 빈다.
- 고칠 방법: `at % 1440`으로 한 번 더 보거나, 종일 종류(`[0, 1440]`)는 늘 true로 둔다. 테스트에 23:45 찜질방 한 줄을 더한다.

### 2. 시간대 순서 테스트가 구현을 되풀이함
- 위치: `tests/browse.test.ts`의 `expect(keys).toEqual([...keys].sort(rank.indexOf…))`.
- 근거: 같은 `ORDER`로 같은 정렬을 하므로 `ORDER` 내용이 틀려도 통과한다. `ORDER`가 모든 `SHELVES`를 담는지도 확인하지 않는다(빠진 키는 indexOf −1이라 맨 앞으로 간다).
- 고칠 방법: 시간대마다 첫 줄을 고정값으로 단언(14:00 → hood, 19:00 → stage/g7 등)하고, `ORDER[b]`가 `SHELVES`의 순열인지 확인한다.

### 3. 「전시·박물관」 줄이 남은 행사를 모두 받음
- 위치: `src/browse.ts` `exhibit: (c) => !isFun(c.item)`.
- 근거: 11-04 자료 14:00 이 줄에 `교육/체험`이 들어 있다. 무대도 이번 주도 아닌 축제·체험도 전시 이름 아래 보인다.
- 고칠 방법: `kind.startsWith('전시')`(예전 규칙)로 되돌리고, 나머지는 「오늘만·이번 주까지」 밖이면 빼거나 줄 이름을 넓힌다.
