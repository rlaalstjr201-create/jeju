# 부산 카카오 대조 S3b — 사전등록 (kakao-01)

등록: 2026-10-19, 호출 전 커밋. 근거: `plans/busan.md` S3b(결과 생성, 1회, 규칙 밖 판단 0), `specs/busan.md` 3.1(「카카오 로컬(ID만, ADR-0050) → `kakaoPlaceId`, 폐업이면 `hide`」), ADR-0050(카카오 로컬로 장소 ID 얻기·실재 확인, 제주 선례 `apps/api/src/scripts/enrich-kakao*.ts`: 이름 검색 + 좌표 반경, 거리 300m), ADR-0094·0095, `docs/research/busan-data-sources.md` 1-5(저장은 장소 ID·place_url만). 주인 지시 2026-10-19 「부산 영역 완성까지 진행」. 이 문서는 결과를 본 뒤 바꾸지 않는다.

## 1. 대상

- S3 판정(`judge-01/out-*.json`)에서 `keep: true`인 **995곳 전부**. 뺀 113곳은 부르지 않는다. `fixes-01.json`은 이유 문장만 고쳤으므로 대상과 무관하다.
- 장소의 이름·좌표·종류는 `review/busan/scope.json`(TourAPI 원문)에서, 기분은 S3 판정에서 읽는다.

## 2. 호출 (곳마다 1회)

- 카카오 로컬 키워드 검색 `GET https://dapi.kakao.com/v2/local/search/keyword`, `query` = 검색어, `x`·`y` = TourAPI 좌표(`lng`·`lat`), `radius` = 거리 한도(3절), `size=15`, `page=1`, 정렬 기본값(정확도).
- 검색어 = `title`에서 괄호(`()`·`（）`·`[]`)와 그 안 글자를 지우고 공백을 하나로 줄인 것. 지워서 빈 문자열이면 `title` 그대로. (예: `감천사(부산)` → `감천사`)
- 곳마다 한 번만 부른다. 다른 검색어로 다시 부르지 않는다. 다시 부르는 것은 **응답을 못 받았을 때만**(HTTP 429·5xx·네트워크 오류): 1초·2초 쉬고 최대 3번. 3번 다 실패하면 그곳은 `error`로 남기지 않고 결과 파일에 쓰지 않는다(같은 명령으로 다시 돌리면 그곳만 다시 부른다).
- 멈춤: HTTP 401·403이면 바로, 20곳 이상 부른 뒤 실패한 곳이 5%를 넘으면(제주 선례) 그 자리에서. KST 하루 1,200회(카카오 한도 하루 10만 회보다 훨씬 아래)에 닿으면 멈추고 다음 날 이어 간다.
- 호출마다 `review/busan/kakao-calls.log`에 `KST날짜\t시각\tid\t결과`를 한 줄 쓴다. 키·응답 본문은 어디에도 남기지 않는다.

## 3. 맞는 곳 고르기 (규칙만, 사람·모델 판단 없음)

응답의 곳(`documents`)마다 아래를 차례로 거른 뒤 고른다. 응답의 이름·좌표·분류는 판정에만 쓰고 저장하지 않는다.

1. **거리**: TourAPI 좌표와의 직선거리가 음식점(39)은 300m 이하(제주 선례), 그 밖은 1,000m 이하(해변·산·공원·사찰은 넓다).
2. **분류**: 카카오 `category_group_code`가 주차장 `PK6`·지하철역 `SW8`·주유소 `OL7`·은행 `BK9`·중개업소 `AG2`·편의점 `CS2`·어린이집 `PS3`·학원 `AC5`·병원 `HP8`·약국 `PM9`·숙박 `AD5`·대형마트 `MT1`이면 뺀다. 음식점(39)은 음식점 `FD6`·카페 `CE7`만 남긴다. S3 기분이 `food`가 아닌 곳은 `FD6`·`CE7`을 뺀다.
3. **이름**: 이름 다듬기 = NFKC, 괄호와 그 안 글자 지움, 공백·`·,./&'-_` 지움, 영문 소문자. 둘 다 앞의 `부산광역시`·`부산`을 떼어 본 값도 함께 본다.
   - `exact`: 다듬은 두 이름이 같다(뗀 값끼리 같아도 같다).
   - `contains`: 한쪽이 다른 쪽을 품고, 짧은 쪽이 두 글자 이상. 다만 카카오 이름이 우리 이름보다 길 때, 카카오 이름이 시설 꼬리(`주차장`·`화장실`·`매표소`·`정류장`·`정류소`·`승강장`·`입구`·`출구`·`관리사무소`·`관리소`·`안내소`·`매점`·`편의점`·`정문`·`후문`·`역`, 뒤에 붙은 숫자·`번출구` 포함)로 끝나면 뺀다.
4. **고르기**: `exact` 가운데 가장 가까운 곳, 없으면 `contains` 가운데 가장 가까운 곳. 거리가 같으면 응답 순서가 앞인 곳.
5. **결과**:
   - 고른 곳이 있고 카카오 이름에 `폐업`·`폐점`·`휴업`·`영업종료`가 있으면 `closed`.
   - 고른 곳이 있으면 `matched`: 그곳의 `id` → `kakaoPlaceId`, `place_url` → `placeUrl`.
   - 없으면 `unmatched`.

## 4. 저장 (`review/busan/kakao-01.json`)

- 곳마다 `{ id, query, status, rule, kakaoPlaceId, placeUrl }`만. `rule`은 `exact`·`contains`·`none`. `unmatched`는 `kakaoPlaceId`·`placeUrl`이 `null`. 카카오의 이름·좌표·주소·분류·거리는 저장하지 않는다(카카오 답변: ID·place_url만 허용).
- 머리에 `criteria`(이 파일), 대상 수, 상태별 수, 규칙별 수, 호출 수.
- 다시 돌리면 이미 쓴 곳은 부르지 않는다(멱등). 모두 끝나면 0회 호출.

## 5. 결과에 따라 (S4 빌드가 읽는 법)

- `matched` → 출하 레코드에 `kakaoPlaceId`.
- `closed` → 출하하지 않는다(spec 「폐업이면 `hide`」).
- `unmatched` → **폐업으로 보지 않는다.** 카카오 키워드 검색은 영업 여부를 알려 주지 않고, 못 찾은 것은 이름·위치가 달라서일 수 있다. 출하는 그대로, `kakaoPlaceId` 없이(앱은 이름 검색 링크로 연다, ADR-0028).
- 통과 기준: `matched` ≥ 50%(498곳 이상). 못 넘으면 규칙이나 호출이 고장 난 것으로 보고, kakao-01을 빌드 입력으로 쓰지 않으며 규칙을 고치지 않고 수치와 가설을 `kakao-REPORT.md`에 적고 멈춘다. 다시 돌리려면 주인 승인.
- 이 회차는 한 번이다. 맞은 수를 늘리려고 검색어·거리·이름 규칙을 바꿔 다시 부르지 않는다. 사람 손으로 ID를 붙이거나 고치지 않는다(규칙 밖 판단 0). 결과와 해석은 `review/busan/kakao-REPORT.md`.
