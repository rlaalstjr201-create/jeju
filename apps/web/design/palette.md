# P의 여행 · 색 후보 (palette.md)

2026-10-01. 지금 색(`src/style.css` `:root`)이 "기본값 같다"는 피드백에 대한 조사와 후보 3개다. 코드는 바꾸지 않았다. 고르면 SPEC 개정과 ADR이 필요하다(아래 6절).

- 조건: **흰 바탕 + 최대 3색**(메인, 포인트, 글자). 회색(보조 글자·선·채움)은 새 색을 만들지 않고 글자색을 흰 바탕에 섞어 만든다.
- 금지: 그라디언트, 베이지·테라코타 계열.
- 비교 화면: `scratchpad/palette.html` (첫 화면·결과·아래쪽 3개 폰 화면, 위쪽 토글로 현재/A/B/C와 자동/라이트/다크 전환).

## 2. 뽑아낸 원칙 (베끼지 않고 가져올 것)

1. **누르는 것에 채도 높은 색 하나.** 두 곳 모두 "행동"(주 버튼, 선택된 칩)에만 강한 색을 몰아 준다. 오늘제주는 바다 파랑, 마이리얼트립은 검정 알약. 지금 우리 앱은 주 버튼(`다른 3곳 보기`)이 회색 `#ebebe6` 채움이라 눈이 갈 곳이 없다.
2. **두 번째 색은 작게.** 오늘제주의 귤색은 번호와 점, 마이리얼트립의 빨강은 26px 배지에만 쓴다. 넓은 면에 두 색을 같이 깔지 않는다.
3. **글자색은 순검정이 아니라 색이 살짝 섞인 잉크.** `#121826`(남색 기운), `#101418`. 회색도 그 잉크에서 파생한다.
4. **바탕은 흰색이 사진을 살린다.** 마이리얼트립은 순백이다. 오늘제주의 `#faf8f5`나 지금 우리의 `#f6f6f3`은 따뜻한 회색이라 사진 옆에서 탁해 보인다. 사용자가 피하려는 "기본값 같은" 인상의 한 원인이다.
5. **이름이 감각을 만든다.** 오늘제주는 토큰 이름을 kelp·basalt·tangerine으로 지었다. 색을 제주의 물건(바다, 귤, 유채, 동백, 현무암, 오름)에서 고르면 "그 앱 색"이 된다.
6. 가져오지 않는 것: 선택 칩 채움(SPEC §13 "선택은 체크·굵기·밑줄, 채운 상자 아님"과 충돌), 태그마다 다른 색(3색 제한 초과), 그라디언트.

## 6. 추천과 다음 단계

**추천: B 유채·동백.**

- 참고 두 곳과 겹치지 않는다. A의 파랑+귤 조합은 오늘제주(`#0882ba` + `#f97015`)와 거의 같은 짝이고, 파랑 메인은 마이리얼트립·트리플과도 같아 "여행 앱 기본값"으로 읽힐 위험이 있다.
- 사진 옆에서 가장 먼저 보인다. 제주 사진은 바다 파랑과 숲 초록이 많아서 A·C의 메인은 사진과 섞이고, 노랑은 섞이지 않는다.
- 대비가 가장 넉넉하다(버튼 12.34, 하트 4.71). 노랑을 선에 쓰지 않는다는 규칙 하나만 지키면 된다.
- "계획 없이 지금 바로"라는 P의 가벼움과 형광펜 표시가 잘 맞는다.

차선은 A(가장 제주답고 무난하지만 오늘제주와 닮음). C는 걷기·쉬기에는 맞지만 맛집·체험까지 덮기에는 신호가 약하다.

고르면 할 일(코드는 이번에 바꾸지 않음):
1. ADR 발행: 색 체계 변경(흰 바탕, 3색, 주 버튼 메인 채움).
2. SPEC §13과 2.2절 갱신: 주 버튼 채움 색, 포인트 색 범위, B라면 "노랑은 선에 쓰지 않음".
3. `style.css` `:root`와 `index.html` 첫 칠 바탕·`theme-color` 갱신, e2e 대비 기대값 갱신.
4. 지금 앱에 없는 두 가지("지금" 강조, 저장 배지)는 제안일 뿐이다. 넣을지는 따로 정한다.
