# proto-b · 현장 안내서 (Field-guide editorial)

작은 동네 안내서의 한 쪽처럼 만든다. 종이색 바탕에 먹색 글자를 쓰고, 굵은 선과 가는 선으로 묶는다. 색은 장소 사진과 저장한 하트에만 쓴다.

프로토타입은 `index.html` 한 파일이다. CSS와 JS는 모두 안에 있고, 밖으로 나가는 요청은 visitjeju 사진뿐이다. 데이터는 `public/spots.json`에 있는 실제 스팟 31곳(애월 근처 30곳, 우도 1곳)이며, 이름·이유·사진·좌표·카카오 ID·예약 여부를 그대로 가져왔다. 이동 시간도 `src/pick.ts`와 같은 식으로 계산한다.

## 상태 바로 열기

| 해시 | 화면 |
|---|---|
| `#home` | 첫 화면. 애월 근처, 저장 2곳 |
| `#cards` | 새로운 거 해보고 싶어 · 3곳. 예약 링크 1곳, 저장한 하트 1개 포함 |
| `#food` / `#food-cafe` | 맛있는 거 먹고 싶어 · 식사 \| 카페·디저트 |
| `#sheet` | 기준 시트: 내 위치 / 숙소 / 15곳 |
| `#saved` | 저장한 곳 2곳. 우도봉은 `우도라서 배를 타야 해요` |
| `#empty` | 위치 권한 꺼짐. 결과 자리에서 바로 동네를 고른다 |
| 추가 | `#first`(첫 방문, 저장 0) · `#loading`(위치 확인 중, 3초 뒤 탈출 링크) · `#error`(목록 실패) · `#stay`(숙소 정하기) · `#offline`(사진 없는 카드) |

조작도 모두 실제로 동작한다. 기분 탭, 바꾸기, 다른 3곳 보기, 식사/카페 전환, 기준 시트, 숙소 정하기(가짜 GPS 0.8초), 하트, 저장 목록, 뒤로가기, Esc를 지원한다. 사진이 실패하면 사진 칸을 빼고 글 카드로 바꾼다.

## 왜 이 방향인가

밤에 누워 반쯤 보는 사람에게 필요한 것은 세 가지다. 고를 곳 몇 개, 거기까지 얼마나 걸리는지, 그리고 누르면 무슨 일이 생기는지. 인쇄된 안내서는 이 셋을 장식 없이 전해 온 형식이다. 쪽 머리에 지명이 있고, 항목마다 이름과 한 줄 설명, 작은 사진이 붙고, 항목 사이는 선으로 나뉜다.

AI 템플릿처럼 보이는 가장 큰 원인은 모든 면이 같은 옷(테두리, 그림자, 큰 라운드)을 입는 것이다. 그래서 역할마다 재질을 하나씩만 준다.

- **읽는 것(장소)**: 상자도 그림자도 없다. 목록 위아래에 2px 먹선, 항목 사이에 1px 가는 선을 긋는다(인쇄 표의 booktabs 규칙). 사진 모서리는 2px로, 인화한 사진처럼 거의 각지게 둔다.
- **누르는 것**: 면 하나(`다른 3곳 보기`, 선택된 칸) 또는 밑줄 글자(`바꾸기`, `아무거나 골라줘`, `닫기`) 가운데 하나만 쓴다. 그림자는 없고, 버튼 모서리는 4px이다.
- **떠 있는 것(시트)**: 한 톤 밝은 종이에 윗모서리만 14px로 둥글린다. 화면에서 유일하게 둥근 큰 면이다.

색은 두 역할만 맡는다. 먹색 면은 선택됨과 주요 행동, 동백 빨강은 저장한 하트다. 거리·링크·메타·아이콘에는 색을 쓰지 않는다. 제주 앱에서 흔한 감귤 주황, 베이지+청록, 크림+테라코타는 피했다. 화면의 색은 실제 장소 사진에서 나온다.

## QA 발견 대응

| 발견 | 이 시안의 답 |
|---|---|
| 결과가 화면 아래에 뜸 | 기분을 고르면 질문과 목록이 사라지고, 고른 기분이 그 쪽의 제목이 된다. 첫 카드 이름 하단은 320×568과 375×667 모두 y=224(기존 590·624)다. 390×844에서는 3곳과 `다른 3곳 보기`가 한 화면에 들어온다(버튼 하단 y=698). |
| '다른 곳 보기'가 숨은 동작 | 세 번째 항목 아래 엄지 자리에 `다른 3곳 보기 →`를 둔다. 기분 버튼은 '고르기' 한 뜻만 가진다. 기분을 바꿨다 돌아오거나 식사↔카페를 오가면 그 기분에서 마지막으로 본 3곳이 그대로 나온다. 새로 뽑는 것은 `다른 3곳 보기`뿐이다. 한 바퀴를 다 돌면 `이 근처는 다 봤어요. 처음 본 곳부터 다시 보여 드려요.`를 띄운다. |
| 출발지가 모호 | 결과 머리 아래 한 줄(머리글)이 출발지를 말한다. 세 곳의 이동 문구가 같으면 `셋 다 애월에서 차로 약 5분이에요.`로 한 번만 쓰고, 다르면 `애월에서 가까운 순이에요.`라고 쓴 뒤 항목마다 `차로 약 20분`을 붙인다. QA에서 270화면 중 247화면은 세 곳이 모두 같았으니, 대부분은 한 줄로 끝난다. 기준 버튼도 `⇄` 대신 `애월 근처 ⌄`로 바꿨다. |
| 저장 목록 history 버그 | history에는 `{view, mood, sub, overlay, depth}`만 담는다. 열 때 push하고, UI로 닫을 때(바꾸기, 돌아가기, 닫기, 딤, Esc)는 이 세션에서 push한 경우에만 `history.back()`, 아니면 `replaceState`를 쓴다. popstate는 `history.state`를 그대로 적용한다. 저장 목록에서 기준을 바꿔도 목록은 닫히지 않고 새 기준으로 다시 정렬된다. |
| 늦은 비동기 결과 | 숙소 GPS 저장은 요청 id를 받는다. 끝났을 때 id가 바뀌었거나 숙소 시트가 닫혀 있으면 결과를 버린다. 위치 실패 때 시트를 띄우지 않고 결과 자리에 동네 목록을 바로 보여 주므로(`#empty`), '늦게 온 실패가 시트를 연다'는 유형이 구조적으로 생기지 않는다. |
| 로딩·실패 | 기다리는 동안 사진 비율 그대로 회색 틀 3개를 보여 준다. 움직이는 효과는 없다(`#loading`). 목록 실패 때는 원인 한 줄과 `다시 불러오기`를 준다(`#error`). |
| 섬 이동 시간 | 출발지와 스팟이 다른 섬이면 분 대신 `우도라서 배를 타야 해요` / `본섬이라 배를 타고 나가야 해요`, 같은 작은 섬이면 `같은 우도 안이에요`라고 쓴다. |
| 문장 어미 반복 | 이유 문장 자체는 S9-3 파이프라인의 몫이라 데이터 그대로 쓴다. 화면은 같은 메타 줄의 반복을 없애서 반복감을 줄인다(위 '출발지' 참고). |
| 새로고침하면 보던 3곳이 사라짐 | 프로토타입 밖의 일이다. 구현에서는 `{기분, 하위, 카드 id 3개, 기준}`을 sessionStorage에 두고 마운트 때 복원한다. 로테이션은 진행하지 않는다. |
| 시각 신호(MINOR) | 기분은 전체 폭 목록 4줄이고, `아무거나 골라줘`는 목록 아래 밑줄 글자로 떼어 두었다. 그림자 0, 그라데이션 0. 거리색 accent는 없애고 muted로 내렸다. 다크에서는 사진 밝기를 0.9로 낮춘다. |
| 시트 문구·위치 권한·하트 안내·접근성·200% | 아래 '문구'와 '부품' 참고. 시트가 열리면 `main`과 쪽 머리에 `inert`를 걸고, 하트의 aria-label은 `{이름} 저장`으로 고정한 채 상태는 `aria-pressed`로만 전한다. 글자를 200%로 키워 글 칸이 좁아지면 사진이 항목 위로 올라간다. |

## 글자

글꼴은 웹폰트 없이 시스템 글꼴 스택을 쓴다. `-apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Pretendard Variable", Pretendard, Roboto, "Noto Sans KR", "Segoe UI", "Malgun Gothic", sans-serif`

크기는 앱 전체에 3단계뿐이고, 모두 rem이라 시스템 글자 크기를 따른다.

| 단계 | 크기 / 행간 / 자간 | 굵기 | 쓰는 곳 |
|---|---|---|---|
| L | 24px(1.5rem) / 1.3 / -0.02em | 700 | 첫 화면 질문, 결과 제목(기분), `저장한 곳` |
| M | 17px(1.0625rem) / 1.4 / -0.01em(이름만) | 700 이름·시트 제목, 600 기분 줄·탭·버튼·칸 이름·안내 제목 | |
| S | 15px(0.9375rem) / 1.5 / 0 | 400 이유 문장·머리글·메타·날짜·대표 지명, 600 무리 제목·글자 버튼 | |

- 굵기는 400·600·700만 쓴다. 위계는 크기와 색으로 만들고 600과 700의 차이에 기대지 않는다(안드로이드 한글 글꼴이 둘을 같은 굵기로 붙일 수 있다).
- `body { word-break: keep-all; overflow-wrap: break-word }`. 제목과 이름에는 `text-wrap: balance`, 이유 문장에는 `pretty`를 준다.
- 괄호 별칭은 이름 뒤에 S·muted로 붙이고 `inline-block`으로 통째 줄바꿈한다. 예: **더럭초등학교** (구, 더럭분교)
- ♥ 개수와 저장 개수에는 `tabular-nums`를 준다.

## 간격

- 좌우 여백 16px, 본문 최대 폭 480px.
- 묶음 안 간격은 4~8px이다(이름→이유 4, 이유→메타 6, 제목→머리글 6).
- 묶음 사이 간격은 14~22px이다(머리글→목록 14, 항목 위 16·아래 18, 목록→`다른 3곳 보기` 20, 무리 사이 22).
- 첫 화면은 질문과 목록을 화면 아래에 붙인다. 목록 시작 위치는 320×568에서 y=253, 375×667에서 y=352, 390×844에서 y=529이고, `아무거나 골라줘`까지 스크롤 없이 들어온다. 위쪽 빈 종이는 의도한 여백이다. 위쪽 모서리에는 보조 행동(기준, 저장)만 둔다.

## 부품

**쪽 머리** (sticky, 53px, 아래 1px `--rule`)
- 왼쪽 기준 버튼: `애월 근처 ⌄`. 15/600, 높이 44 이상. aria-label은 `애월 근처, 기준 바꾸기`.
- 오른쪽 저장 버튼: 빨간 하트 + 개수. 저장이 0개면 없다. 저장한 곳을 보는 중에는 개수 아래 2px 밑줄을 긋고 `aria-pressed=true`를 준다. 줄이 넘치면 flex-wrap으로 내려가고, 개수는 nowrap이다.

**첫 화면**
- 날짜(`10월 1일 목요일`, S·muted), 질문(L)을 두고, 그 아래 기분 목록을 둔다.
- 기분 목록은 위아래 2px 먹선, 사이 1px 선이다. 줄은 전체 폭, 최소 높이 58px, 17/600 왼쪽 정렬이며 오른쪽에 muted 꺾쇠를 둔다. 누르면 배경만 `--fill`로 바뀌고 크기는 변하지 않는다.
- `아무거나 골라줘`는 목록 밖 아래에 17/600 밑줄 글자로 둔다(높이 48). 목록에서 떼어 성격이 다른 선택지라는 것을 보여 준다.

**결과 머리**
- 제목(L, 기분 문구)과 오른쪽 `바꾸기`(밑줄 글자, aria-label `기분 바꾸기`)를 둔다.
- 먹기일 때만 제목 아래에 `식사`, `카페·디저트` 글자 탭을 둔다. 17/600이고, 선택된 쪽은 먹색에 2px 밑줄, 아닌 쪽은 muted다. 그룹 aria-label은 `먹을 것 종류`, 각 탭은 `aria-pressed`를 쓴다. 채운 알약 세그먼트를 쓰지 않으니 다크에서 밝은 면이 생기지 않는다.
- 머리글(S·muted)은 출발지와 이동을 한 번 말한다. 카카오맵을 한 번도 열지 않은 사람에게만 둘째 줄 `누르면 카카오맵이 열려요.`를 보여 준다. 한 번 열면 기기에 기억하고 다시는 띄우지 않는다.

**장소 항목**
- 2열 격자: 글 칸 `1fr` + 사진 112px(320px 폭에서는 88px), 사이 14px.
- 글 칸에는 이름(M/700), 이유(S), 이동 문구(S·muted, 머리글로 올라가지 않았을 때만), 예약 링크를 쌓는다.
- 사진은 1:1, 모서리 2px, `object-fit: cover`, 로딩 중 바탕은 `--fill`이다. 실패하면 사진 칸을 통째로 빼고(`.nophoto`), 하트는 글 칸 오른쪽 위로 옮긴다.
- 항목 전체가 카카오맵 링크다(이름 `<a>`의 `::after`가 항목을 덮는다). aria-label은 `{이름}, 카카오맵에서 보기`, 키보드 포커스는 항목 전체에 2px 먹선 윤곽으로 보인다.
- 하트: 사진 오른쪽 위, 누르는 영역 44×44, 보이는 원판 32px. 빈 하트는 흰 선에 `--scrim` 원판, 저장한 하트는 `--leaf` 원판에 빨간 채움이다. aria-label은 `{이름} 저장`으로 고정하고 상태는 `aria-pressed`로만 전한다. 하트를 눌러도 지도가 열리지 않는다(z-index 1).
- 예약(예약 가능한 곳만): `마이리얼트립에서 예약 찾아보기`. 15/600 밑줄, 높이 44.
- 첫 저장(저장 0→1)일 때만 그 항목 안에 `저장한 곳은 맨 위 하트 버튼에 모여요.`를 2.6초 보여 주고 150ms에 걸쳐 사라지게 한다. 그 뒤로는 띄우지 않는다.

**다른 3곳 보기**
- 전체 폭, 높이 52, `--fill` 면, 모서리 4, 라벨은 왼쪽 17/600이고 오른쪽에 muted →. 누르면 `scale(0.98)`.
- 400ms 안에 다시 누르면 무시한다(기분 줄도 같다). 카드가 바뀌어도 등장 애니메이션은 없다.

**회색 틀**
- 항목과 같은 격자에 이름 막대 46%, 이유 막대 92%·68%, 사진 자리 1:1을 둔다. 모두 `--fill`이고 움직이지 않는다.
- 위에 상태 줄 `위치 확인 중…`을 두고, 3초가 지나면 옆에 `지역으로 고르기`를 붙인다.

**안내**(권한 꺼짐, 목록 실패)
- 2px 먹선 아래에 안내 제목(M/600, 마침표 있음)과 설명(S·muted)을 두고, 다음 행동 하나를 준다.
- 권한이 꺼졌으면 시트를 띄우지 않고 결과 자리에 동네 색인을 바로 펼친다. 맨 아래에 `위치를 쓰려면 브라우저 설정에서 위치 권한을 켜 주세요.`를 둔다.

**동네 색인**(시트, 권한 꺼짐, 숙소 시트에서 같은 부품)
- 무리 제목은 `제주시 쪽`(S/600 muted) + `서쪽부터`(S/400)이다. 무리 안은 경도 순(서→동)이라 지명을 몰라도 지도 감각으로 찾을 수 있다.
  - 제주시 쪽: 한경·한림·애월·신제주·구제주·조천·구좌·우도
  - 서귀포 쪽: 대정·안덕·중문·서귀포 시내·남원·표선·성산
- 칸마다 지역 이름(M/600)과 그 아래 여행자가 아는 이름 하나(S·muted)를 둔다: 수월봉, 협재, 한담, 공항 근처, 동문시장, 함덕, 월정리, 배로 가는 섬, 모슬포, 산방산, 주상절리, 올레시장, 위미, 성읍, 일출봉. 각 대표 지명은 spots.json의 해당 장소 좌표에서 가장 가까운 지역 중심으로 확인했다.
- 격자는 `repeat(auto-fill, minmax(6.4em, 1fr))`이다. 390px에서 3칸, 320px에서 2칸, 글자 200%에서 1칸이 된다. 칸 사이는 가로선만 긋고 세로선은 없다. 왼쪽 정렬이라 키패드가 아니라 색인처럼 읽힌다.
- 선택된 칸은 `--sel-bg` 면이다. 칸 높이는 54 이상.

**기준 시트**
- 제목 `어디 근처로 볼까요?`(M/700)와 `닫기`를 sticky 머리에 둔다.
- 그 아래 두 칸: `내 위치`(`지금 있는 곳` / 권한 꺼짐이면 `위치 권한이 꺼져 있어요`), `숙소`(숙소 지역 이름 / 없으면 `처음 한 번만 정해요`).
- 이어서 동네 색인을 두고, 숙소가 있으면 맨 아래에 `숙소 다시 정하기`를 둔다.
- 딤, `닫기`, Esc, 뒤로가기로 닫는다. 열리면 포커스를 제목으로 옮기고, 닫히면 기준 버튼으로 돌려준다.
- `max-height: 88dvh`이고 안에서 스크롤한다.

**숙소 시트**
- `숙소가 어디예요?` / `한 번 정하면 이 기기에 기억해 둘게요.`
- 주요 행동 `지금 위치를 숙소로`(`--sel-bg` 면)를 두고, 진행 중에는 `위치 확인 중…`으로 바꾼다. 그 아래 동네 색인을 둔다.
- 기준 시트에서 넘어올 때는 `replaceState`를 쓰므로, 뒤로가기 한 번이면 시트 전체가 닫힌다.

**저장한 곳**
- 제목 `저장한 곳` + 개수(L/400 muted)와 `돌아가기`를 둔다. 기준 버튼은 쪽 머리 제자리에 그대로 있다.
- 머리글은 `애월에서 가까운 순이에요.`이고, 항목마다 이동 문구를 쓴다(거리순 목록이라 반복이 정보다).
- 열 때의 id 목록을 보여 준다. 여기서 하트를 풀어도 항목은 빈 하트로 남아 되돌릴 수 있고, 다시 열면 빠진다.
- 맨 아래에 `이 브라우저에만 저장돼요.`를 둔다.

**움직임** (전부 `prefers-reduced-motion: no-preference` 안에서만)
- 시트: 등장 `translateY(100%)→0` 240ms `cubic-bezier(0.2,0.8,0.2,1)`, 퇴장 190ms ease-in. 딤: 200ms / 160ms.
- 면 버튼 누름은 `scale(0.98)` 120ms, 하트 누름은 원판 `scale(0.88)` 120ms.
- 카드 등장, 스켈레톤 반짝임, 스크롤 애니메이션은 없다. 화면이 바뀌면 맨 위로 즉시 이동하고 제목에 포커스를 둔다(스크린리더가 새 화면 제목부터 읽는다).

## 이동 문구

`src/pick.ts`의 `travel()`·`islandOf()`와 같은 계산이다.

1. 섬이 다르면 `{섬}라서 배를 타야 해요` 또는 `본섬이라 배를 타고 나가야 해요`.
2. 같은 작은 섬 안이면 `같은 {섬} 안이에요`.
3. 출발지가 실제 점(GPS, GPS로 정한 숙소)이고 1km 안이면 `걸어서 약 N분`.
4. 그 밖에는 `차로 약 N분`(60분 이상이면 `1시간 10분`).

출발지는 머리글이 말한다. GPS는 `여기서`, 숙소는 `숙소에서`, 지역은 `{지역}에서`다. 세 곳의 문구가 모두 같으면 머리글이 `셋 다 {출발지} {문구}이에요.`(섬 문구면 `셋 다 {문구}.`)로 한 번만 말하고 항목에는 쓰지 않는다. 하나라도 다르면 머리글은 `{출발지} 가까운 순이에요.`이고 항목마다 출발지 없는 문구를 쓴다. 메타 줄에는 마침표를 찍지 않는다.

## 문구

규칙은 이렇다. 시스템 문장은 해요체 하나로 쓴다. 반말은 기분 버튼(사용자의 속마음)에서만 쓴다. 느낌표, 이모지, em dash, `당신`, `AI`·`맞춤`·`추천`은 0개다. 문장형 안내·상태·오류에는 마침표를 찍고 버튼·라벨·제목·탭·메타에는 찍지 않는다. 오류는 무엇이 안 됐는지와 다음 행동만 쓴다.

## 확인한 것

실제 Chrome(Playwright)에서 `file://`로 열어 확인했다.

- 12개 상태 × 320×568 / 390×844 / 430×932 × 라이트·다크 = 72장에서 가로 넘침 0, 44px 미만 탭 대상 0, 본문 글자 대비 4.5:1 미만 0.
- 글자 200%(root font-size)와 페이지 확대 200%(195×422)에서 가로 넘침 0, 잘린 버튼 0, 쪽 머리는 한 줄을 유지했다.
- 흐름 18개 모두 통과했다. 기분→3곳, 사진 실패→글 카드, `다른 3곳` 연타는 한 번만, 한 바퀴 문장, `바꾸기`→첫 화면(뒤로가기 항목 균형), 식사→카페→식사에서 같은 3곳, 시트가 열리면 하트 좌표의 최상위 요소가 시트, 지역을 고르면 시트가 닫히고 머리글이 `한림에서 …`로 바뀜, 그 뒤 뒤로가기에 헛도는 항목 없음, 저장한 곳 2곳과 섬 문구, 하트를 풀어도 줄 유지·개수 감소, 저장 목록에서 기준을 바꿔도 목록 유지, 숙소 GPS 도중 닫으면 기준 그대로, Esc로 닫고 포커스 복귀, 페이지 오류 0.
- 그라데이션, backdrop-filter, box-shadow, 이모지, em dash, 금지어는 grep 결과 0건이다.

## 사용자 확인이 필요한 것

1. **동네 칸의 대표 지명**(협재, 함덕, 일출봉 등)은 ADR-0029에 없는 새 문구다. 데이터 수집은 없고 화면 문구만 추가된다. 지명을 모르는 여행자가 고를 수 있게 하려는 것이다.
2. **`누르면 카카오맵이 열려요.`를 처음 한 번만** 보여 주는 방식. 기기에 플래그 하나를 저장한다.
3. **결과 화면도 history 항목으로 둔다.** 뒤로가기를 누르면 앱을 떠나지 않고 기분 목록으로 돌아간다. 감사안의 nav.ts(시트·저장 목록만 경로로 둠)보다 한 단계 넓다.
4. 오래된 지역 기준을 하루 뒤 GPS로 되돌릴지(ADR-0029 해석)와 지도 폴백을 좌표 핀으로 바꿀지(ADR-0028 수정)는 이 시안에서 정하지 않았다. 프로토타입의 폴백은 현재 `links.ts`와 같다(`제주 {이름}` 검색).

## 한계

- 데이터는 애월 근처만 들어 있다. 다른 동네를 고르면 같은 스팟을 그 동네에서 잰 시간으로 보여 준다(예: 한림에서 20~25분).
- 이유 문장은 원문 그대로라 `#cards`(가장 가까운 3곳)에는 `~이에요`·`~예요`가 두 번 나온다. 끝맺음을 섞는 일은 S9-3 파이프라인의 몫이다. `상가리야자숲`의 `여유를 누려요`도 데이터 문장이다.
- sessionStorage 복원, 두 탭 동기화, 서비스워커는 프로토타입 범위 밖이다. 구현 구조는 코드 감사안(state / render / effects / nav / store / data)을 따른다.
